# 理解页翻译阶段 8：检查与定点修复

## 交付范围

实现离线检查控制器、独立审查材料/证据提交、定点修复及重检。不会调用 API，不会修改中文审核、Batch 原始译文或正式页面，不会发布。当前测试用的是人工构造的隔离夹具及合成审查证据，不能表述成真实页面已完成语义审查。

实现：`tools/deepdive-stage2/lib/translation-quality.js`；通过 `core.js` 和原 Stage 2 MCP 服务提供受控入口。Batch 模块内部新增只读材料接口，要求全部章节收齐、输出摘要正确，重新读取冻结章节合同；不接收调用方伪造的原文或翻译任务。

## 九项门禁与真实完成条件

| 编号 | 项目 | 本阶段如何处理 |
|---|---|---|
| 1 | 中文版本与批准 | 每次检查重核源快照；过期/不可核验即停止审查与返修；缺少人工源批准继续标记待批准 |
| 2 | 内容覆盖 | 检查完整章节及单元键、缺失/多余/空译文；已有自测也参与 |
| 3 | 结构保护 | 源文和任务元数据不可改；文本禁止未转义标签，属性禁止未转义引号。此处通过不是浏览器 DOM 验证通过 |
| 4 | 术语 | 程序找出需复核的术语映射，独立审查逐单元判断上下文用词；不是简单的术语出现计分 |
| 5 | 数字、单位、公式、代码 | 核对数字/日期/版本及常见单位、数学符号；代码/MathML 保护片段不向返修开放。复杂单位换算和语义关系仍需审查 |
| 6 | 链接与图表资源 | 资源目标和源结构不可改；图片、SVG、MathML 标签、未知资源依赖标记待专门复核，不自动通过 |
| 7 | 翻译忠实性 | 独立角色核对整页全部单元，提交原文/译文定位证据、理由和具体缺陷 |
| 8 | 整页表达 | 独立角色提交跨章节术语、指代和逻辑关系审查；返修后整份旧结论失效，重新检查整页 |
| 9 | 实际页面表现 | 固定为 pending-stage9-browser-test；必须等阶段 9 的前端接入后实际点击与视觉测试，本阶段不能填“通过” |

所有报告均为 `publicationAllowed:false`。即使语义审查没有问题，也只到 `awaiting-resource-browser-human-review`，不是最终批准，更不是中文 L3 Pass。

## 审核调度策略

质量记录持久化并校验以下固定策略；策略被修改或生成强度不符时，控制器拒绝进入质量流程：

| 阶段 | 角色 | 推理强度 | 材料范围 |
|---|---|---|---|
| 翻译生成 | 翻译提供方 | high | 冻结页的全部章节任务 |
| 首次语义审查 | translation-review | medium | 完整中英页面 |
| 定点返修 | translation-repair | high | 净化缺陷允许的英文单元 |
| 返修后复验 | translation-review | low | 完整中英页面 |

`stage2_inspect_translation_quality` 的 `reviewSchedule.next` 返回下一阶段、角色、强度和范围。`stage2_read_translation_quality_packet` 必须提交匹配的 `reasoningEffort`；不匹配时不会交付材料。机械缺陷在首次语义审查前被修复时，下一步仍是 medium 首审；只有已经存在语义审查历史的返修，下一步才是 low 复验。

low 复验仍重新读取整页，因为定点修改可能影响跨章节术语、指代和逻辑关系；它降低推理强度，但不会假装减少输入 token。所有能确定性完成的门禁继续由程序执行，不调用模型。

## 角色与接口

| MCP 配置 | 接口 | 权限 |
|---|---|---|
| translation-quality | stage2_begin_translation_quality、stage2_inspect_translation_quality | 从完整 Batch 初始化检查记录、查看门禁结果；不能提交语义证据或返修 |
| translation-review | stage2_read_translation_quality_packet、stage2_submit_translation_review | 获得当前整页中英对照、源 HTML、术语、源文疑点；只能审查，不能改译文 |
| translation-repair | stage2_read_translation_quality_packet、stage2_repair_translation_units | 只获得已定位缺陷的单元、术语和净化问题；不能读取旧审查答案或提交审查证据 |

三个配置都绑定 STAGE2_MCP_PAGE_ID。review/repair 还必须明确配置不同的 STAGE2_MCP_WORKER_ID；同一检查记录中参与返修的身份不能作为审查者，审查者不能返修。full 协调配置也不暴露审查提交与返修写入工具。

审查与返修各使用新的独立进程/任务。调度方先读取 `reviewSchedule.next`，以指定强度启动对应角色，再把相同 `reasoningEffort` 传给任务包接口。单进程按 offset=0 顺序完整读取当前材料，每次最多 12000 字符；未读完、跳页、换检查记录、版本或调度强度改变时拒绝提交。每个进程只尝试提交一次。新工具需要重连 MCP 后可见。

身份隔离依赖可信启动方正确配置，不是密码学意义上的身份认证。证据校验能阻止缺页、错误引用和越权修改，不能由程序证明审查理由的知识判断一定正确；最终仍保留人工验收。

## 审查合同

每个可译单元都必须在 checkedUnits 中出现一次，包含 unitKey、与源/译文精确匹配的引用、实质性 rationale。另有完整 wholePageRationale 和 findings。

findings 只接受规则 4、7、8，必须绑定真实单元、原文和译文引用及具体原因。无依据的引用、漏掉的单元、重复单元、缺少整页检查、伪造 reviewerId/revision 等字段都被拒绝。语义角色不负责把浏览器/资源的 pending 改成 pass。

该合同由 `stage2_read_translation_quality_packet` 下发。模型或人工提供的材料是数据而非指令。审查不允许改写中文事实，也不能借引用文本执行指令。

## 修复闭环

1. 初始化检查，对 Batch 结果保留独立副本，绑定源快照、计划和译文摘要。
2. 机械问题直接定位到单元；语义问题由独立审查提交。
3. 修复者只能替换当前缺陷允许的英文单元；不能修改其他章节、原文、术语表、链接目标或证据。
4. 每次提交必须匹配当前 revision，拒绝无变化的返修；写入使用检查记录锁及原子替换。
5. 修复后自动重跑程序检查，清除当前语义结论，但保留旧审查和修改历史；必须重新完成整页语义审查。
6. 最多两轮修复；仍有缺陷，或结构问题无法定位到可修单元时转 manual-review-required，不降低规则、不无限重试。

此流程不自动生成修复文本、不自动发出付费 Batch。后续如需要把独立语义审查或返修任务批量交给 API，必须新增对应结果合同与角色路由，不能把本阶段完成误解为这些付费任务已经自动运行。

## 存储与测试

记录位于独立翻译数据根目录 `quality/<pageId>/<reviewId>/review.json`，包含不可变初始材料、当前译文版本、两轮限制、审查证据及修改历史。读写不接触 `.stage2/state.json`、私有中文审计、正式中文页或英文发布文件；原 Batch 记录不被返修覆盖。

`npm run test:translation-quality`：12 项隔离测试，覆盖门禁待审状态、调度强度、生成强度、定位、越界修复、证据完整性、身份分离、返修失效、轮次限制、过期、注入保护及 MCP 权限。

`npm run test:stage2`：完整回归包含上述质量调度测试；Batch 成功结果到质量检查的材料接入也在模拟端到端测试中覆盖。没有真实页面翻译、实际语义审查、付费调用或浏览器测试。

下一步是阶段 9：英文重组、前端展示、资源处理、实际浏览器测试与受控发布。
