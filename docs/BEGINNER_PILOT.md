# 首个双语入门单元：产品设计与用户测试

状态：设计稿，2026-09-07。不是理解页正文、审计结论或已批准出版候选。

## 选择依据

官方路径第 `1` 页为 `supervised-learning`（监督学习），已通过 Stage 2 MCP 精确解析。首个样板围绕现有页面验证“从带答案的例子学习规律”能否讲清楚。正式内容只能从 Stage 2 受控流程取得；本设计不向内容生成 Agent 的固定提示词添加指令，不绕过逐页/逐章合同。

这只是完整产品“理解基础原理”入口的第一个样板，不代表覆盖全部 AI，也不改变官方学习顺序。全貌入口后续在同一产品中建设，不用一页监督学习代替 AI 世界全景。

## 用户任务与学习结果

用户为没有编程或数学专业背景的中文 / 英文读者。目标是验证能否：

1. 解释例子、输入、目标答案与模型预测之间的关系。
2. 区分学习阶段与使用阶段，并理解新例子可能预测错误。
3. 在一个新的日常场景中判断是否适合用带答案的例子学习，说明理由。
4. 在网站中找到当前概念、查看已有关系并知道如何继续学习。

这些是待验证目标，不是对现有正文的评价，也不预设一页已经覆盖所有目标。

## 最小完整旅程

语言入口 → 监督学习理解页 → 复述或应用问题 → 当前概念的关系视图 → 官方下一学习项。

- 中文与英文页面分别具备可直接访问的地址；切换语言保留概念身份。
- 手机和电脑都能阅读正文、看关系、返回原位置。
- 阅读无须账号；现有本地进度保留。账号同步属于后续 M3 工作。
- 用户可以明确反馈“看不懂”“怀疑有错”或“导航困难”。反馈入口实现前，首轮研究使用观察员记录。
- 未准备好的英文明确标记，不将中文回退当成英文样板已完成。
- 独立 HTML 与交互地图使用同一受控版本；不手工复制一套脱离源版本的理解正文。

## 第一轮用户测试协议

每种语言先邀请 5—8 位目标用户。小样本只用于发现问题，不推断全体用户表现。记录实际语言能力、AI 接触经历、设备和测试版本，不要求姓名或无关个人信息。先获得参与和必要记录的同意；用户可跳过问题或停止。

1. 开始前：让参与者解释“模型如何从例子学习”，允许回答不知道；记录原话。
2. 不讲解界面，请参与者找到基础学习入口并打开样板。记录是否需帮助以及卡住的位置。
3. 请参与者阅读，允许正常使用网站；不要边读边教答案。
4. 阅读后先请其用自己的话解释，再给与正文不同的日常场景作应用判断。
5. 请参与者查看关系、返回正文并找到下一项；单独记录操作问题。
6. 最后问“哪句话或哪张图最难理解”“还有什么问题”，满意度作为辅助信息。
7. 愿意回访者可在数日后用另一场景复述，观察是否保留核心理解。

应用题及评分依据应在实际候选确认后编写，避免在未读候选前生成题目当作正式审计证据。任务应检验目标概念，不依赖参与者不熟悉的文化背景或额外术语。

## 观察记录模板

| 字段 | 记录内容 |
|---|---|
| 匿名参与者编号 / 日期 | 不记录无关个人资料 |
| 语言 / AI 经验 / 设备 | 用于判断问题来源 |
| 页面版本 / 测试任务版本 | 与实际受测页面绑定 |
| 学习前解释 | 原话与不确定处 |
| 入口、关系和下一步任务 | 独立完成 / 需帮助 / 未完成，以及原因 |
| 阅读后解释与新场景应用 | 原话与判断依据，不只记总分 |
| 内容或交互问题 | 位置、现象、严重程度 |
| 修改建议 / 复测结果 | 具体改动及是否解决 |

第一轮完成条件：记录每位参与者的主要卡点，按事实、讲解、前置知识、语言、交互分类，修复阻断核心旅程的问题后复测。尚无真实测试，不填写通过率、不宣称学习时长或效果已验证。
