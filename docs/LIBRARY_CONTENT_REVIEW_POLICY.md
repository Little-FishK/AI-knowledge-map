# 专业资料库内容审核机制

版本：1.1（人工试行）｜日期：2026-09-23

来源资格见 [来源机制](FRONTIER_SOURCE_POLICY.md)。本文件决定合格来源下的哪些内容值得收录、如何合并及维护。审核通过表示适合作为可追溯资料提供，不等于文中所有结论已验证，也不自动改写节点或理解页。

## 0. 系统收录目标（2026-09-23 补充）

学术投稿的重要性采用 [学术论文重要性审核机制 v1.2](ACADEMIC_IMPORTANCE_POLICY.md)，以已核实的专业评价机制及其正式结果为依据。按领域、年份、赛道与奖项逐项核验；来源合格、普通录用、AI自评或高引用不自动通过。宁缺毋滥，不设收录配额。按相关分类、专业关键词、成熟评价与文献线索三路合并建立候选池，再执行重要性审核。收集入口不以获奖为前提。范围、身份与去重见 [arXiv 收录办法](ARXIV_COLLECTION_SCOPE.md)。下面的批次示例不限制收录总量。

## 1. 发布多少：数量是审核结果

不设每来源最低数、固定配额或永久上限。首次整理可先找 3—5 个代表候选作为工作批次，通过几项就处理几项；此数不是首页展示量，也不是永久总量。高产来源不能因同类名额已满而被拒绝，低产来源不凑数。

新增独立条目数 = 合格候选去除重复、版本更新和已有覆盖后剩下的独立资料对象数。一次发布可以增加零个、一个或多个条目；多个页面也可以只组成一个条目。

持续收集时先完整登记指定栏目一个批次的发布记录，再审核，不只挑看起来容易通过的内容。学术投稿按《arXiv 待审文章收集要求》冻结日期、分类、关键词与外部名单；2026 年试验允许缺必要证据即暂缓，证据齐备者完成六步审核。审核能力不足时进入队列，不自动降低门槛。精选展示位、推荐排序和分页数量属于展示设计，另行决定。

## 2. 审什么：读者用途与资料对象

每项先写一句“它帮助谁解决什么问题”，并关联至少一个已有节点或知识区。用途可以是理解概念、使用资源、核对事实、比较方法、研究进展或复盘失败，不限基础教程，也不强迫所有专业内容都适合初学者。

按“成果/资源 + 具体问题 + 版本”识别资料对象，不按 URL 数量计数：

- 同一成果的论文、模型卡、代码、发布说明作为不同入口关联起来；不同媒介本身不构成新增理由。
- 补丁、服务迁移、同一评测的新版本通常更新原条目，保留日期与版本历史。
- 同一品牌的新架构、独立研究问题、不同评测对象可以单列，但需写出独立用途；不能把整家机构压成一张卡。
- 独立评测与厂商模型说明可以各有条目：两者回答不同问题，交叉链接即可，不因模型名相同就合并。
- 官方操作指南、维护文档、失败报告、负面结果不要求首创或外界应答；内容审核不再重复来源四闸门。

## 3. 四项检查，不用总分抵消缺陷

| 检查 | 需要写出的答案 | 不满足如何处理 |
|---|---|---|
| 相关性 | 对应谁的什么问题、哪个知识范围 | 仅笼统“与 AI 有关”不收录 |
| 实质价值 | 具体获得什么方法、资源、证据、解释或可迁移教训 | 宣传、预热、纯机构动态不收录；不能只凭标题判断 |
| 材料充分性 | 原文与关联原件是否足以支持拟写的简介和使用范围 | 缺关键材料或无法消解的核心矛盾则待补；可缩小到已有依据支持的用途 |
| 增量/重复 | 与现有库及本批候选比较，多了什么；关联哪个已有 ID | 纯重复不新增；同一对象实质更新合并；独立用途才新增 |

材料充分性随类型判断，不一律要求开源、同行评审或可复现：

| 内容类型 | 最低需要检查 |
|---|---|
| 模型/系统/资源 | 具体产物、版本、原件或使用入口、适用范围；能力比较保留为作者报告，不能当作本站实测 |
| 研究/评测 | 研究问题、方法或任务说明、主要观察、限制；统计结论需保留关键测量条件和不确定性 |
| 文档/指南 | 适用版本、可执行的步骤或明确接口说明、使用条件；本轮未实际运行就不声称已实测 |
| 事故/复盘 | 事件、已知原因、处置与可迁移教训；当事方说法与独立证据区分 |
| 框架/观点/综合分析 | 明确论证、可追溯依据和适用范围；标记建议或分析，不能写成既定标准或事实 |

资料有价值而结论不稳健，可以收录为“测量局限案例”；只有一句自夸、核心依据完全不可见，则不能靠免责声明变成合格研究资料。

学术论文还必须先通过独立的重要性门槛；本节的实质价值判断不能代替外部评价证据。

## 4. 四种结果

| 结果 | 条件与动作 |
|---|---|
| 收录 | 相关、实质、有足够材料支撑限定用途、有独立增量；建立一个资料对象 |
| 更新已有条目 | 指明已有 ID 或本批合并目标；维护入口/版本/限制，原始记录保留 |
| 待补证据 | 指明阻断发布的具体缺口与下一步；无依据时不先写肯定结论 |
| 不收录 | 写明不相关、无实质价值、完全重复等原因；不影响来源资格 |

一个条目可以通过，但某个字段仍待核实。只有该缺口阻断核心用途时才把整条置为待补。例如架构资料可收录，而相互冲突的当前 API 路由必须留空或明确标为冲突。

首次建库没有合并目标时：先审核并创建对象，再附各版本；不能假装已有条目。多条拟新增资料合并时指定唯一主条目，其余记更新，统计不能重复。纯转载且无补充价值则不收录，不制造一次无意义更新。

## 5. 每条审核记录

保存候选标题、URL、发布/更新/查阅日期、来源 ID、栏目、内容类型、读者用途、节点/知识区、四项判断、材料定位、已有 ID 或拟建对象、结果、理由、证据状态及复核触发条件。

证据状态用普通语言说明，如作者自述、外部评测、合作评测、部分信息非公开、观点建议、历史版本；它不替代最终审核结果。涉及共同研究、资助、预发布访问或发布方审阅时如实说明，不能把第三方署名自动当完全独立。

拟展示的最小资料卡：名称、解决的问题、一句收录理由、原始入口、版本/日期、关键限制。没有实质内容可写时，应回查是否只有名气或标题在支撑收录。

## 6. 维护

- 原件修正、撤回、替代或入口失效时复核对应条目；记录变化，不默默把新版本数字套入旧报告。
- 同站不同页面冲突时，先比较版本与更新时间，再查当前正式文档；不能简单认定公告或变更日志永远优先。无法消解则限制相关字段。
- 旧模型仍有研究价值可保留为历史资料；旧接口不能作为当前使用入口。
- 待补项有新证据时重审；未找到证据不能伪称不存在，也不自动转通过。
- 本轮实施的是人工规则和试审记录，没有上线自动抓取、自动发布或改造网站卡片。现有 selectionReason 中以来源四闸门代替内容价值的写法，后续应按本机制重审，不能批量视为已合格。

试验见 [20 条连续发布内容试审](LIBRARY_CONTENT_REVIEW_PILOT_20260923.md)。这是两种发布栏目下的机制测试，不代表全站合理收录比例。


范围收紧（v1.1）：只收录有外部证据支持对AI发展有重大贡献的论文。获奖不单独通过；取消学科覆盖目标，跨领域评价仅定向补证。与此前“遍历全部评价名单”的表述冲突时，以本条及重要性机制第4节为准。
