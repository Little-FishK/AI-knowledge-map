# 追前沿来源选材标准

版本：1.0
生效日期：2026-09-22

本文定义专业资料库二级来源的入选标准。它解决一个具体问题：**按"是否有名、是否权威"选来源不可执行，也无法维护**。旧标准下会出现"2025 年 7 月已关闭的索引"与"实时更新的榜单"被并列为同等来源，以及"某类机构形态"被当成"某类用途"来凑数。本文件把标准改成对**出处**的判定。

## 1. 三个"重要"的常见定义都是陷阱

"权威的、重磅的、引领的"这三个词不能各自成为标准，因为在追前沿这一区，"权威"不能按"公认"定义——前沿的定义就是还没有共识。坚持"公认权威"只会得到两种结果：要么选不出东西，要么选出一堆**事后总结**（年度回顾、Top 10、解读文章）。它们看起来最重磅，但永远是跟着跑的。

把三个词统一到同一个属性上：**它是不是前沿的原产地**。

## 2. 四道硬闸门

缺一不可。**一个闸门一个问题，必须能用"是/否"回答**，否则标准不可执行。

| 闸门 | 问题 | 通过意味着 | 它杀掉谁 |
|---|---|---|---|
| 一手 | 我引用的是它**自己产出的**，还是它**转述别人的**？ | 是原始产物的宿主：论文、模型卡、技术报告、标准文本、原始榜单、原始数据库 | 转述型媒体、解读号、综述博客、聚合站 |
| 首创 | 近 12 个月，是否至少有一个"第一次"发生在它这里？ | 它是某类产物的首发者或唯一标记体系 | 榜单搬运站、跟风聚合、二手排行榜 |
| 应答 | 它的新产出是否会被独立来源引用、复现或对比？ | 进入了他人的证据链 | 自说自话、无人应答者、空壳类目 |
| 归属 | 它能明确挂到某个已有节点、或归属到某个区吗？ | 挂得上，进入得了正文或 activity | 挂不上的空壳 |

**时效不设闸门。** 时效是追前沿的默认属性，不是筛选条件。但必须登记 `cadence`（多久回来看一次），那是给维护者用的，不是用来淘汰的。

## 3. 30 秒判断流程

对任何候选来源只问三句：

1. 我引用的是它自己产出的，还是它转述别人的？→ 答"转述"，直接出局。
2. 抹掉它，有没有某个"第一次"就查不到了？→ 答"是"，进 S 级候选。
3. 它最近一条产出，有独立第三方引用、复现或对比吗？→ 答"是"，进 A 级。

## 4. 分级

| 级别 | 含义 | 在本站的用法 |
|---|---|---|
| `S` | 原产地：一手、有首创、被应答 | 可直接支撑概念或事实断言，可作为节点与 activity 的来源 |
| `A` | 可靠的实测或原始记录，首创性或覆盖度稍弱 | 可支撑事实断言，重要结论建议二次交叉 |
| `B` | 原始记录型但范围窄，或机构形态本身不保证一手 | 作背景与交叉验证 |
| `archive` | 曾合格但已停更、冻结节或降级 | 只作历史记录，引用必须注明状态 |

**级别与健康度不能互相补偿。** S 级来源一旦进入冻结或降级状态，必须降到 `A` 或标 `archive`；校验器强制"`tier: S` 必须 `health: active`"。

## 5. 归属区（`originScope`）

资格与归属是两件事。一个来源完全合格，不代表它服务于当前你要做的板块。

`originScope` 取六大区之一，或 `cross` 表示跨区：

`foundations`（基础 / 共享）、`building`（应用搭建）、`coding`（编程与 Agent）、`generation`（内容生成）、`safety`（安全与对齐）、`frontier`（追前沿）。

这条直接修正了一个常见误判：**MITRE ATLAS 与 NVD 不是"放错了类"，而是 S 级 / B 级资格 + 安全区归属**。它们该留在资料库里，只是不该被算作追前沿的来源。

## 6. 其余治理字段

| 字段 | 取值 | 用途 |
|---|---|---|
| `provenance` | `primary` / `secondary` | 相对于本站在该来源上要支撑的断言，是否为原始产物 |
| `purposes` | `concept` / `fact` / `news` / `discovery` | 明确服务哪一个作用：定义概念、核对事实、追踪资讯、发现候选 |
| `cadence` | `daily` / `weekly` / `monthly` / `quarterly` / `yearly` / `static` | 维护者回访节奏 |
| `health` | `active` / `maintenance` / `degraded` / `retired` | 当前是否还能被引用 |
| `sourceUse` | `evidence` / `explainer` / `market-forecast` / `discovery` | 在本站的角色 |
| `lastVerifiedAt` | `YYYY-MM-DD` | 来源状态（不是档案文案）的最近复核日期，超过 180 天触发告警 |

两条派生规则由校验器强制：

- 声明 `purposes` 含 `news` 的来源，`cadence` 不得为 `static`；
- `sourceUse: explainer` 与 `market-forecast` 必须 `provenance: secondary`。

## 7. 三类来源的定位澄清

这三类都留在库里，但不参与"事实源"的比较：

- **权威创作者 → `explainer`（讲解源）**。创作者的一手性在"讲解与实现"，不在"事实来源"。Karpathy 讲的东西全部来自论文与官方文档。它们服务节点正文的"为什么这样"，不服务追前沿的事实供给。
- **咨询与市场研究机构 → `market-forecast`**。产出的是对已有事实的加工与预测，不是新事实。作为商业决策参考保留，不参与前沿事实源排序。
- **黑客马拉松 → `discovery`（发现入口）**。赛题与获奖原型是"第一次出现"的一手产物，但演示不等于生产可用。

## 8. 出局清单

不论多有名的，一律出局：

1. 转述型媒体的 AI 新闻（"报道别人发布了什么"）；
2. 二次总结（年度回顾、Top 10、综述博客）；
3. 已停更或已关闭且无替代的索引（例：Papers with Code，2025-07 关闭）；
4. 无任何官网与条目的空壳类目兜底（例：`benchmark-other`）；
5. 只有人气、没有一手产物的榜单搬运站；
6. 纯索引与聚合（例：Semantic Scholar 一类）；索引不是原产地。

一句话判据：**只收"原产地"，不收"转口港"。**

## 10. 维护

- 每次修改来源清单或档案后运行 `node tools/validators/library.js`；
- 定期运行 `node tools/validators/library-links.js` 检查链接存活。该脚本把 400/403/406/412/429 与重定向环路归为"站点拒绝自动化访问，需人工确认"，把跨主机 2xx 归为"域名已迁移"（链接仍可用，建议改档），只把 404/410/5xx/域名无法解析视为失败；新增来源可用 `--only <子串>` 定向复核；
- `lastVerifiedAt` 超过 180 天会被校验器列为待办；
- 判定结果来自公开检索，登记时必须逐条复核；本文件中的具体状态（日期、版本、数量）都可能变化，引用前重新核对。
