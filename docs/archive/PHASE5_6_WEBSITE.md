# 第五、六阶段：独立阅读与网站发布基础

本轮范围由维护者指定：暂缓第二阶段入口重设计和第四阶段新英文翻译，先实现独立 HTML、地图连接、构建发布流程及阅读体验。构建完成不代表内容审核通过，不修改正文或审核结论。

## 地址合同

- 正式基址默认 `https://little-fishk.github.io/AI-knowledge-map/`，支持构建时替换 HTTPS 域名和目录前缀。
- 中文：`zh/concepts/<pageId>/`；英文：`en/concepts/<pageId>/`。
- 地图继续使用 `?lang=zh-Hans#/map/<pageId>`；旧 `#/concept/<pageId>` 在对应静态页存在时跳转，地图路由仍可独立使用。
- 语言切换及 hreflang 只指向同一产物内真实存在的语言版本。本轮控制器只生成中文，不制作新英文，不复制过期英文样板。
- 不存在的页面返回 404，提供地图和搜索入口，不伪装成首页成功响应。

## 内容与构建门槛

`node tools/build-website.js preview` 通过 Stage 2 MCP 读取已展示的中文源，生成全站本地预览，所有页面保留醒目预览提示和 noindex。预览不包含未发布候选正文，不覆盖现有站点目录。

`node tools/build-website.js production` 要求当前中文源与控制器人工批准摘要一致、无活动租约、无阻断，且当前完整 v4 审核通过。没有合格页面时拒绝生成生产包。不得手改清单 eligible 或 mode 绕过门槛；清单摘要用于检测漂移，不是密码学签名或人工批准的替代品。

每次产物位于 `.tmp/site-releases/<mode>-<time>-<id>/`；记录页面源摘要、语言、文件摘要、大小、排除原因。运行：

```text
node tools/verify-website.js <产物目录>
node tools/serve-website.js <产物目录> 4993
```

首页只加载图谱与必要脚本；理解页按需加载，静态阅读正文无需 JavaScript。文字目录提供原图关系方向，全文索引仅在搜索页使用。资源超时给出失败状态，可重试。动态目录和图表滚动增强不改控制器正文。

## 发布、预览与回滚

1. 通过控制器构建 production 包；核对本次排除清单，避免误以为所有内容已可发布。
2. 在本地预览验收该精确包。将通过验证的产物作为 `site-release/` 提交到独立发布提交；不要复制仓库根目录、私有审核或预览包。
3. 首次发布使用隔离的 `gh-pages` 根目录分支，只提交验证后的 `site-release/`。这是为了避免把本地主分支领先远端的其他提交和未提交工作一起推送。GitHub Pages 发布源设置为 `gh-pages /`，HTTPS 保持启用。
4. 后续可在主分支整理并合并发布工作流后改用 GitHub Actions；在此之前继续从相同构建门槛生成独立发布提交，不让 CI 读取本机私有 Stage 2 状态。
5. 发布后验收根目录、中文深链接刷新、旧 hash、404、搜索、移动端；保存发布分支提交、Pages 构建提交和访问结果。
6. 回滚：恢复上一个已批准发布提交中的完整 `site-release/`，验证摘要后重新手动部署。保留两个版本及其清单，不通过重新生成内容模拟旧版本。

流程参考 [GitHub Pages 自定义工作流官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。项目子路径下的 robots.txt 不是域名根 robots.txt；在当前 GitHub Pages 托管结构中，预览主要由 HTML noindex 和仅本地服务保证，生产 sitemap 可单独提交。不得宣称已提交搜索引擎或已有收录。

## 验收维度

- 自动：中文不依赖英文、缺失译文无假链接、完整 HTML、文件摘要、未管理文件、内部链接、预览禁止部署、路由回归。
- 浏览器：独立页、目录搜索、目录跳转、地图返回、旧链接、404、手机窄屏、键盘聚焦。
- 范围限制：字体和可滚动容器不等于每张图表已经逐项验收；键盘支持不等于完整 WCAG 合规。真实读者学习效果、屏幕阅读器人工检查及线上 Core Web Vitals 留待实际验收，不冒充通过。
- 当前不做：新英文翻译、学习入口重设计、账号同步、线上引擎收录与品牌推广。
