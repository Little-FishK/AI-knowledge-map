# 竞赛与黑客马拉松内容审核机制

版本：1.1（试行）｜日期：2026-09-24｜原则：独立机制、单次审核、五项硬门槛、合格全收

本机制只适用于专业资料库一级来源“黑客马拉松”下的竞赛、黑客马拉松和社区构建活动成果。它独立决定本类内容是否进入资料库，不继承学术论文、标准与监管、官方技术资料或其他一级来源的门槛、评分与审核结论。

**黑客马拉松不设候选池与二阶段审核。每个被检查的项目直接接受五项硬门槛审核，五项全部通过才收录；不用总分，也不能用名次、奖金、平台声望或某一项优势抵消另一项缺口。**

## 1. 审核对象与适用范围

审核单位是“具体赛事 + 团队提交成果 + 可访问产物”，不是赛事平台的整个网站，也不是只有一个 URL 的页面。

只有报名页、倒计时、宣传视频、颁奖新闻、团队合影、项目口号或产品营销文案的页面，不构成独立资料对象。它们可以帮助确认赛事或奖项，但不能单独通过内容审核。

## 2. 五项硬门槛

五项逐项记录为 `pass`、`unknown`、`fail`。

| 门槛 | 必须确认的内容 | `unknown` 的典型情形 | `fail` 的典型情形 |
|---|---|---|---|
| 1. 身份可确认 | 官方赛事页、结果页、团队/作者信息与成果页面能够对应 | 结果页暂不可访问，团队名称与作者对应关系不完整 | 只有转载、项目自称获奖，或无法确认属于该赛事 |
| 2. AI 专业相关 | 能关联到现有节点、软件，或写明明确的待建 AI 知识区和关联理由 | 可能使用 AI，但材料不足以判断核心方法 | AI 只是宣传标签，核心成果与 AI 知识或实践无关 |
| 3. 产物可访问 | 至少有代码、模型、数据集、技术报告中的一种可访问产物 | 原件声明存在但暂时受限、失效或需补充访问条件 | 只有视频、幻灯截图、宣传文案、口号或无技术内容的展示页 |
| 4. 知识有增量 | 相比现有资料或本批重复项目，明确增加新的工作流、实现方式、数据资源、评测方法或应用约束 | 产物可见，但尚不能判断与既有内容的差异 | 只把常见 API 接到常见界面、只有功能清单，或完全重复已有成果 |
| 5. 奖项符合要求 | 获得赛事主奖、正式赛道冠军，或具有明确 AI 技术主题的专项奖 | 奖项名称含糊，或无法确认 Finalist/Runner-up 是否属于正式授奖档位 | 仅为 Honorable Mention、普通入围、社区推荐、编辑精选、主办方展示、排行榜前列或未获奖项目 |

五项门槛互相独立。奖项符合要求不能替代技术产物或知识增量；反过来，产物完整、方法优秀但没有符合要求的奖项，也不能进入本一级来源。

### 2.1 奖项符合要求的解释

以下三类可以通过第五项门槛：

1. **主奖**：赛事总榜冠军、亚军、季军，以及主办方明确设置并实际授予奖金、奖品或同等级正式权益的其他主奖名次；
2. **赛道冠军**：正式技术赛道、任务赛道或应用赛道的第一名/冠军；
3. **明确技术主题的专项奖**：奖项名称和评奖说明直接指向具体 AI 技术主题，例如端侧部署、模型微调、机器人、多模态、评测、安全、开源实现或特定训练技术，并且项目确因该主题获奖。

`Finalist`、`Semi-finalist`、`Runner-up` 等标签不能只按字面判断。若官方规则明确该档位获得奖金、奖品或正式名次权益，可视为主奖；若只是进入下一轮、获得展示资格或列入短名单，则第五项为 `fail`。

下列身份不能通过第五项门槛：

- `Honorable Mention`、社区奖、热度奖、编辑精选和赛后推荐；
- 没有正式奖项权益的 Finalist、Semi-finalist、入围或展示席位；
- 排行榜前列、高票、高热度、完整公开产物或赛后继续维护；
- 未获奖但代码、模型、数据或报告质量较高的项目。

泛化的“最具影响力”“最佳展示”“社区选择”等专项奖也不自动通过。只有评奖说明明确对应可识别的 AI 技术主题时，才满足第五项。

### 2.2 “技术报告”的最低含义

赛事平台上的 solution write-up 可以算技术报告，但至少要说明问题、核心方法、主要实现或实验依据，并足以写出受限定的知识增量。只有“使用了某模型”“做了若干特征”“以后再公开细节”等简短获奖感言，不算可访问技术报告。

### 2.3 组合创新如何判断

项目不必发明全新算法。将已有模型、Agent、工具、数据和评测组合成一个非显然、可解释、可复用的工作流，也可以通过知识增量门槛。反之，仅调用某个 API 完成常见聊天机器人、摘要器或网页包装，不因获得奖项而自动形成知识增量。

### 2.4 允许记录但不作为门槛的事项

许可证、隐私、安全性、生产稳定性、可扩展性和独立验证仍应记录在资料卡限制中，但不增加为本一级来源的准入硬门槛。某项目以后若要支持正式节点断言、教程结论或生产推荐，应进入目标内容体系自己的晋升与验证流程；其结果不反向改变本机制的收录结论。

## 3. 决定规则

| 结果 | 条件 | 动作 |
|---|---|---|
| `admitted` 收录 | 五项硬门槛全部 `pass` | 建立资料对象；默认 `discoveryOnly: true` |
| `merge-update` 合并或更新 | 五项全部通过，但与现有条目是同一成果、版本或补充入口 | 更新唯一主条目，关联赛事页、结果页和产物，不重复计数 |
| `pending` 待核实 | 没有 `fail`，但至少一项为 `unknown` | 写明缺口、待核实入口和下一步，不先按通过发布 |
| `ineligible` 不收录 | 任一硬门槛为 `fail` | 记录具体失败项；不据此否定赛事、团队或平台的其他成果 |

审核允许短路。若第五项明确失败，其余尚未核查的门槛记为 `not-assessed`，不能写成已经通过或失败。

## 4. 对象合并与来源归属

- 同一项目的赛事页、结果页、官方 write-up、代码仓库、模型页和数据集页组成一个资料对象，以关联材料保存，不按 URL 拆卡。
- 同一团队对同一成果的赛后版本通常更新原条目；出现新的独立任务、数据集或评测对象时才考虑单列。
- 同一赛事的数据集/基准只有在它属于通过第五项门槛的获奖成果时，才可随该成果建立或关联资料对象。
- 项目同时出现在多个赛事或平台时，以成果身份去重；各赛事成绩作为关联记录，不重复建立相同项目。
- 二级来源表示本站从哪个赛事平台或活动集合发现和核验对象，不对该平台全部内容背书。

没有通过第五项奖项门槛的项目，仍可由开源仓库、学术论文、官方技术资料等一级来源的独立机制另行审核，结论互不影响。

## 5. 最小审核记录

每条被审核项目至少保存：

- 项目标题、赛事名称、二级来源 ID、赛事页、结果/奖项页和成果页；
- 团队名、作者、官方名次或奖项、比赛结束日期和审核日期；
- 奖项类型属于主奖、赛道冠军还是技术专项奖，以及对应官方证据；
- 关联节点、软件或待建知识区及具体理由；
- 代码、模型、数据集、技术报告的入口和访问状态；
- 与现有资料相比的具体知识增量；
- 五项门槛的状态、理由、证据 URL 和页面定位；
- 最终决定、已有条目或合并目标、限制和待补事项；
- 复核触发条件。

资料卡必须把“赛事事实”和“技术事实”分开：官方结果页证明奖项，团队产物证明实现，二者不能相互替代。

## 6. 批次范围与完成条件

每个批次先冻结：二级来源、赛事集合、结束日期范围、检索日期，以及哪些官方奖项属于主奖、赛道冠军或技术专项奖。

批次报告至少列出：

1. 检查的赛事数量；
2. 赛事结果页发现的项目总数；
3. 通过第五项奖项门槛并接受完整审核的项目数；
4. 因奖项门槛失败而短路的项目数；
5. `admitted`、`merge-update`、`pending` 和 `ineligible` 数量；
6. 无法访问的结果页、产物入口和未覆盖范围。

只有冻结范围内的官方结果均获得明确处置，才能称该批次完成。抽查若干冠军、只看前三名或只看平台搜索首页不能冒充全量审核。

## 7. 维护与复核

出现以下情况时定向复核：

- 官方结果更正、取消资格或奖项归属改变；
- 官方规则补充说明某个 Finalist、Runner-up 或专项奖的正式权益与技术主题；
- 代码、模型、数据集或技术报告失效、删除或迁移；
- 项目形成实质新版本，或原有内容被证明完全重复；
- 资料库新增内容改变了原先的知识增量判断；
- 条目准备从发现材料晋升为节点证据、教程依据或生产推荐。

旧赛事不因时间过去自动删除；入口失效时先寻找团队或主办方保留的原件，无法确认则标记状态变化。

## 8. 与其他一级来源审核机制的关系

- 本机制与其他八个一级来源的审核机制相互独立，互不增加门槛、互不替代结论、互不继承通过或失败状态。
- 学术论文奖项规则不适用于本类；黑客马拉松获奖也不能替代学术论文的重要性审核。
- 官方文档、开源仓库或标准材料可以作为本条目的关联产物，但是否进入各自一级来源，由各自机制单独决定。
- 本机制通过只表示该获奖赛事成果值得作为可追溯的发现型资料进入专业资料库，不表示技术结论已经独立验证。

## 9. 机制验收标准

首次验证至少覆盖：

- 主奖且四项技术门槛完整的项目；
- 主奖但产物不足或知识无增量的项目；
- 正式赛道冠军；
- 技术主题明确的专项奖；
- Honorable Mention 或普通 Finalist 因第五项失败的项目；
- 有代码但与 AI 无关的获奖项目；
- AI 相关但只有视频或宣传文案的获奖项目；
- 简单 API 包装且获得奖项、但知识增量不足的项目；
- 同一成果多个入口或多个赛事的去重场景。

机制有效应同时满足：获奖不会自动通过；未获得合格奖项的项目不会因代码完整而进入；五项判断都有可定位证据；同一项目不会因多个 URL 重复建卡；其他一级来源的规则不会进入本类准入结论。
