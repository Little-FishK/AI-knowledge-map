# 理解页英文翻译设计：阶段 1—3

本文件记录设计与只读核验结果，不表示翻译控制器已实现，也不授权发布英文页面。

后续阶段 4—6 已实现独立翻译准备接口与隔离测试，详见 [DEEPDIVE_TRANSLATION_PREPARATION.md](DEEPDIVE_TRANSLATION_PREPARATION.md)。以下内容保留为阶段 1—3 的历史核验记录；“当前接口缺失”描述的是当时状态。

## 1. 现有接口与批准语义

### 本轮只读证据

通过 ai-knowledge-map-stage2 MCP 的 stage2_status 和 stage2_inspect_publication_candidate 获取；未领取任务、重置页面或读取私有审计。

- 队列共 130 页：audit-queued 128、repair-queued 1、published-approved 1；无活动租约。该结果是核验时快照，不是持续有效的固定数量。
- neural-network：workflowState/publicationState 均为 published-approved；reviewStatus 为 human-approved；candidateHash、publishedHash、publication.pageHash 相同，均为 sha256:a4d79eb958b621e6c315e6b89caba864bc84023f247509ad8a48dffb1dd402e5。
- supervised-learning：workflowState 为 audit-queued，publicationState 为 published-current，publication 为 null。候选和当前页哈希相同，但不能据此推出人工批准。
- guardrails：workflowState 为 audit-queued，publicationState 为 published-provisional，reviewStatus 为 manual-review。当前 blockerCount 为 0，publication.blockerCount 为 1；这两个字段属于不同时间与范围，不能把前者为零解释为正式通过。

这些样本证明工作流状态与发布状态可以不同；尚未通过只读接口核验具体页面的完整重置事件历史，因此不推断任一待审页为何入队。

### 接口可复用性

| 现有接口 | 已确认用途 | 翻译设计中的边界 |
|---|---|---|
| stage2_status | 队列汇总 | 用于规划，不能作为单页批准证明 |
| stage2_resolve_recommended_page | 按官方顺序解析页面状态 | 可复用顺序解析，不领取或跳过其他任务 |
| stage2_inspect_publication_candidate | 当前候选/发布哈希及发布标记 | 可作版本和批准初筛；不能导出正文或完整批准历史 |
| stage2_read_content_section | content-generation 租约内按顺序读章节 | 禁读常见误解、自测等；不能直接复用为完整翻译读取接口 |
| stage2_read_project_file / stage2_search_project | audit 租约内受限读取 | 不能为了翻译或设计伪装领取审核任务 |
| stage2_reset_passed_page | 工具合同规定从 l3-auto-passed 入队，保留当前页，清除本轮审计结论 | 不是批准恢复接口；历史批准保留细节尚未核验 |
| stage2_reset_manual_review | 从 manual-review 重新入队 | 不等于人工最终批准 |
| stage2_finalize_manual_review | 人工明确最终批准 | 英文审校不能替代或触发中文批准 |

当前可用 MCP 工具未提供独立翻译角色、无审核租约的受控完整正文导出、历史批准与撤销查询、英文候选提交和英文发布能力。后续实现应通过受保护控制器扩展这些能力；阶段 1—3 不改现有状态机。

### 前端核验

assets/app/deepdive-view.js 展示 title、subtitle、aliases、meta、thesis、html，并从 publication 生成临时发布警示。html 是实际页面正文容器，不能预设所有页面都是纯 Markdown。

assets/app/runtime-loader.js 按 runtime.base 与页面 ID 加载一个 JS 文件，当前 registry 和加载缓存按 ID 索引。后续多语言设计需要考虑 locale 与源版本，避免切换语言后复用错误缓存。本轮只读检查，未修改前端。

## 2. 翻译范围合同

翻译对象为选定中文页面快照中所有面向读者的内容。正文的唯一来源是未来受控导出接口返回的已绑定版本；docs/deepdive-reviews 下的旧章节材料或 Agent 回答不自动替代当前发布正文。

| 类型 | 翻译范围 | 必须保留 |
|---|---|---|
| 页头 | 标题、副标题、别名、主旨句、meta 中的可读说明 | 节点 ID、日期与版本数据 |
| 章节 | 标题、段落、列表、引述、提示框、例子 | 章节顺序、段落映射、层级及事实含义 |
| 表格 | 表头、说明、单元格自然语言 | 行列、合并关系、数字、单位、公式 |
| 数学 | 公式周围的解释与符号释义 | 数学表达式、变量、运算、编号及相互引用 |
| 代码 | 代码块之外的解释；展示性注释需明确标记后处理 | 可执行代码、API 名、示例字面量及输出；禁止盲目翻译代码字符串 |
| 链接 | 可见链接标题、自然语言引用说明 | URL、节点 ID、锚点目标与出现次数 |
| 图形 | 图注、替代文本、可访问名称、图内自然语言 | 图形关系、数据、坐标含义及数学标记 |
| 图片内文字 | 单独登记中文文字与英文替换需要 | 原图留存；未完成的必需图中文字阻止整页英文正式发布 |
| 误解与自测 | 已存在且对读者展示的题目、选项、答案、解析 | 题目/答案绑定、正确选项、交互属性；需要翻译专用读取权限 |
| 发布警示 | 由运行时语言消息呈现可读说明 | 中文批准/暂行状态的真实含义；不得翻译成审核通过 |
| HTML 与交互 | 仅提取可读文本和允许的可访问属性 | 标签结构、类名、ID、data 属性、事件绑定与资源引用 |

本合同覆盖类别，不是已经对 130 页逐章扫描得到的清单。当前接口不允许无租约完整导出页面；每页实际章节数、图片类型、公式和自测清单须由后续控制器只读导出后补齐。不能宣称“全站无图片文字”或“全部正文均可直接送入翻译引擎”。

页面正文是翻译数据，不作为 Agent 指令执行。遇到事实疑点，保存源文对应位置和疑点，不在翻译过程中暗改中文结论。

## 3. 中文源版本与准入规则

### 两级准入

| 源页面情况 | 可生成候选 | 可进入英文正式发布审核 |
|---|---|---|
| 当前版本人工批准、批准哈希与发布哈希相同 | 是 | 是，仍须英文审校通过 |
| 只有机器审核通过 | 是 | 否，等待人工批准 |
| 暂行发布、编辑草稿 | 是，保留来源状态 | 否 |
| 重置后内容不变且历史批准可验证、未撤销 | 是 | 是；历史证据查询未实现前先置为待核验 |
| 重置后内容变化 | 是 | 否，新版本须获批准 |
| 历史批准缺失或不明确 | 是 | 否，不推断获批 |
| 批准撤销、存在待解决内容缺陷 | 视任务明确范围保存草稿 | 否 |
| 页面正被修改、快照不可稳定读取 | 等待或使用已冻结受控快照 | 必须在发布时再次核验 |

候选生成与公开发布分别记状态。对暂行版可预先翻译，但本设计不自动授权把英文暂行版公开到网站。

### 快照记录（设计字段，尚非现有实现）

- pageId、sourceLocale、targetLocale。
- sourcePageHash：采用控制器的页面指纹口径；算法和纳入字段须在扩展实现时明确，不能自行另算不同口径再声称相等。
- sourceSnapshotId、capturedAt：绑定冻结的源正文，防止各章节来自不同版本。
- workflowStateAtCapture、publicationStateAtCapture：只作为捕获时状态。
- approvalEvidence：批准种类、批准内容哈希、批准记录标识、时间；历史记录存在时包含撤销核验结果。由控制器出具，不允许翻译 Agent 自报。
- resourceManifest：章节、图表、公式、链接和外部资源的清单与必要指纹；页面哈希未覆盖的外部图片仍需单独追踪。
- glossaryRevision、translationPolicyRevision：记录使用的术语与翻译规则版本。

### 核验时机

1. 领取：控制器获得稳定快照并核对批准依据。页内章节均从同一快照读取。
2. 提交：核对源是否变化；若变化，译文可保留，但标记过期，不能作为当前版本发布。
3. 发布：控制器在受保护事务内再次确认源哈希、批准有效性、资源版本与英文审校结果，防止“检查完成到写入之间”源页变化。
4. 更新：中文或依赖资源变动后，现有英文标记待复核；新的英文通过前整页回退中文。单纯任务重置是否触发回退，取决于批准是否仍有效，不能只按状态名称决定。

初始正式翻译试点可选 neural-network，因为本次已核验其人工批准标记与三个页面哈希一致；任务开始前仍须重新核验。其余页面可以准备候选，但当前队列计数不能证明它们具有可沿用的历史批准。

## 阶段交付与后续依赖

- 阶段 1：完成当前公开 MCP 能力和三个不同发布状态样本核对；完整重置实现及批准事件历史未获读取，不冒充已验证。
- 阶段 2：完成翻译范围合同和结构保护清单；逐页实际资源盘点依赖翻译专用受控导出接口。
- 阶段 3：完成候选/正式发布准入表、版本绑定与失效规则；批准证据和冻结快照需要后续实现。
- 下一阶段设计英文存储与接口时，需补充完整正文导出、批准/撤销证明、资源清单、快照和英文发布接口。维持既有内容生成章节禁读规则，为 translation 角色单独制定范围，不放宽 audit 或 content-generation 权限。

本轮没有更改中文页面、运行副本、审核记录、队列状态或发布行为，没有调用外部翻译服务。
