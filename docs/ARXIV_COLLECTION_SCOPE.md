# arXiv 系统收录范围与重要性审核

日期：2026-09-23。用户要求：收录该来源所有重要且不重复的文章。此要求替代把单日10篇样本或首批3—5篇当作收录范围的做法。

## 1. 目标与边界

目标是尽可能完整地发现并收录本站知识范围内的重要、合格、非重复论文，不是挑几个代表作后停止。不设总量上限，不因已有同主题论文就拒绝新贡献。

覆盖历史与前沿两个轨道，时间不限。以现有130节点和六大知识区作为检索入口；尚无具体节点但对知识区有明确重要贡献的论文也可进入候选，不能为了匹配旧图谱漏掉新方向。与本站学习/研究用途没有明确关系的其他学科论文不因为在 arXiv 就全部收录。

不只查 cs.AI。结合主题检索 cs.CL、cs.LG、stat.ML、cs.CV、cs.SD、eess.AS、cs.RO、cs.SE、cs.CR 等相关分类，并处理跨类投稿。分类是发现入口，不是质量门槛。早于 arXiv 或仅在其他正式出版平台出现的经典原作，应记录为其他来源缺口，不制造 arXiv 版本。

## 2. 重要性采用外部正式评价

自2026-09-23起，以 [学术论文重要性审核机制 v1.1](ACADEMIC_IMPORTANCE_POLICY.md) 为准。先核实评价机制，再核实单篇正式获奖结果、身份与当前状态。重要性通过只开启后续内容审核，不自动发布。

旧版“基础方法、关键改进、关键资源、纠错、高价值综合研究”保留为贡献描述，不再是编辑或AI自行判定通过的通道。未获可采信评价的前沿预印本暂缓；经典论文也不凭记忆、名气或引用量自动通过。无证据不等于无价值，不改变来源资格。

## 3. 去重以研究贡献为核心

1. arXiv 基础 ID 作为身份键：abs、pdf、html 链接与 v1/v2/v3 归入同一记录，保留版本证据。
2. arXiv 与会议/期刊版本：核对 DOI、题名、作者与内容，通常保留一个成果对象并关联多入口。正式发表不自动等于完全相同，新增重要内容应记录。
3. 同一成果的论文、技术报告、代码与模型卡：先合成原件入口；其他来源已登记时更新/关联，不能仅因论文来自 arXiv 再发同内容卡片。
4. 不同 ID 不能仅靠标题相似自动删除。明确相同成果时合并，并保留被合并 ID 和依据。
5. 独立复现、负面结果、关键替代方法、不同用途的综述，只要有独立贡献就保留；“都讲 RAG”不是重复理由。
6. 全局只建一个资料对象，可关联多个节点、主题与发现渠道；跨分类、跨节点检索命中不重复计数。

## 4. 从评价名单发现论文

选择AI主入口的明确批次，筛查对AI发展的重大贡献线索；其他领域仅在已有具体线索时定向核查。再确认原件、获奖身份、版本、外部贡献评价与当前状态。使用题名、作者、DOI、arXiv ID 定向补查；不再以泛化关键词全量抓取作为默认发现流程。

历史轨道优先时间检验奖、经典论文奖；当届轨道使用已启用的论文贡献正奖。二者不按论文数配额截断，也不把当届获奖等同于长期影响。参考文献、引用索引和综述可以提供线索，但线索自身不能通过重要性门槛。

先前广泛检索的数据库仅保留为历史发现材料，其命中量不等于重大论文数，不自动重启采集，也不自动转入新规则的通过清单。

## 5. 如何报告完成程度

“全量收录”是覆盖目标，不能用一个固定条数宣告达成。每轮报告：

- 检索覆盖的主题/分类/年份/截止日与未覆盖范围；
- 发现数、去重后候选数、已审核数、收录数、合并数、待补数、排除数；
- 尚无候选的主题，以及有候选但未完成重要性核查的主题；
- 仍待核查的关键参考文献、修正或新增方向。

只有声明的领域、年份、赛道、评价机制名单已核查，名单候选均有处置，且本轮阻断性证据缺口均已说明，才能说“本轮名单审核已完成”。不以遍历整个arXiv或全部引文图作为完成条件，也不能宣称所有重要论文已收齐。
