# AI 软件目录 · 使用教程页规范

> 本文件是软件教程资源选择、写作与复核的唯一权威口径。
> 正式标准版本：1.0 · 2026-07-21

## 一、目的与数据位置

软件详情页回答“它是什么、最擅长什么”；使用教程页继续回答“怎样可靠地开始使用”。入口位于软件详情页顶部，阅读形态与概念的“理解原理”页一致。

教程数据独立存放在 `data/tutorials.js`，以软件 `id` 为键注册到 `window.TUTORIALS.items`。没有经过本规范三层审核的资源，不得作为正式教程显示。

## 二、平台分类与阅读方式

当前分类为 Bilibili、小红书、YouTube、GitHub、文章与文档。教程页使用侧边栏切换平台，一次只显示当前平台；没有合格来源的平台显示“尚未收录”，避免把来源缺口误当成不存在。

同一平台下的视频默认折叠，读者按需展开。平台不使用顺序编号；新增平台不能迫使读者滚动到页面底部才能访问。

## 三、正式收录的三层审核

审核顺序固定为：

```text
第一层：证据等级与硬门槛
          ↓ 通过
第二层：五项关键标准
          ↓ 全部通过
第三层：70 分质量评分
          ↓ 达到收录线
正式收录
```

任何资源必须依次通过三层审核。后面的高分不能补偿前面的失败。

### 第一层：证据等级与硬门槛

#### 1. 证据等级

先判断编辑实际掌握了多少视频内容，而不是先评价标题是否吸引人。

| 等级 | 可核验材料 | 处理方式 |
|---|---|---|
| **E0** | 视频无法访问，或只能看到转载标题 | 淘汰 |
| **E1** | 只有标题、封面和一句简短简介 | 只能进入候选池，不得生成正式总结 |
| **E2** | 已完整观看并留下逐段记录；或有较完整字幕、章节、详细简介及可见操作画面，足以还原关键步骤 | 可以继续参加正式审核 |
| **E3** | 有完整字幕或结构化人工观看记录，并有源码、配套文档、时间戳、官方资料等旁证 | 优先审核与收录 |

正式收录的最低证据等级为 **E2**。没有字幕不自动淘汰；但必须用完整观看和结构化记录补足证据。只根据标题、封面或简介推断操作内容，最高只能判为 E1。

#### 2. 硬门槛

出现以下任一情况，暂不正式收录：

1. 无法确认视频实际教授了什么，只能看到标题和一句简介。
2. 没有字幕、章节、详细简介、配套文档或源码，也没有完整观看记录，因而无法可靠提炼。
3. 内容主要是宣传、资讯转述或产品吹捧。
4. 操作过程不完整，只展示结果，没有关键步骤。
5. 使用来源不明的安装包、破解工具、共享密钥或高风险中转服务。
6. 版本已经明显过时，而且没有仍然有效的方法论价值。
7. 与现有教程高度重复，没有新增知识。

第一层通过条件：**证据等级达到 E2 或 E3，且没有命中任何硬门槛。**

硬门槛第 7 条只判断明显重复，不再设置独立的“地图贡献分”。如果两条视频教授相同内容，保留证据更充分、步骤更完整、版本更新或解释更清晰的一条。

### 第二层：五项关键标准

通过第一层后，对以下五项分别打 `0 / 1 / 2` 分：

| 标准 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| **准确性** | 存在核心事实或操作错误 | 基本正确，但有未核实或易误导之处 | 核心原理、命令和配置均可核验，易变信息已标注 |
| **目标—操作—验证对齐** | 标题承诺与实际内容不符 | 有操作，但缺少目标或验证 | 每个重要目标都有对应操作和完成验证 |
| **可复现性** | 只能观看结果，无法照做 | 可部分照做，但缺少环境、参数或关键步骤 | 相似环境中的读者可以独立复现 |
| **证据可追溯性** | 总结无法回到来源 | 只有部分内容可定位 | 关键结论都能回到字幕、画面、章节、源码或官方文档 |
| **安全性** | 存在未说明的明显风险 | 风险有提示但处理不完整 | 来源、凭证、权限、隐私和第三方风险均有适当说明 |

第二层通过条件：**五项必须全部达到 2 分。** 任一项为 0 或 1，都不能靠第三层总分补偿；应先补充证据、修改总结或更换资源。

### 第三层：70 分质量评分

只有通过前两层的资源才进入质量评分。评分用于决定正式收录等级和同类资源排序。

| 维度 | 权重 | 评估内容 |
|---|---:|---|
| **教学闭环** | 20 | 准备、操作、验证、排错是否完整 |
| **解释与迁移** | 15 | 是否解释为什么这样做，读者能否迁移到其他任务 |
| **内容完整度** | 15 | 是否覆盖标题和章节承诺的全部重要知识 |
| **结构与效率** | 10 | 是否清晰、有章节，是否避免重复和无关内容 |
| **时效与维护性** | 5 | 版本是否明确，过时部分能否识别和校准 |
| **可访问与可提炼性** | 5 | 字幕、章节、源码、画面和文字替代是否充分 |

每个维度先按统一锚点评为 `0—4` 级，再按权重换算，禁止直接凭感觉填写百分数：

| 等级 | 含义 |
|---:|---|
| **0** | 没有涉及，或与目标无关 |
| **1** | 只提到概念，没有形成操作 |
| **2** | 有演示，但过程、解释或验证不完整 |
| **3** | 完整演示，步骤清楚并可以复现 |
| **4** | 在完整可复现基础上，还包含排错、边界条件、原理解释或替代方案 |

单项换算公式：

```text
单项得分 = 该维度权重 × 等级 ÷ 4
总分 = 六个单项得分之和（满分 70）
```

收录等级：

| 总分 | 结论 |
|---:|---|
| **60—70** | 核心推荐；可作为该软件的主要学习入口 |
| **53—59.75** | 正式收录；质量合格 |
| **46—52.75** | 候选；需要补强后重新审核 |
| **低于 46** | 不收录 |

因此，正式收录必须同时满足：**第一层通过、第二层五项全为 2、第三层总分至少 53。**

评分不是行业认证，也不代表视频的绝对价值；它是本项目用于稳定编辑判断的内部规则。出现争议时，应保存各维度等级、证据和理由，而不是只保存最终总分。

### 评分如何记进数据并被强制校验

三层审核不再只停留在本文档，而是作为每条资源的 `review` 字段记进 `data/tutorials.js`，由 `tools/validate-tutorials.js` 强制校验：

```js
review: {
  evidence: "E2",            // E0|E1|E2|E3（第一层）
  status: "formal",          // formal | candidate（最终状态；formal 须过全部三层）
  reviewedAt: "2026-07-21",
  standards: { accuracy: 2, alignment: 2, reproducibility: 2, traceability: 2, safety: 2 }, // 各 0|1|2
  quality:   { closure: 3, transfer: 3, completeness: 3, structure: 3, freshness: 3, accessibility: 3 }, // 各 0-4 级
  notes: "证据与评级理由"
}
```

校验器的硬规则（不满足即报错）：

- 每条资源必须有 `review`，且 `evidence`、`status`、`reviewedAt` 合法；`standards` 取值 0/1/2，`quality` 取值 0-4 级。
- `status: "formal"` 必须同时满足：**证据 ≥ E2、五项标准全为 2、质量总分 ≥ 53**（总分由 `Σ 权重×等级÷4` 现算），否则报错。
- `status: "candidate"` 允许暂缺 `standards`/`quality`（记为 `null`），但**若证据为 E0/E1 却已展示完整操作总结，会给出警告**——因为按第一层与 §五，E0/E1 不得当作正式教程呈现；应补足观看升 E2，或下调展示。

这样「打分」从纸面规范变成每条教程都带、可核查、可校验的属性；`status` 也让「已充分复核」与「暂列候选」在数据层面区分开。

## 四、正式教程的写作结构

每条正式资源必须包含：平台、标题、作者、原链接、发布日期、时长、适合对象、完整内容总结、完整操作、独门内容和复核提醒。

### 1. 完整内容总结

总结必须覆盖视频教授的一切重要行为，并回答：

1. 视频最终帮助读者完成什么？
2. 开始前需要准备什么？
3. 按什么顺序操作？
4. 每个关键功能怎样使用？
5. 怎样确认已经完成？
6. 失败时首先检查什么？

不能用几句抽象观点代替教程内容。视频标题如果承诺安装、Plan、Git、Memory、Skills 和 MCP，总结与操作区就必须分别解释这些内容怎样执行。

### 2. 完整操作

把视频拆成若干操作单元。每个单元必须包含：

- 清晰的操作主题；
- 按顺序排列的具体步骤；
- 可观察、可检查的“完成标志”。

### 3. 独门内容

独门内容只写该资源相对同页其他教程真正独特的技巧，必须包含：

- 技巧独特在哪里；
- 适用场景；
- 可执行步骤；
- 最终结果或验收方式；
- 必要时说明限制和代价。

“要先规划”“注意代码管理”“Memory 保存偏好”这类抽象句子不构成独门内容。

## 五、事实、时效与版权

视频内容只能总结和重新组织，不能复制字幕，也不能把标题中的营销说法当成事实。

关键结论应能回到时间戳、章节、操作画面、源码或配套文档。涉及价格、账号、模型名、按钮位置、第三方 API 和安装方式的内容默认视为易变信息，必须记录访问日期，并使用官方资料复核当前操作。

公开视频材料不足时，必须诚实标记为 E0/E1 或候选，不得用官方文档补写后冒充视频内容。官方资料只能用于事实校准和补充说明。

外部资源只作事实核对与选题依据；教程正文必须重新组织和原创表达。不得收录盗版字幕、付费内容全文或未经允许的长段转录。

## 六、本地取证管线（tools/video-evidence.py）

为把资源从 E1（仅凭标题/简介）提到 E2（足以还原关键步骤），提供一条**本地、免费、可自动化**的取证管线：

```text
py -3.11 tools/video-evidence.py <视频URL> <输出前缀> [--asr auto|groq|local] [--prompt "领域词表"] [--interval 8] [--height 480|720]
```

它**免登录**完成：yt-dlp 下音频+低清视频 → **转录**（逐段带时间戳）→ 按固定间隔**密采关键帧**并**相邻感知去重**（治长镜头漏采、去冗余）→ RapidOCR 读出屏幕上的命令/URL/配置/型号名 → 汇成 `<前缀>.evidence.md`。

调参：`--prompt` 领域词表纠专名拼写（Groq/本地都用）；`--interval` 抽帧间隔秒（越小越密）；`--height 720` 抽更高清帧、OCR 小字更准；`--dedup` 相邻帧去重阈值。

**转录后端**（`--asr`，默认 `auto`）：

- **Groq Whisper（推荐）**：设了环境变量 `GROQ_API_KEY` 时自动启用，跑 `whisper-large-v3`——比本地准、快约百倍、近乎免费（有免费额度）。长音频自动压成 16kHz 单声道并切段以避开单请求上限。key **只从环境变量读，绝不写进代码/仓库**（`setx GROQ_API_KEY "..."` 或临时 `$env:GROQ_API_KEY="..."`）。
- **本地 faster-whisper（回落）**：没 key 时用，零成本但 CPU 上慢；`--model` 选 small（快）或 large-v3-turbo（准）。
- 无论哪家，ASR 都只作草稿——专有名词/命令仍以 OCR 与官方文档为准。

用法要点：

- **转录（ASR）只作步骤草稿**；专有名词、命令、路径、数值以 **OCR 与官方文档为准**，不照抄转录（本地小模型常把 Ollama 听成 Olonema、显存听成线传）。
- **三源交叉**——转录给步骤顺序、OCR 给界面与确切命令、官方文档给语法与型号——都印证过的才写进教程；未印证的标「未能核实」。
- 全程本地、**零 API 费用**，适合日后定时自动运行。CPU 上大模型转录较慢（large-v3-turbo 约 1.4× 实时），追求速度可用 small 并更依赖 OCR/文档纠名。
- 依赖：`yt-dlp faster-whisper scenedetect[opencv] rapidocr-onnxruntime` + 系统 ffmpeg。
- 只下载低清视频/音频供内部取证，正文必须原创、不整段转载字幕（见 §五）。
