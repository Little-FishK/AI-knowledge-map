# 专业资料库来源政策

版本：0.7
修订日期：2026-09-23

## 1. 原则

专业资料库的一级分类只回答“信息从哪里来、经过什么审查”，不按论文、视频、代码、模型卡等内容形式分类。内容形式、主题、语言和关联节点只作为二级标签。

白名单单位不是整个平台或整个域名，而是“发布主体 + 具体栏目/集合 + 内容类型 + 允许支持的断言”。GitHub、arXiv、OpenReview、Hugging Face、YouTube 和 Bilibili 都不能因平台身份整体获得权威资格。

进入资料库不等于内容为真，也不等于有资格成为节点。白名单只表示系统允许抓取、分类和继续审核。

## 2. 九类一级来源

1. 学术投稿：正式论文、同行评审出版物、预印本与前沿投稿。
2. 标准与监管：正式标准、法规、监管文件和官方风险框架。
3. 官方技术资料：官方文档、模型卡、系统卡、公告、更新日志及官方仓库。
4. 专业知识库与评测机构：结构化知识库、基准、公共评测和测试方法。
5. 专家与行业分析：专业机构报告、趋势研究、跨产品分析和事故复盘。
6. 公开视频与讲座：不属于前述更高优先来源的公开课、会议演讲和技术分享。
7. 黑客马拉松：官方赛题、获奖项目、演示和项目记录；默认只作发现。
8. 权威创作者：按具体专业范围认证的个人来源，不能跨领域继承权威。
9. 开源项目与代码仓库：独立社区项目的主仓库、版本、RFC、代码和已确认实现记录。

## 3. 唯一归类优先级

一条资料只能有一个一级来源分类。发生重叠时依次采用：

`标准与监管 → 学术投稿 → 官方技术资料 → 专业知识库与评测机构 → 黑客马拉松 → 权威创作者 → 专家与行业分析 → 公开视频与讲座 → 开源项目与代码仓库`

例如：论文官方实现仍归学术投稿；厂商官方教学视频归官方技术资料；权威创作者的视频归权威创作者；独立社区主仓库才归开源项目与代码仓库。

## 3.1 二级来源

每个一级来源下继续细分为具体平台、机构、资料集合或经认证个人。二级来源用于：

- 控制抓取入口和频率；
- 限定该来源能够支持的断言范围；
- 分别记录停用、降级和版本变化；
- 避免把整个平台误当成白名单。

二级来源必须隶属于唯一一级来源。资料必须同时填写 `sourceClass` 和 `sourceSubcategory`；不能只写“来自 GitHub”“来自 YouTube”或“来自 arXiv”而省略正式归类和逐条审核。

当前二级目录维护在 `data/library.js` 的 `sourceClasses[].subcategories`。目录本身只是允许进一步审核的来源范围，不等于其中全部内容自动可信。

每个二级来源还必须在 `data/library-platform-profiles.js` 中登记官网、定位、背景、运营组织、创始或发起团队和复核日期。若二级来源是多个机构组成的集合，必须明确标记为 `collection`，不得为了满足字段而虚构统一公司、官网或创始人。

二级来源页面必须提供足以独立阅读的完整介绍，不得把一句定位文案冒充平台介绍。正式介绍不得少于 90 个中文字符，并至少列出 3 项优势或特征；随后还要覆盖主要内容、资料库使用方法和证据边界。具体平台有特殊优势、访问方式或引用规则时，应覆盖一级来源的通用说明。

## 3.2 二级来源的入选标准

来源准入与内容审核分开：本阶段只决定来源是否合格，合格者全部可以进入来源池，不按名额、同类数量或展示位置择优淘汰。

经典与前沿分别审核。经典不套用近期产出门槛；前沿采用“一手、近 12 个月实质原创贡献、独立应答、专业归属”四道来源级闸门，完整规则见 [FRONTIER_SOURCE_POLICY.md](FRONTIER_SOURCE_POLICY.md)。首创与应答可由同一来源、同一专业范围内的不同成果证明；应答不限定同一时间窗口。

先区分原创发布者、原件发布渠道与发现入口，不给整个平台或品牌统一授信。个人、研究机构、咨询机构等只按所审范围内的实际产物判断，不按机构形态预先排除。

判定为通过、待核实或不符合当前前沿资格。旧 S/A/B 元数据不能替代本轮证据；下一节的断言权威等级不作为此次来源准入排名。六个来源的试审见 [试审记录](FRONTIER_SOURCE_REVIEW_PILOT_20260923.md)。

“标准与监管”的具体资料采用[单层专用审核机制](STANDARDS_REGULATORY_REVIEW_POLICY.md)：只设官方身份、对象适格、AI 相关性、状态、适用边界及版本去重六项硬门槛，不设重要性评分、名额或第二轮择优；通过的独立资料对象全部收录。

“开源项目与代码仓库”采用[双轨专用审核机制](OPEN_SOURCE_REPOSITORY_REVIEW_POLICY.md)：以能力覆盖补齐零基础 AI 开发工具集，同时以独立证据和高门槛收录顶级开源项目；热度指标只能用于发现和采用度佐证，不能自动通过审核。

## 4. 权威等级与用途

- `A1`：规范性或官方一手来源，可支持其明确管辖范围内的事实。
- `A2`：正式研究、专业评测或高强度一手证据。
- `B`：专业解释、实现或汇总，需要按断言类型交叉验证。
- `R`：新颖性雷达，只能提出候选。

权威性与新颖性不相互补偿。预印本、黑客马拉松、未合并 PR、单一创作者观点和厂商性能宣传不得单独支持正式新节点。

## 5. 与现有页面的关系

资料首先成为可追溯的资料对象，然后可以：

- 关联节点、软件和教程；
- 提出新节点或新教程候选；
- 为已有节点进入待复审队列；
- 标记软件教程可能过时；
- 保留为重要资料，而不强迫转换成节点。

单条新资料不得自动改写现有理解原理页正文。资料库中的关联信息与经过审校的正文分离展示。

## 6. 当前边界

v0.7 已建立分类、展示、真实种子、来源治理元数据与两类数据校验，仍不进行自动抓取，不把资料自动晋升为节点或教程。

二级来源 85 个，其中官方技术资料 9 个二级来源共 1391 条，专业知识库与评测 117 条、学术投稿 105 条、黑客马拉松 158 条、标准与监管 66 条已成形，其余四类各保留 1 条种子资料。校验器会逐类列出"尚未登记资料"的二级来源作为待办，种子条目用于验证信息架构，不代表完整来源白名单。

“专业知识库与评测机构”采用来源专属收录机制（`reviewMode: source-specific`）：核心资料全收，按各二级来源自身的数据库、方法、版本与榜单结构收录，不设跨机构统一评分机制。动态数据库不逐条镜像；收录数量是逐来源完整性审核的结果，不是预设配额。资料位于 `data/library-knowledge-base-core.js` 与 `data/library-knowledge-base-expanded.js`。
