# 可复用提示词模板 — 换主题做同样的知识地图

> 用法：把下面代码块整段复制到新对话，**把【主题】全部替换成你想做的主题**（如"投资理财""生物医学""某门专业课"）。
> 这份模板沉淀了 AI 知识地图项目**踩完坑之后**的结论，新对话不必重走一遍弯路。
> （最后更新 2026-07-19，已同步到网状图 / maturity 标签 / 核心视图等最终决策。）

---

```
我要做一个网页，整理【主题】领域对我有用的概念与知识，核心价值在于**展现概念之间的联系**。
要求：纯静态网页（双击即开、可分享、无后端）；能通过我提供的资料（网址/文档/视频）半自动更新；
每个概念有足够深的介绍（不是一句话词条）。

我已有一套在另一个项目（AI 知识地图）里踩完坑验证过的方案，请针对【主题】判断哪些适用、哪些要改，
不要照搬。以下每一条都是结论，不是待讨论的开放项——除非【主题】的特点明显不适用：

■ 结构 = 网状图（不是树）
- 概念可以有多个"上级"，用有类型的边表达关系，不强行给每个节点选唯一父节点。
  （教训：最初用"唯一父节点的树"，结果和"展现联系"这个核心目标打架——树天生只能一个父亲。）
- 布局用力导向（Cytoscape.js fcose），大区靠颜色+聚类区分。
- ★ 关键：坐标要固化进数据文件。fcose 每次布局朝向随机（谱初始化符号任意），
  不固化的话每次打开图都不一样。搜一个不重叠的布局种子，导出坐标存进数据。

■ 边（关系）= 精而少、有类型、有方向
- 起点 8 种：is-a / part-of / prerequisite / uses / variant-of / enables / contrast / related
- 但要准备好扩：AI 项目实际用了 11 种，补了 constrains(约束) / mitigates(缓解) / threatens(威胁)
  ——这三类往往是最有价值的联系，用 related 兜底等于把信息丢了。按【主题】需要增删。
- 全部渲染、按类型着色、可单独开关。跨大区的边优先找（同区联系读者自己能想到，跨区的才是增量）。

■ 成熟度 = 一个轻量标签，不是"分层结构"
- 只用 maturity: stable | evolving（缺省 stable）。evolving 视觉上标一下即可。
- ★ 教训：最初设计了 base/emerging/news 三层叠层，后来发现它的作用要么弱、要么被别的机制替代
  （默认视图入口→核心视图接管；学习路径→边类型表达得更准），最终降为一个标签。
  除非【主题】的"时效性"极强（如新闻、投资），否则别做重的分层。
- 具体的时效条目（新闻/版本/事件）不建节点，作为概念详情页里的动态条目。

■ 用途大区 = 按"我怎么用【主题】"分，不按学科
- ★ 关键洞察：用途分区会和很多"共享基础概念"打架。解法：设一块"共享基础区"当公共底座，
  其余为用途大区。请针对【主题】提议一组用途大区。

■ 默认视图 = 核心视图（这条到 50+ 节点才显出必要性，但要一开始就设计）
- 默认只显示每个大区的少数骨干概念，点击任一节点再逐层揭开邻居。
- ★ 教训：节点一多，全展开既糊成毛线球、新读者又不知从哪看起。核心视图两个问题一起解。
- 配合"聚焦模式"（点节点只显示其 N 跳邻域）默认开启。

■ 详情页 = 有深度，不是词条
- 每个概念正文按固定四段写：**是什么 → 为什么会这样(机制) → 约束/影响了什么 → 怎么应对**。
  ★ 教训：只写"是什么"的词条没价值。第二段(机制)最容易被跳过，也最有价值。
- 正文里提到别的概念用内联链接直接点跳，不重复解释（这也是防正文膨胀的闸）。
- 详情页含：定义、四段正文、案例、带类型的相关知识、动态条目、来源。

■ 技术形态
- 单个数据文件用 window.GRAPH（JS 而非 JSON）——为了 file:// 双击即开，浏览器禁止 fetch 本地文件。
- Cytoscape.js 做图渲染，本地内嵌保证离线可用。展示层只读数据，不写。
- 展示与入库解耦：入库是离线步骤（我给资料→你抽取→出可审核的 diff 提案→我确认→你合并），不是在线服务。
- ★ 去重匹配是入库最容易垮的一步：同一概念不同叫法要合并，避免长出重复节点。
  提案必须显式列出"疑似重复+置信度"给我判断，宁可交给我审也别自作主张新建。

■ 节点粒度：清单定骨架，写作发现器官
- ★ 教训：一开始的节点清单是从外部目录筛来的，继承了它的颗粒度，漏掉了很多该有的概念。
  写正文时如果发现自己在解释一个"有自己的成因和对策"的东西——它就该是个独立节点。

请按 规格 → 我审批 → 实现 → 验证 → 提交 的流程推进，每步先确认。
遇到会显著改变方案的岔路，直接问我，别替我决定。
```

## 换主题时特别值得重新想的三点

1. **用途大区**要重设计。AI 分的是"编程/搭应用/内容生成/追前沿/安全对齐"，换主题这组完全不同。
2. **成熟度是否值得标**。AI 有明确的"稳定 vs 演进"之分；但历史、数学这类几乎全是 stable，可能连标签都不必；新闻、投资则时效性极强，或许要更重的处理。按【主题】的变化速度定。
3. **边类型**可能要增删。那 11 种偏通用，具体领域常需专有关系（医学"导致/治疗"、投资"影响/对冲"、历史"引发/继承"）。

## 这个项目本身踩过、值得下一个项目直接避开的坑

- fcose 布局：`animate:true` + 定种子会毁掉布局（异步计算，随机源被提前还原）；`randomize:false` + 初始共线会塌成一条线；中文标签宽，不开 `nodeDimensionsIncludeLabels` 会互相压。
- 中文正文里写英文双引号会破坏 JS 字符串语法——用「」，并写一个校验脚本每次入库前跑。
- Windows 上 git commit 中文用 `-F` 读 UTF-8 文件，别用 `-m` 内联。
