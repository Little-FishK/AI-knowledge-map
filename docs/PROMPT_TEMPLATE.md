# 可复用提示词模板 — 换主题做同样的知识地图

> 用法：把下面代码块里的内容整段复制到新对话，**把【主题】全部替换成你想做的主题**（如"投资理财""生物医学""历史""某门专业课"等）。
> 这份模板已经沉淀了 AI 知识地图项目讨论出的结构结论，新对话不必从零重来。

---

```
我要做一个网页。目标是：整理对我来说有用的【主题】领域的所有信息，尤其是概念和知识。

网页内容的要求：
1. 必须展现【主题】的概念与知识之间的联系。
2. 可以自动捕捉和更新该领域的概念和知识。
3. 可以通过查阅我提供的资料（网址、视频、文档等）来捕捉和更新概念和知识。
4. 内容分为基础层和活跃层。基础层为该领域的基础知识，大部分时间没有新知识更新；活跃层更新频繁。

【第一步】请先帮我调研市面上有没有类似的网站或工具（尤其是【主题】领域的知识地图/概念图/知识图谱类产品），
说明它们各自的结构、技术栈、长处和短板。如果有开源的，请把它的数据结构和分类体系扒出来给我学习。

【第二步】和我讨论知识结构如何设计，然后写一份完整的规格文档。

我已经有一套经过讨论验证的结构方案作为起点，请在此基础上针对【主题】调整（不要照搬，要判断哪些适用、
哪些需要按【主题】的特点改造）：

■ 五个结构要素
1. 主干树：每个概念节点有唯一的 primary_parent，形成干净、可折叠、可导航的层级树。
   （负责"整理和导航"。灵感来自开源项目 aiknowledgemap.org 的 D3 层级树。）
2. 跨边：在主干树之上叠加有类型、有方向的跨分支连线，这才是真正"展现联系"的部分。
   建议 6~8 种类型（精而少），起点集合：
   is-a（是一种）/ part-of（组成部分）/ prerequisite（前置知识）/ uses（使用依赖）
   / variant-of（变体改进）/ enables（使之可能）/ contrast（常被对比二选一）/ related（弱相关兜底）
   全部类型都渲染，用颜色区分，每种可单独开关过滤。
   ★ 关键：纯树最大的缺陷是一个节点只能有一个父亲，无法表达跨分支联系——跨边就是来补这个的。
3. 叠层（按稳定度纵向堆叠，不是二分）：
     L2 news     最新新闻/项目/案例（天~周）—— 主要住在概念的详情页里，不一定成节点
     L1 emerging 已站稳的新技术/新概念（月~季）—— 多以新节点出现
     base        教科书级稳定知识（年）—— 常驻主图骨架
   内容默认进活跃层，被证明持久后经人工确认可向下沉淀（news→emerging→base）。
4. 用途分区：顶层大区按"我怎么用【主题】"来分，不按学科。
   ★ 关键洞察：用途分区会和树骨架打架（很多基础概念是所有用途共享的，不属于任何单一用途）。
     解法是设一块"共享基础区"当公共底座，其余为用途大区，用途节点通过跨边连回基础区。
   请针对【主题】提议一组合适的用途大区。
5. 交互：点击节点 → 先弹【概念卡片】（定义、用途、信息来源、"查看详情"入口）
        → 再进【详情页】（更丰富内容：相关新闻、项目、案例、完整来源列表）。
   主图只放概念和联系，日常资讯沉到详情页，避免把地图撑爆。

■ 技术形态
- 纯静态网页：双击即可打开，也能部署分享。不要后端服务。
- 图渲染用 Cytoscape.js（同时支持树布局和网状跨边、聚焦展开、可离线内嵌）。
- 数据是本地 JSON 文件（nodes + edges），展示层只负责读取渲染。
- 展示与入库解耦：入库是离线步骤，不是在线服务。

■ 自动更新策略
- 先做半自动：我提供资料 → 你抽取概念+连线+判定层级 → 生成可审核的 diff 提案 → 我确认后合并进 JSON。
- 去重匹配是难点（同一概念不同叫法要合并，避免长出重复节点），先用标题+别名匹配，不够再加语义相似度。
- 验证可用后再升级为定时全自动。

■ 防"毛线球"（这是这类产品最常见的失败模式）
- 不做"一张全景大图"。默认只渲染基础层主干。
- 跨边和活跃层按需逐层揭开，而不是靠隐藏边类型。
- 用途大区提供"地图分区"感。

【第三步】结构确认后，先出一份"知识结构展示"文档：用一块【主题】领域的真实知识切片，
把上面五个要素具象化画出来（主干树长什么样、有哪些跨边、三层怎么叠、卡片和详情页长什么样、
对应的 JSON 数据是什么），让我在做成品前先看清楚结构。

【第四步】我确认后，再做 M0 原型：用那块真实切片做成能点、能展开、能看卡片的单页网页。

请按 规格 → 我审批 → 实现 → 验证 → 提交 的流程推进，每一步先和我确认再往下走。
遇到会显著改变方案的岔路，直接问我，不要自己替我决定。
```

---

## 换主题时特别值得重新想的三点

1. **用途大区**要重设计。AI 项目分的是"编程/搭应用/内容生成/追前沿/安全对齐"，换个主题这组完全不同。
2. **叠层的时间尺度**要调。AI 是"天/月/年"，但如果主题是历史、数学这种，活跃层可能几乎不动；如果是新闻、投资，活跃层会比 AI 还快。
3. **边类型**可能要增删。那 8 种比较通用，但具体领域可能需要专有关系（如医学的"导致/治疗"、投资的"影响/对冲"、历史的"引发/继承"）。
