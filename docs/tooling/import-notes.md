**一句话：这个网站停留在"大模型之前的机器学习"时代。** 它是一份很扎实的**经典 ML / 数据管线教科书目录**，但你想做的"AI 知识地图"里最活跃、最有价值的那一大半（LLM、Agent、RAG、提示工程、MCP），它**一个都没有**。

这直接影响我们的计划：原本设想的"导入它的树 + 我们补跨边和分层"里，**"导入"能贡献的比例远小于预期**——大概只能填满我们六个大区里的 **1.5 个**（基础/共享 的一部分 + 安全对齐 的一小部分）。剩下四个半大区要从零写。

## 2. 它的树是什么形状 —— 和我们的"概念图"不是一回事

它的层级不是 `概念 → 子概念`，而是三段式：

```
概念(Transformers) → 能干的任务(Sequence Classification) → 评价指标(Accuracy / F1 / AUC)
```

所以它的"深度"很大程度上是**任务和指标的排列组合**，同一批指标（Accuracy/Precision/Recall/F1/ROC/AUC）在树里被重复挂了几十次。1410 个节点里有 **664 个是 `type: url` 的叶子**，绝大多数就是这类重复指标条目，且 `url` 字段基本是空的。

对我们的意义：
- 它的节点数 ≫ 它的概念数。**688 个唯一名，真正够格当我们"节点"的（SPEC §3.1 的粒度标准）我估计只有 120~150 个。**
- 重复挂载的指标不能照搬成节点，否则我们的图里会出现几十个"Accuracy"。指标应当合并成**少数几个节点**，用 `evaluated-by` 类的边连过去（或者干脆放进详情页，不占节点）。

## 3. 分支体量与去留建议

| 它的顶层分支 | 节点数 | 建议 | 理由 |
|---|---|---|---|
| Machine Learning › **Data** | 464 | **几乎全丢**，压缩成 3~5 个节点 | 数据清洗/缺失值/编码/切分/泄漏防范……是 MLOps 工程细节，颗粒度远低于我们的标准，且对你"怎么用 AI"没帮助。压缩为「数据质量」「训练/验证/测试划分」「数据泄漏」几个概念即可 |
| Machine Learning › **Supervised Learning** | 456 | **取 ~15 个** | 线性/树/集成/核方法/kNN/贝叶斯是真·基础概念，值得留；但它把每个模型 × 每个指标都展开了，指标要合并 |
| Machine Learning › **Deep Learning** | 96 | **全取，且要扩写** | 最贴近我们的一支：CNN/RNN/Transformer/自编码器/GAN/扩散模型/深度RL。但它对 Transformer 的展开太浅（见 §4） |
| Machine Learning › Unsupervised | 64 | **取 ~8 个** | 聚类、PCA/t-SNE/UMAP 值得留（尤其降维，和嵌入可视化直接相关） |
| Machine Learning › Reinforcement Learning | 71 | **取 ~6 个** | Q-Learning / 策略梯度 / Actor-Critic / PPO 前置。RLHF 要我们自己补 |
| Machine Learning › Semi-supervised | 82 | **取 1~2 个** | 伪标签、一致性正则可留个概念；其余对你无用 |
| **Symbolic AI** | 87 | **取 2~3 个** | 符号 AI / 知识表示 / 自动推理，当历史脉络的锚点有价值，不展开 |
| **Expert Systems** | 42 | **全丢** | 上世纪的东西，且它的子结构（诊断/监控/配置/排障）是应用场景罗列，不是概念 |
| AI Incidents | 4 | **丢节点，转成来源** | 三个事故数据库链接 —— 正好当活跃层-L2 的**素材源**，记进 §6 |

| AI Governance and Risk Management | 14 | **取 2 个** | NIST AI RMF、ISO 标准各一个节点 |

**合计可用：约 55~60 个概念**，其中绝大多数落在我们的 **🧱 基础/共享** 大区。

## 5. 因此我建议调整 M0-3 的做法

原计划是"导入 + 重整"。基于以上，实际动作应该是：

1. **把它当"基础层的素材库"，不当"骨架"。** 我们的骨架仍按 SPEC §3.2 的六大区自己搭。
2. 从它那里**摘 25~30 个基础层节点**（主要是 Deep Learning + Supervised 的模型概念 + 治理框架），直接复用它的 `short_definition`（写得挺规范，可作为 `summary` 的初稿），并在 `sources` 里注明出处。
3. **另外自己写 20~25 个现代 AI 节点**（Transformer 展开、注意力、LLM、RAG、提示工程、Agent、MCP、微调、量化、对齐、幻觉……）——这部分才是你真正每天用得上的，也是这张地图相对它的价值所在。
4. 指标类（Accuracy/F1/BLEU/Perplexity…）**不建节点**，收进相关概念详情页的"评价方式"一节。
5. 这样 M0-3 的 25~35 个基础节点目标不变，但**来源比例大约是 一半导入 / 一半自写**。

## 7. 需要你拍板的一件事

§5 的调整意味着：**这张地图的一半内容是我们自己写的，不是"综合"那个网站的。** 这和你最初"必须综合那个网站的树状分类"的设想有出入——不是我不想综合，是它那边确实没有 LLM 时代的内容。

三个选择：
- **A（我推荐）**：按 §5 做——它当素材库，我们自己搭六大区骨架，一半导入一半自写。地图对你有用，但"继承 aiknowledgemap"的成分会比预期少。
- **B**：严格照搬它的树当骨架，我们只在上面挂活跃层。忠实于原设想，但地图会是一张"经典 ML 目录"，你最关心的 Agent/RAG/提示工程无处安放。
- **C**：先只做导入那 55 个节点看看效果，再决定要不要自写另一半。稳，但 M0 验证不了"跨边"这个核心卖点（经典 ML 概念之间的跨边比较稀疏）。
