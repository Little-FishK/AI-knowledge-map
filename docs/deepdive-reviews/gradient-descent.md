# 梯度下降理解原理页审查记录

审查日期：2026-07-25  
页面：`data/deepdive/gradient-descent.js`  
官方学习路径：`1.3 · 梯度下降`  
状态：已修复本轮发现的问题；尚未进行 L4 独立人工认证

## 记录目的

本记录用于积累后续统一优化 L1/L2/L3 门禁规范的真实缺陷样本。重点不是列出改了哪些文字，而是记录用户为何无法理解、现有自动门禁为何漏检、什么检查可能提前发现，以及哪些教学判断仍需人工完成。

## 发现与修复

### 1. 第 3 节更新公式解释不足，`w=2` 再次突然出现

- 用户影响：更新式只定义了 g 和 η，没有解释 t、θ、减号和参数更新前后；案例直接给出 w=2，读者不知道 w 是什么、为什么不是 3。
- 漏检原因：L3 能识别更新公式、符号和手算表，却不检查变量是否在第一次赋值前获得自然语言角色。
- 修复：在页首第一次出现时定义 w 为模型要学习的倍数参数，说明真实规律需要 w=3、w=2 是故意设错的初始值；第 3 节逐项翻译更新式中的每个符号。

### 2. 第 4 节重要但几乎只有数学式

- 用户影响：a、w*、eₜ 和稳定区间同时出现，读者不知道曲率、误差收缩和跨过谷底分别意味着什么。
- 漏检原因：门禁把公式密度和推导视为深度证据，不判断公式前是否建立了语言直觉和具体数值锚点。
- 修复：先用碗壁解释曲率，再把贯穿案例化为 `J(w)=2(w−3)²`，用五个具体学习率展示靠近、一步到达、衰减震荡、等幅震荡和发散，最后才推广到一般二次函数。

### 3. “狭长谷地”没有定义

- 用户影响：图和术语看似直观，但读者不知道谷地对应损失函数的什么性质，也不知道为什么会产生之字形。
- 漏检原因：存在图、图注和“条件数”关键词即可得分，没有检查视觉隐喻是否映射到参数、损失、等高线和曲率。
- 修复：定义损失地形、等高线、横向陡坡、纵向平缓谷底和最低点，解释梯度为何被陡方向主导，并在图注中定义条件数是曲率比例。

### 4. “硬件效率代价高”没有可操作含义

- 用户影响：不知道代价指时间、吞吐、显存、计算单元空闲还是设备通信，也无法理解小批量为何有时更慢。
- 漏检原因：自动门禁只识别吞吐、显存和 batch 等工程词，不要求抽象成本落到可观察资源。
- 修复：定义硬件效率，加入 100 万样本、batch 256 的反馈频率例子，分开解释 GPU 利用率、显存和跨设备同步。

### 5. SGD、Momentum 和 Adam 未定义便直接比较

- 用户影响：表格默认读者已知道三种优化器，无法理解“当前梯度、一阶矩、二阶矩”分别是什么。
- 漏检原因：比较表包含三个标准术语和作用描述，结构评分很高，但没有检测术语首次出现是否具备定义、更新过程和直觉。
- 修复：先定义优化器，再按“SGD 不记历史 → Momentum 记近期方向 → Adam 再记平方梯度尺度”的顺序介绍，给出更新式和狭长谷地中的作用。

### 6. 第 8 节新概念密集且互相借词解释

- 用户影响：warmup、cosine decay、clipping、激活、归一化统计和自适应矩同时出现，读者无法区分它们解决训练哪个阶段的问题。
- 漏检原因：术语覆盖率被误当作内容完整度，没有限制单位段落中新概念密度，也没有要求每个术语具备“动作—症状—边界”说明。
- 修复：用表格分别定义预热、衰减和裁剪的实际动作、适用阶段、观察证据和不能替代的内容；移除不必要的未解释依赖。

### 7. 第 2 节把多变量微积分当作已知

- 用户影响：泰勒展开、点积、范数、归一化和柯西—施瓦茨一次出现，官方路径早期读者只能背结论。
- 漏检原因：数学符号与定理名称会提高深度评分，门禁不会判断目标受众是否已具备前置知识。
- 修复：先用每个梯度分量取反解释方向，再逐项定义 Δθ、点积、向量长度和 ε；把不等式证明折叠为可选内容。

### 8. 第 9 节诊断术语没有解释

- 用户影响：detach、饱和、冻结、更新比、混合精度缩放等新词密集出现，诊断步骤无法执行。
- 漏检原因：工程诊断关键词数量满足门禁，却没有“看到什么—意味着什么—下一步查什么”的语义检查。
- 修复：改为七步可执行检查，定义小样本记忆测试、梯度范数、参数冻结、更新/参数比和学习率短跑，删除当前不必要的术语。

### 9. 小批量梯度的统计与计算角色混在一起

- 用户影响：原文一句话同时说近似无偏、向量化硬件和反馈速度，没有解释“不精确”来自抽样，也没有区分每轮样本计算量与单次更新等待。
- 漏检原因：门禁能看到 batch、噪声、吞吐和显存，却不检查同一因果链是否区分统计效率与硬件效率。
- 修复：分别解释抽样误差、更新频率、吞吐、显存和通信，并明确全量梯度“单步精确”不代表达到目标的总时间更短。

### 10. 最终自测被通用问题追加

- 用户影响：源码五题之后自动出现线上均值、权限、预算和评分器等跨主题题，难度和正文断裂。
- 漏检原因：生成器只看题量和高阶疑问词，不验证题目术语来自正文。
- 修复：将本页移出通用追加名单，改为八道主题专属题，覆盖梯度定义、局部最陡、稳定区间、狭长谷地、小批量硬件、三种优化器和三类训练配方。

## 候选门禁改进

| 缺陷模式 | 候选自动检查 | 误报与人工边界 |
|---|---|---|
| 变量第一次赋值前没有角色说明 | 建立案例变量首次出现索引，检查附近是否含“参数、输入、目标、初始、表示”等语义 | 公式复习页可沿用前文变量，需读取章节和相邻节点作用域 |
| 数学深度来自未解释符号堆叠 | 统计单段新符号与定理密度，要求先有白话解释、符号表或可选证明层 | 高阶页面允许高密度公式，应结合官方路径位置 |
| 视觉隐喻没有映射到数学对象 | 对“谷地、地形、盆地、陡坡”等隐喻检查是否说明坐标、等高线、目标值和动作 | 某些图本身已充分标注，仍需人工判断可读性 |
| 抽象工程代价没有资源维度 | 对“代价高、效率低、昂贵”检查是否至少落到时间、显存、吞吐、通信或质量之一 | 概览页可能只需定性描述，不应机械要求全部维度 |
| 比较表中的条目没有首次定义 | 检查表格首列专有名词是否在表前获得定义、展开全称或操作过程 | 常识术语和后续复习表可以豁免 |
| 单段新概念密度过高 | 建立官方路径术语词表，对连续短段中多个首次术语触发告警 | 新概念边界难自动划分，应作为人工审校线索 |
| 诊断步骤不可执行 | 要求每个步骤至少具备观测量、异常含义或下一动作中的两项 | 原理页不必写成运维手册，规则需按章节目标启用 |
| 统计效率与硬件效率混用 | 对 batch 章节检查抽样噪声、更新频率、吞吐/显存是否分别解释 | 不是所有页面都需展开硬件，适用于明确提出工程权衡的页面 |
| 自测出现正文外术语 | 对最终 HTML 的题干做正文术语覆盖和跨页高相似题检测 | 迁移题可以引入新场景，但不能依赖未教授的新机制 |

## 验收边界

本轮修复和自动验证不等于 L4 认证。正式 L4 仍需独立审校者复算稳定区间、SGD/Momentum/Adam 更新含义和批量案例，核对来源，并登记当前页面哈希及桌面/移动端证据。
