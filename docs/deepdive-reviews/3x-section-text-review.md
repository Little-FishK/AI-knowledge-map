## 3 大语言模型 LLM（llm）

### 3.1 为什么需要大语言模型

本节回答：我们已经有神经网络了，为什么还要「大语言模型」这样一类特殊的东西？。 1.1 旧世界：一个任务，一个模型，一堆标注 在 LLM 之前，处理语言是「分而治之」：情感分类训一个模型，机器翻译训另一个，问答、摘要、命名实体识别各训各的。每一个都要 大量人工标注 的专用数据，而且换个任务几乎从头再来。这条路能走，但又贵又碎，且每个模型都只懂自己那一小块。 1.2 关键转念：几乎所有语言任务都能写成「续写文本」 有一个朴素但极强的观察：把任务塞进文字里，它们就都变成了同一件事—— 接着往下写 。 把任务变成续写 翻译 = 续写「 英文：… 中文：___ 」； 问答 = 续写「 问：… 答：___ 」； 摘要 = 续写「 原文：… 摘要：___ 」； 情感分类 = 续写「 这条评价的情绪是：___ 」。 只要一个模型足够会「续写」，它就 用同一套参数 顺手做了所有这些任务——不必为每个任务单独建模型、单独标数据。 于是问题从「怎么为每个任务建模型」变成了「怎么训练一个特别会续写的通用模型」。这个「特别会续写的模型」，就是大语言模型。它 值不值得 、 怎么做到 ，是后面全部内容。 它不是万能，也不该万能 LLM 擅长开放、语言性的任务。但要精确计算、要可靠事实、要严格可复现，直接问它并不合适——后面会看到这是它的 结构性 短板，而不是「再大一点就好」。

### 3.2 它每一步到底在算什么

上一节说它「会续写」。抛开神秘感，续写这件事，机器每一步具体在算什么？。 答案朴素得让人意外：给定前面的一串 token，模型输出的是 整个词表上的一个概率分布 ——词表里每一个候选 token，各自「接下来最可能是我」的概率。 图示：给定前文，模型输出下一个 token 的概率分布。 图 1 模型的每一步输出，不是一个词，而是 词表上所有 token 的一张概率表 。这张表由最后一层的数值经 softmax 归一化得到。 。 P(下一个 token = w │ 前文) = softmax(z)_w。 符号说明： P 表示条件概率， w 是词表中的某个候选 token，竖线右侧“前文”表示概率以当前上下文为条件； z 是模型最后一层为每个候选 token 算出的实数向量（logits）， softmax(z)_w 表示 softmax 把整排 z 归一化后取候选 w 对应的那一项。所有候选项相加等于 1。 2.1 一次一个词：自回归生成 有了「下一个 token 的概率表」，怎么生成一整句？ 把它接回去，再来一遍 ：挑出「巴黎」，拼到前文末尾变成「法国的首都是巴黎」，再让模型预测 下一个 token（可能是「。」或「，」），如此滚动，直到生成结束符。这种「一次一个、每步都把已生成的接回输入」的方式，叫 自回归（autoregressive） 。 图示：自回归生成的滚动循环。 图 2 自回归：模型一次只吐一个 token，然后把它接回输入、再算下一个。你看到的「流畅长文」，是这个循环滚了很多次的结果。 。 你可能会困惑 「它是不是先在心里想好整句，再说出来？」—— 不是 。它没有全局草稿，就是一步一步、每步只挑「此刻最可能的下一个 token」。这条性质后面很重要：它解释了为什么模型能一本正经地把话说圆、却在中途拐进一个根本不存在的事实。 写成一个乘积 整段文本的概率，被拆成每一步条件概率的连乘： P(x₁…xₙ) = Π P(xₜ │ x₁…xₜ₋₁) 。这里 xₜ 是第 t 个 token， x₁…xₜ₋₁ 是它之前的前缀， n 是序列长度， Π 表示把每一步条件概率相乘。这就是「语言模型」这个名字的数学含义——它建模的是 文本序列的概率 。 2.2 手算两步序列概率 在图中的前文后，假设模型选“巴黎”的条件概率是 0.62；接上“巴黎”后，句号的条件概率是 0.80。那么生成“巴黎。”这条两步路径的联合概率是：。 P(巴黎。│前文)=0.62×0.80=0.496。 第一步； 第二步条件概率； 整条路径概率。 巴黎：0.62； 句号：0.80； 0.496。 里昂：0.09； 句号：0.90； 0.081。 。 第二条路径的第二步更“顺”，仍补不回第一步的巨大差距。真实生成拥有指数多条路径：贪心只保留当前概率最高的一个 token；束搜索同时保留有限条累计概率较高的候选路径；随机采样则按每一步分布探索。它们是不同解码规则，不能混称为“模型的答案”。

### 3.3 从文字到向量：token 与嵌入

第 2 节默默假设了模型「能读」前文。可模型只会算数字，「法国的首都是」这串汉字，怎么变成它能处理的东西？。 分两步： 切分 与 嵌入 。 分词（tokenization） ：文本先被切成一个个 token （子词片段），每个 token 对应词表里的一个编号。常见词往往整词一个 token，生僻词会被拆成几块。于是「法国的首都是」变成一串整数 id，比如 [121, 340, 88, 502] 。 嵌入（embedding） ：每个 token id 查一张大表，取出一个几百到几千维的 向量 ；再叠加一个表示「它排在第几位」的 位置编码 。到这里，一串文字终于变成了一叠模型能做数学运算的向量。 为什么必须先变成向量 神经网络只会对连续数字做加权求和与非线性变换。离散的字符/词编号（1 号词、2 号词）本身没有「远近」可言；嵌入把它们放进一个连续空间，让 语义相近的词落在相近的位置 ，模型才有的算。 一个务实的后果 计费和「上下文长度」都按 token 算，不按字数；而且模型「看不见字母」——问它「strawberry 里有几个 r」常出错，因为字母信息在分词那一步就被打包进 token 了。

### 3.4 中间那个 Transformer 做了什么

输入已经是一叠向量了。核心命题说「超大 Transformer」，那它把这些向量 怎么了 ，才能算出下一个词？。 这里只讲它在 LLM 里扮演的角色（完整原理见 Transformer 深读页）。一句话： 它把「前文的每个 token 向量」反复加工，让每个位置的向量都吸收进它需要的上下文，最终得到一个「足以预测下一个 token」的表示。 。 关键机制是 注意力 ：处理某个位置时，模型对 前面所有位置 算一组「相关性权重」，按权重把它们的信息汇总过来。所以预测「首都是___」时，模型能把注意力落在「法国」上，而不是被语序束缚。很多个注意力层叠起来，信息就被逐层组合成越来越抽象的表示。 4.1 一个 LLM 特有的关键约束：因果掩码 训练时整段文本是一次性喂进去的。但预测第 t 个 token 时，模型 绝不能偷看 第 t 个及以后的词——否则就是「拿着答案预测答案」，学不到任何东西。为此在注意力里加一层 因果掩码（causal mask） ：每个位置只允许看它 左边 的位置。 图示：因果掩码：每个位置只能看它左边的位置。 图 3 因果掩码是一张下三角。第一个词谁也看不到（只能靠自己），越往后能看的前文越多——这正是「只用前文预测下一个词」在计算上的实现。 。 它省了大工程 有了因果掩码，一段长度 n 的文本喂一次，就同时得到了 n 个训练样本（每个位置都在「用它的前文预测它的下一个」）。这让训练效率极高，是海量文本能被高效利用的关键之一。

### 3.5 训练目标：预训练就是一个巨大的交叉熵

结构清楚了。那这几千亿个参数，是怎么从数据里学出来的？为什么能用「整个互联网」这么多数据？。 诀窍在于目标选得巧：让模型预测下一个 token，而 正确答案就是文本里真实的下一个 token ——数据自己给自己当标签， 不需要任何人工标注 。这叫 自监督学习 ，也正是它能吃下海量文本的根本原因：不用人标，数据就几乎无限。 训练时用 交叉熵 损失衡量「预测的概率分布」离「真实的下一个 token」有多远，再用梯度下降把它压小：。 L = − Σₜ log P(xₜ │ x₁…xₜ₋₁)。 符号说明： L 是一段训练文本的总损失， Σₜ 表示对所有预测位置 t 求和； xₜ 是位置 t 的真实 token， x₁…xₜ₋₁ 是它之前的前缀， P 是模型给真实 token 的条件概率。概率越低， −log 越大，惩罚越重。训练就是把这个“对真实后续的惊讶程度”不断压小。 怎样读这个结果： 输入是文本前缀与其中真实的后继 token，输出是模型的词表概率分布和汇总损失。损失下降表示模型对这类文本的真实后续更少“意外”，不表示这些文本已经过事实核验。它还受训练语料的时间、语言、来源、噪声和偏见限制；扩大数据与参数不能自动消除这些边界。 为什么「不用标注」这么重要 旧范式的天花板是人工标注：标得越多越贵越慢。自监督把这个瓶颈 拆掉了 ——于是「加数据、加参数、加算力」成了可以持续下注的方向（这条经验规律叫缩放定律）。 「能 scale」这件事，根子就在「预测下一个词不用人标答案」。 。

### 3.6 为什么「猜下一个词」能学会推理

这是全页最反直觉、也最关键的一节。一个只会猜下一个词的模型，凭什么会翻译、写代码、甚至推理？。 先承认这确实反直觉 「预测下一个词」听起来像高级的输入法联想。但请注意一件事： 要把下一个词猜准，往往被迫理解到位。 。 把「猜词」逼到极致，会发生什么：。 要续写一段 推理 （「因为 A 且 B，所以 ___」），模型必须学到足以预测结论的模式或中间表示；这可能支持真正的新题泛化，也可能只是复现训练中常见模板，必须用分布外题目区分。 要续写一段 代码 ，就得懂语法和语义，否则下一个 token 填错程序就崩。 要续写一段 对话 ，就得建模对方的意图和语气。 要续写「 1234 × 5678 = ___ 」，就得掌握乘法的规律。 换句话说，「预测下一个词」覆盖了非常广的统计任务：为了降低损失，模型会学到可复用的语法、事实、代码和部分推理表示。 这些能力不是由单独类别标签逐项教授，而是在预测目标中作为可迁移副产品形成。 但会输出正确推理步骤，不等于每次都执行可靠算法；模仿、记忆和真正组合泛化会混在一起。 把输入和输出说清楚： 输入是大量、多样的训练文本和足够的模型容量；训练直接输出的是更低的预测损失与一组内部表示，而可被提示调用的翻译、代码或推理表现是这些表示的迁移结果。能力测评上升只能说明模型在该测试中表现更好，不能单凭流畅回答断言它具有人的理解；要用新组合、反事实和分布外题目检查能力边界。 压缩与理解的关系 为了用有限参数在许多上下文中续写，模型会学习可复用的语法、语义和推理模式；这解释了它为何能泛化。但参数也会记忆训练片段，行为能力也不等同于人类理解。更稳妥的说法是： 压缩压力促成了有用的内部表示 ，而不是“规律就是完整理解”。 这一切都以 规模 为前提。参数、数据、算力按比例一起放大时，模型这种「猜词能力」会平滑地变强，很多具体能力也随之出现。 诚实的边角 「某些能力在规模跨过某个点后 突然涌现 」是流行说法，但也有研究指出，换一种连续的评价方式后曲线其实是平滑上升的——「突然」可能来自我们用了非黑即白的指标。这个争论没有定论；知道它有争议即可，不必站队。

### 3.7 生成时的旋钮：采样、温度、上下文窗口

第 2 节说输出是「一张概率表」。既然是概率，具体怎么从里面挑词？这直接决定了它多稳、多有创意。 7.1 挑词：贪心 vs 采样 最简单是 贪心 ：每步都挑概率最高的那个 token。稳，但容易呆板、重复。更常用的是 随机采样 ：按概率大小掷骰子，高概率词更可能被选中，但低概率词也有机会——这带来多样性和「创意」。 因此，解码过程的输入是模型给出的 logits、采样参数和当前可见前文，输出是本步被选中的 token；循环执行后才得到最终文本。它改变的是同一模型概率分布的取法，而不是重新训练模型。 7.2 温度：一个调「胆量」的旋钮 采样前，先把 logit 除以一个 温度 T 再做 softmax：。 P(w) = softmax(z / T)_w。 z 是词表各候选的 logits， T 是采样温度， w 是某个候选 token， P(w) 是温度缩放后选到它的概率。T 只改变当前分布的形状，不会修改模型参数或补充新知识。 温度； 对分布的影响； 表现。 T → 0； 分布变尖，几乎只剩最高那个； 确定、保守、可能重复。 T = 1； 就用模型原本的分布； 默认。 T > 1； 分布被摊平，低概率词也有机会； 多样、有创意、也更容易跑偏。 。 温度其实在调「熵」 用信息论的话说，温度调的是输出分布的 不确定性（熵） ：低温＝低熵＝更笃定，高温＝高熵＝更发散。所谓「让模型更有创意」，本质就是把这张概率表摊得更平一点。 7.3 上下文窗口：它一次能看多长前文 模型一次能直接条件化的 token 数有上限，叫 上下文窗口 。窗口之外的内容不会自动参与本次计算，除非应用重新检索或摘要注入。标准全局注意力的分数矩阵随长度平方增长，是重要约束；KV 缓存、硬件、位置表示和训练长度也共同影响可用窗口。

### 3.8 从「基座」到「助手」：三步

预训练完，我们得到一个会「续写」的超强模型。可你把问题丢给它，它可能续写出 更多问题 而不是回答。为什么？还差哪几步？。 因为预训练只教了它「文本通常怎么接下去」，没教它「被提问时应该 回答 」。补齐要两步，合起来是今天所有对话模型走的三段路：。 这里的输入不再只是原始网页文本，而是“指令—理想回答”示范、回答偏好比较或反馈数据；输出是参数经过继续更新、行为更符合目标规范的助手模型。比较三个阶段时，要分别观察知识与续写能力、指令遵循率、偏好和安全指标，不能把“更听话”误读成“事实更正确”。后训练只改变行为倾向，无法保证每次回答都正确、安全，也不能替代检索、工具和外部验证。 阶段； 做什么； 补上了什么。 ① 预训练（得到 基座模型 ）； 海量文本上自监督预测下一个词； 渊博的语言、知识、模式——但不听话。 ② 指令微调 SFT； 用「指令 → 理想回答」的示范数据继续训练； 学会「被问就答」的对话格式与习惯。 ③ 偏好对齐（RLHF / DPO）； 用人类对「哪个回答更好」的偏好来调； 答得更有用、更安全、更像人想要的。 。 图示：从基座模型到对话助手的三阶段。 图 4 你日常用的对话模型，都是走完这三步的产物。基座模型很强，但「能对话、听话、安全」是后两步教的。 。

### 3.9 一句话，推出 LLM 的一切

现在把机制收束成一句能记一辈子的话——它几乎能推出 LLM 的所有典型行为和风险。 记住这一句 它输出的是 「在训练数据的统计规律下，最可能接下去的内容」，而不是「事实」 。它优化的是「像不像人写的下一个词」，从来不是「对不对」。 从这一句往下推：。 由这句性质； 直接推出。 只追求「最可能」，没有真值约束； 会 幻觉 ——把话说得流畅自信，内容却是编的。 知识全来自训练那一刻的数据； 有 知识截止日期 ；要最新/私有事实，得 外挂检索（RAG） 。 「最可能说的」≠「应该说的」； 需要 对齐 ，才不会有用地帮倒忙。 在它眼里，指令和数据都只是 token； 会被 提示注入 ——藏在内容里的指令可能被当成命令执行。 一次一个 token、无全局草稿； 能把错误答案也说得圆；靠「让它先写推理过程」等技巧改善。 。 这里的 语言似然 ，是模型依照训练数据的统计规律，给某段续写分配的相对可能性；它用来比较哪种续写更像训练文本，并不负责核验事实真伪。语言似然不等于事实真值，确实解释了幻觉风险和为什么需要外部证据；但 RAG 还解决知识更新与私有数据，对齐处理偏好和安全目标，提示注入则源于指令与不可信数据共享同一输入通道。它们相关，却不是完全相同的单一根因。 给定提示和上下文，模型输出候选 token 的概率以及由解码形成的续写；若任务要求事实结论，还必须把续写交给检索、引用或工具验证。高语言似然只能解释“像训练文本”，不能当作事实证明。

### 3.10 把整条因果链连起来

把全页串成一条链，逐环检查「每个环节为什么必须存在」。 把语言任务都改写成「续写」，就能用 一个 通用模型顶替一堆专用模型。 （§1） 。 「续写」= 每步在词表上输出一张概率表，取一个词再拼回、滚动生成。 （§2） 。 文字先被切成 token、再变成向量，模型才有的算。 （§3） 。 Transformer 用带因果掩码的注意力，把前文加工成「足以预测下一个词」的表示。 （§4） 。 训练目标是「预测真实的下一个词」，答案来自文本本身——不用标注，所以能吃海量数据、能 scale。 （§5） 。 把「猜词」逼到极致，理解、推理、翻译作为副产品被逼出来；规模越大越强。 （§6） 。 生成时用采样与温度在「稳」和「有创意」之间调，上下文窗口决定它能看多长。 （§7） 。 预训练得到博学的基座；再经指令微调和偏好对齐，才成为听话、安全的助手。 （§8） 。 语言似然不等于事实真值，带来幻觉与外部证据需求；对齐和提示注入还分别涉及目标规范与信任边界。 （§9） 。 过关标准 如果你能不看笔记，讲清「为什么预测下一个词不用标注、又能学会推理」，并说出「为什么幻觉是结构性的」，你就真正跨过了 LLM 的原理门槛。

### 3.11 常见误解

误解； 更准确的理解。 它像数据库，在「查」答案； 它在 生成 最可能的下一个词；没有可查的条目，也因此会编。 它先想好整句再回答； 一次一个 token 自回归生成，没有全局草稿。 它知道自己不知道； 不知道。答对和瞎编，它做的是 同一件事 ：挑最可能的下一个词。 参数量越大一定越强； 要参数、数据、算力 按比例 配平；单拉一项会浪费。 它能实时知道最新消息； 知识止于训练时；要最新/私有信息得靠检索（RAG）或工具。 调「温度」是在改它的知识； 只是在改 挑词的随机性 （分布的熵），不改它会什么。 ChatGPT 就是预训练出来的； 预训练只给基座；「会对话、听话、安全」是指令微调和对齐教的。 。

### 3.12 检查你是否真的理解

「把任务改写成续写」为什么能让一个模型顶替一堆专用模型？。 模型每一步的输出到底是什么？为什么说它是「一张概率表」而不是「一个词」？。 自回归生成是什么意思？它和「先想好整句再说」有何本质不同？。 为什么预训练「不需要人工标注」？这一点和「能 scale」有什么关系？。 因果掩码解决了什么问题？没有它训练会出什么错？。 用一句话解释：为什么「只会猜下一个词」的模型能学会推理？。 温度调高和调低，分别让生成变成什么样？它在调分布的什么？。 为什么预训练完的基座模型还不能直接当聊天助手用？。 为什么说「幻觉是结构性的」，而不是「再大一点就能修好」？。 参考答案 因为翻译/问答/摘要/分类都能表述成「给定前文，接着往下写」，于是同一套「会续写」的参数就能顺手做全部，不必各自建模型、各自标数据。 是词表上所有候选 token 的一张概率分布（最后一层数值经 softmax 得到）；取其中一个（贪心或采样）才得到一个词。 一次只生成一个 token、并把它拼回输入再预测下一个；它没有全局草稿，是逐词滚动出来的，所以能把错误也说得很圆。 因为「正确答案」就是文本里真实的下一个 token，数据自己当标签；不靠人标，数据近乎无限，于是加数据/参数/算力成了可持续的路。 它保证预测第 t 个词时只看前文、不偷看答案；没有它等于拿答案预测答案，学不到东西。 因为要把下一个词猜准，往往被迫理解语法、事实、逻辑和意图——能力是为猜准而被逼出的副产品。 调高＝分布摊平＝更随机多样也更易跑偏；调低＝分布变尖＝更确定保守；它调的是输出分布的不确定性（熵）。 基座只学了「文本通常怎么接」，没学「被问要回答」；还要指令微调教它对话、偏好对齐教它有用又安全。 因为它优化的目标是「最可能的下一个词」（似然），本就没有真值约束；规模能让它更像、更少错，但只要目标是似然而非真相，编造的可能就消不掉。

## 3.1 预训练（pretraining）

### 3.1.1 为什么要「预」训练

本节回答：为什么不直接拿任务数据训练，非要先来一步「预」训练？。 直接针对某个任务训练，要专门标注的数据，而且学到的只有那一小块本事。预训练换了个两段式的思路： 先 在海量通用数据上学出一个「通用底子」（语言怎么用、世界大致什么样）， 再 针对具体任务做少量调整。「预」，就是「在面对具体任务之前，先打好通用基础」。 把任务说完整： 预训练输入的是大规模通用数据和一个尚未学会任务规律的模型，输出是一份可继续微调或直接用于表示提取的参数检查点。训练过程中，模型反复从数据自身构造目标、计算损失并更新参数；我们要通过留出集损失和多类能力评测判断“通用底子”是否形成，而不能只看训练损失。它适合复用广泛规律，但若目标领域与预训练数据相差很远，仍需领域适配，甚至应选择专用模型。 先通才，后专才 这就像人先接受多年通识教育（预训练），再做岗前专项培训（微调）。通识那一步最贵、最耗时，但一次做好，之后各种专项都能快速上手。

### 3.1.2 它具体怎么训

这份「通用底子」，是怎么从数据里学出来的？。 核心是 从数据本身构造监督信号 。自回归模型预测下一 token，BERT 类编码器预测被遮住的 token，多模态系统还会用图文对比或重建目标。以自回归为例，用交叉熵衡量预测分布与真实下一 token 的差距，再用梯度下降更新参数。它减少了逐样本人工标签需求，但高质量数据并非无限：采集许可、清洗、去重、语言与领域配比都会直接影响能力、偏见和记忆风险。 预训练目标； 输入怎样构造； 模型输出什么； 适用重点。 下一 token 预测； 给定左侧前缀； 下一 token 的词表概率； 自回归生成模型。 掩码预测； 遮住序列中的部分 token； 被遮位置的词表概率； 双向编码表示。 对比或重建； 配对视图，或被破坏的样本； 匹配分数，或还原后的样本； 视觉与多模态表示。 。 三者都在解决“怎样让原始数据自己提供学习目标”，却不是可以随意互换的同一算法。目标决定模型每次能看见什么、输出什么，也影响它更擅长生成、编码还是跨模态匹配。验证时必须使用与目标相符的留出数据，并额外检查数据泄漏、重复样本和目标与下游任务的错位。 一句话 预训练 = 在尽可能多的文本上，反复做「预测下一个词」这一个自监督任务 。简单到反直觉，却是整座大厦的地基。

### 3.1.3 手算一次 next-token 训练信号

一句文本怎样同时产生多个训练样本，预测变准又怎样让损失下降？。 文本 猫 喜欢 鱼 <EOS> 经过右移，会产生三次预测：看到“猫”预测“喜欢”，看到“猫 喜欢”预测“鱼”，再预测结束符。假设模型给三个正确 token 的概率依次为 0.50、0.25、0.80：。 前缀； 正确下一个 token； 正确概率 p； 损失 −ln p。 猫； 喜欢； 0.50； 0.693。 猫 喜欢； 鱼； 0.25； 1.386。 猫 喜欢 鱼； <EOS>； 0.80； 0.223。 。 公式：平均交叉熵等于三个位置负对数概率的平均，约为零点七六七；困惑度等于平均交叉熵的指数，约为二点一五。 符号说明： L̄ 是三个预测位置的平均交叉熵， t 是位置编号， pₜ 是模型在位置 t 分给正确 token 的概率， ln 是自然对数。 PPL 是困惑度， exp 是以自然常数 e 为底的指数函数，正好把平均负对数损失变回概率尺度；在相同分词器和数据上，PPL 越小通常表示模型越会预测后续。 第二个位置最不确定，贡献最大损失。反向传播会同时调整共享参数，使相似上下文下正确 token 的 logit 相对上升。若一次更新后“鱼”的概率从 0.25 升到 0.50，该位置损失就从 1.386 降到 0.693。 图示：同一文本右移产生三个下一 token 训练目标。 训练不是每段文本只给一个标签；长度为 L 的序列通常贡献约 L 个 next-token 监督位置，因此大规模原始文本可自动产生密集训练信号。 低困惑度不等于事实更真或助手更好。 它只表示在评测文本分布上更会预测 token；数据污染、记忆、风格捷径和任务错位都可能让该指标与真实能力分离。

### 3.1.4 凭什么这一步能灌进这么多能力

最关键的疑问：只是预测下一个词，怎么就学到了语法、常识，甚至推理？。 因为要降低许多不同文本上的预测误差，模型必须形成能复用的语法、语义、代码结构和事实共现表示：只背某一句，无法解释大量新前缀。输入是跨主题的大规模样本，训练直接输出的是更低损失和更新后的内部表示；翻译、代码或推理成绩，是这些表示被提示和评测任务调用后的外部表现。 这里不能把“会续写推理文本”直接等同于可靠推理。模型可能复用了抽象规律，也可能记住模板或利用表面线索。若新组合题、反事实题和分布外样本仍能稳定答对，才有更强的泛化证据；若只在熟悉格式上成功，就不能声称学到了通用算法。 规模怎样读 增加参数、数据和算力，通常能平滑降低预测损失，并可能使某些能力越过可用阈值；这类经验关系称为 缩放定律 。但规模不是充分条件：数据质量、目标设计、模型结构和评测口径都会改变结果，“更大”也不保证事实可靠或对所有群体更公平。

### 3.1.5 产出的是「基座模型」

预训练跑完，我们是不是就得到一个能用的助手了？。 还不是。 预训练结束时得到的是 基座模型（base model） ：知识渊博，但 不听话 ——你问它一个问题，它可能顺着续写出 更多问题 ，而不是回答。因为它只学了「文本通常怎么接下去」，没学「被提问时应该回答」。 要把基座变成能对话的助手，还要两步： 指令微调 教它「被问就答」， 偏好对齐 教它答得有用又安全（见「微调」「对齐」深读页）。 因此本阶段的输入是预训练数据流，输出是基座模型检查点及其训练记录；“能续写且留出损失较低”说明语言建模目标取得进展，不说明它已经遵循指令。后续训练可以改变回答习惯和偏好，却也不能保证事实正确；高风险用途仍要独立评测、检索或工具验证。 图示：从海量文本到基座模型再到助手。 图 1 预训练负责灌进「知识与能力」，得到博学但不听话的基座；微调与对齐负责校准「行为」，把基座变成你日常用的助手。三步缺一不可。 。 分工记住这一句 预训练给「会什么」，微调对齐给「怎么表现」。 模型的绝大部分知识和能力，都是预训练那一步灌进去的。

### 3.1.6 它为什么这么贵

既然预训练这么关键，为什么不是人人都能做？。 前沿通用模型的从头预训练会消耗大规模数据、加速器集群与长期工程投入，成本通常只有少数机构能承担；但“小模型预训练”并非绝对做不起。总训练预算还要在参数量与 token 数之间分配，Chinchilla 等工作表明：只增参数而训练数据不足，并非计算最优。 成本来源； 为什么会增长； 工程结果。 计算与显存； 更多参数和 token 需要更多前向、反向计算； 决定训练时长与加速器规模。 通信； 多设备要同步梯度、参数或激活； 集群利用率可能被网络拖住。 数据工程； 采集、许可、过滤、去重和配比需反复迭代； 决定污染、偏见和长尾覆盖。 失败与验证； 硬件故障、数值异常和坏批次会中断长训练； 需要检查点、监控和恢复系统。 。 预算规划的输入是目标模型规模、训练 token 数、硬件效率和数据方案，输出是预计计算量、时间、成本及可恢复的检查点计划。实际吞吐低于理论峰值并不一定表示模型设计错误，也可能是通信或数据管线瓶颈；反过来，训练跑得快也不代表数据和能力质量达标。小规模领域模型、继续预训练或直接微调何者合适，要按数据量、任务差异和预算选择。 这也正是「微调」存在的理由 既然预训练这么贵，绝大多数人不会从头来，而是 站在别人预训练好的模型上做微调 （迁移学习）——花很小的代价，就借用了那份天价的通用底子（见「微调」深读页）。预训练与微调，是「一次昂贵的通才养成」和「无数次廉价的专才适配」的分工。

### 3.1.7 把整条因果链连起来

从原始文本到基座模型，监督信号、优化与后训练怎样接成一条链？。 针对任务直接训练又贵又窄，于是先学通用底子、再适配任务——这就是「预」训练。 （§1） 。 它用数据自身构造监督信号：自回归模型预测下一 token，其他架构也可用掩码、对比或重建目标，因此能利用大规模弱标注数据。 （§2） 。 每个位置以 −ln p 贡献损失，整段文本自动产生密集监督；梯度让正确 token 的相对概率上升。 （§3） 。 预测目标迫使模型压缩许多可复用结构，但能力与数据、规模和任务分布共同决定。 （§4） 。 产出的是博学但不听话的基座，还需微调+对齐才成助手。 （§5） 。 预训练同时消耗数据、算力、通信与工程时间，所以多数团队复用基座再适配。 （§6） 。 过关标准 如果你能讲清「预训练为什么能不用标注就学到这么多」，并说出「基座模型和对话助手差在哪两步」，你就抓住了它的内核。

### 3.1.8 常见误解

哪些说法把自监督、语言建模指标和助手行为混成了一件事？。 误解； 更准确的理解。 预训练需要大量人工标注； 是 自监督 ，答案来自文本本身，不用人标。 预训练完就是 ChatGPT； 得到的是不听话的基座，还需指令微调和对齐。 模型的能力主要靠微调； 绝大部分知识和能力来自预训练；微调主要改行为。 所有预训练都只有下一 token 目标； 自回归模型常用它；编码器、多模态模型还会用掩码、对比、重建等目标。 谁都能预训练一个大模型； 需海量数据+算力+时间，极贵；多数人做微调。 。

### 3.1.9 检查你是否真的理解

为什么要先「预」训练，而不是直接针对任务训练？。 预训练用什么目标、什么监督方式？为什么能用海量数据？。 只是预测下一个词，为什么能灌进语言、常识、推理？规模起什么作用？。 预训练产出的「基座模型」为什么还不能当助手用？还差哪两步？。 预训练为什么贵？这和「微调」的流行有什么关系？。 参考答案 直接针对任务训练要标注、且只学一小块；先学通用底子再适配任务，通用那步一次做好、之后各任务都能快速上手。 监督信号来自数据自身：可预测下一 token、遮住的 token，或使用对比/重建目标。这样减少人工标签需求，但数据仍受质量、许可、去重和配比约束。 因为猜准下一个词往往被迫理解语法/事实/逻辑，能力作为副产品被逼出；规模足够大时这些能力才充分涌现（缩放定律）。 基座只学了「文本怎么接」，不会「被问就答」；还需指令微调（教对话）和偏好对齐（教有用又安全）。 因为它同时吃海量数据、成千上万显卡、数月时间；正因如此，多数人不从头预训练，而在别人的基座上做廉价的微调。

### 3.1.10 概念依赖与延伸学习

学习层级； 涉及概念。 先修； 监督学习、自监督学习、大语言模型、Transformer。 本页核心 ； 两段式（预训练→微调）、自监督预测下一个词、基座模型、通才 vs 专才。 紧邻延伸； 缩放定律、微调、对齐、指令微调。 更远； 合成数据、蒸馏、量化与部署。 。

## 3.2 后训练 Post-training（post-training）

### 3.2.1 它在训练链条里的位置

预训练结束后，模型已经博学，为什么还不能直接当助手？。 文本似然 是模型给训练文本及其续写分配的相对可能性；预训练提高它，是为了学会数据中常见的语言规律，而不是判断“用户现在希望我怎么做”。后训练改用更接近产品目标的数据和反馈，塑造指令遵循、风格、工具使用、安全边界与推理策略。 后训练是阶段总称，微调是其中使用的参数更新手段。 。 后训练的输入是基座模型、指令示范、偏好比较或可验证反馈，输出是参数更新后的助手模型和相应评测记录。各阶段都通过“生成候选—比较目标—计算损失或奖励—更新参数”改变回答分布。结果应解释为目标行为的触发概率发生变化，不是模型突然拥有了权威事实；若基础能力、事实性或少数语言切片回归，就不能仅凭总偏好分数宣布成功。

### 3.2.2 第一层：监督微调 SFT

怎样先教会模型“收到指令就这样回答”？。 收集高质量的“指令—理想回答”示范，用交叉熵继续训练。SFT 建立基本行为分布：回答而非随意续写、按格式输出、在合适位置拒绝。它高度依赖示范覆盖和质量。 每个训练样本输入一条指令和可选上下文，目标输出是示范回答中的 token 序列；模型像预训练一样逐 token 降低交叉熵。训练后，格式遵循率或拒答准确率提高，表示模型更常复现示范行为，并不表示未覆盖场景也会正确。示范之间若标准冲突、语言失衡或充满模板，模型会把这些问题一并学进去。 SFT 学的是示范分布。 示范没覆盖的新场景仍可能失败；把大量最新事实塞进 SFT 也难以更新和溯源，变化知识通常更适合 RAG。

### 3.2.3 第二层：偏好优化

当“最好回答”写不成唯一标准答案时怎么办？。 让标注者比较同一提示的多个回答，再用 RLHF 或 DPO 提高被偏好回答的概率。比较信号比逐字标准答案灵活，但它只是人类目标的代理，可能偏爱冗长、自信或迎合。 输入是提示 x 、被偏好的回答 y⁺ 、较差回答 y⁻ ，以及作为行为锚点的参考模型。训练输出仍是更新后的策略模型：它应拉大好回答与差回答的相对分数，但又不能为迎合偏好数据而完全丢掉原有语言能力。 公式：总目标等于偏好收益减去 lambda 乘当前策略与参考策略的 KL 偏离。 怎样读式子： θ 是正在更新的模型参数， J 是要提高的总目标， R偏好 衡量回答符合偏好数据的程度。 πθ 是当前模型的回答分布， π参考 是更新前或 SFT 模型的分布； KL 衡量当前分布偏离参考分布多少， λ 控制“追求偏好”与“别偏离太远”的权衡。这里是帮助理解 RLHF 类目标的结构式；DPO 会把比较数据写成可直接优化的分类式，不必显式训练同一个奖励模型。 偏好胜率提高表示在当前标注者、提示和候选生成方式下更常选中目标回答，不是普遍质量或事实正确率。偏好有群体差异，参考模型和 λ 也会改变结果；必须另测迎合、冗长、事实性、拒答和跨群体表现。

### 3.2.4 第三层：可验证反馈与推理

数学、代码等有客观答案的任务，能否用更强反馈？。 可以用单元测试、答案检查器、证明器或过程验证器给反馈。输入是题目、模型生成的答案或步骤以及验证规则，输出是通过/失败、分数或具体出错步骤。结果奖励稀疏但定义清楚，过程反馈更早指出哪一步偏离，却需要昂贵标注且可能偏好特定解法。模型由此学习拆解、搜索、检查与修正，形成推理模型的重要训练来源。 验证分数上升只说明模型更会满足当前检查器。验证器不是事实本身：测试覆盖、证明器公理和规则代码决定可见目标。弱验证器会被奖励黑客利用，所以要保留隐藏测试、对抗样例和独立终验，并监控训练奖励与真实任务指标是否背离。

### 3.2.5 它改变什么、不改变什么

看到后训练指标改善时，怎样区分新增能力、能力被更稳定调用和表面风格变化？。 擅长改变 ：行为方式、格式、拒答边界、工具选择、推理策略。 可能重分配 ：已有能力何时被调用。 不保证 ：注入精确可更新事实、消除幻觉、在分布外稳定泛化。 可能损伤 ：过窄数据会造成能力回归或过度拒答。 能力“出现”与“被稳定调用”要分开测：基座模型可能在少量采样中解出题，却不会默认采用该策略；后训练可提高触发概率，但也可能让模型过早套用固定模板。评测应同时看 pass@1、更多采样下的能力上限和跨提示鲁棒性，判断究竟新增了能力、提高了可访问性，还是只改变表面风格。 事实更新还涉及删除与时间：权重很难证明某条旧政策已彻底移除，也无法自然给出处。需要可撤销、可审计知识时，检索或工具查询通常比继续训练更合适。

### 3.2.6 评测与数据闭环

训练损失下降，是否说明助手真的更好？。 必须在独立保留集上同时测帮助性、事实性、安全、推理、格式、延迟与成本，并按语言、领域、风险和长度切片。新失败样例可回流成训练数据，但测试集不能直接混入训练，否则形成污染；应保留永不训练的终验集，并记录每批数据来源与去重关系。 采用阶段闸门：SFT 后先查基础能力，偏好阶段后查帮助/迎合与拒答，可验证训练后查目标任务和验证器外泛化。若总分升高但某类用户或任务回归，不能用平均值掩盖。

### 3.2.7 把因果链连起来

数据、目标和约束怎样逐层改变同一个基座分布？。 预训练提供广泛能力，但目标不是用户意图。 SFT 用示范建立助手基本行为。 偏好优化处理没有唯一答案的质量取舍。 可验证反馈训练搜索、检查与修正。 代理目标可能被钻空子，所以要约束并独立评测。 后训练塑造行为，不替代外部事实系统。

### 3.2.8 同一个退款提示怎样穿过三阶段

基座模型会续写、SFT 助手会回答，偏好与可验证反馈又分别改变什么？。 图示：同一基座模型经过 SFT、偏好优化和可验证反馈形成助手行为的后训练流程。 图 1 三阶段使用不同监督信号：SFT 模仿示范，偏好优化排序可行回答，可验证反馈奖励能被外部检查的结果或过程。 候选回答； SFT 似然； 偏好概率； 规则验证； 最终解释。 A：一律超过 30 天不可退； 0.45； 0.20； 失败：忽略质量例外； 流畅但事实条件不完整。 B：质量问题可能适用例外，并核对订单； 0.35； 0.70； 通过； 保留。 C：保证全额退款； 0.20； 0.10； 失败：无订单证据； 过度承诺。 。 偏好数据把 B 相对 A 的胜率从原始候选倾向中抬高，但“偏好 0.70”不是事实正确率；外部规则验证进一步检查日期、质量例外和订单字段。若验证器只检查是否出现“质量问题”，模型可能学会堆关键词而不核对订单，这就是奖励投机。 阶段分工： SFT 先让有效行为进入模型分布；偏好优化在候选间移动概率质量；可验证反馈把搜索预算导向可检查目标。任何阶段都不能超过数据、奖励和评测覆盖。 失败边界： 后训练会改变已有能力的可访问方式，也可能产生过度拒绝、迎合、模式化措辞和领域回归。上线必须同时保留基座能力、目标行为和安全切片，不能只看一个总奖励。

### 3.2.9 概念依赖与评测路线

怎样避免把后训练、微调、对齐、RLHF 和事实更新混成同一个词？。 层级； 概念依赖与延伸。 先修； 预训练、监督微调、交叉熵、采样。 本页核心 ； SFT、偏好数据、RLHF/DPO、可验证奖励、KL 约束与回归。 紧邻； 对齐、推理模型、测试时计算、奖励投机。 工程延伸； 模型评测、训练数据治理、RAG、人在回路与安全护栏。 。 训练评测至少分三层：离线目标是否优化、目标行为是否改善、未直接优化的能力是否回归。还要与提示工程、RAG 或更强基座比较同等成本收益；如果只是需要最新政策，把事实写进权重通常比检索更难更新、删除与溯源。

### 3.2.10 常见误解与自测

常见误解； 更准确的理解。 后训练就是 RLHF； RLHF 只是偏好阶段之一，还包括 SFT、DPO、拒绝采样和可验证训练。 后训练让模型学会所有新事实； 更适合塑造行为；可更新事实通常用检索。 奖励越高越好； 弱奖励会诱发奖励黑客，必须看独立评测。 。 为什么预训练模型不能直接等同于助手？。 SFT 与偏好优化分别解决什么？。 为什么验证器既有用又危险？。 后训练为什么不能替代 RAG？。 参考答案 预训练优化似然而非用户意图。 SFT 教基本示范行为；偏好优化处理多个可行回答的排序。 它提供客观反馈，但代理不准时会被模型钻空子。 权重中的事实难更新、难溯源，检索更合适。

## 3.3 微调 Fine-tuning（fine-tuning）

### 3.3.1 什么是微调

本节回答：已经有了强大的预训练模型，怎么让它专精我这一件事？。 从零训练一个大模型，要海量数据、成千上万张显卡、几个月时间——绝大多数人做不起。微调换了个思路： 拿别人预训练好的模型当起点，用你自己的一小批数据，让它接着训练一会儿 ，权重只被 轻微 调整。通才于是变成了专才。 微调的输入是预训练模型、任务样本和训练配置，输出是适配后的权重或一个可挂载的适配器。训练仍然计算任务损失并用梯度更新参数，只是起点不是随机权重、数据范围也更窄。留出任务指标提高说明模型更适合当前任务；若通用能力或其他语言切片下降，则说明专精伴随回归。数据太少、任务差异太大或基础模型本来不会该任务时，“轻推一步”未必够。 ； 从零训练； 微调。 起点； 随机初始化的空白模型； 已预训练好的模型。 数据量； 海量； 少量、针对性。 成本； 天价（算力/时间/数据）； 相对很低。 产出； 一个通用能力； 一个专精某任务/领域的版本。 。 一句话 微调不是「造一个新模型」，而是 「把一个现成的好模型，往你的方向推一小步」 。

### 3.3.2 它凭什么有效：迁移学习

最关键的疑问：为什么用一小批数据「接着训一会儿」就够，不必从头学？。 因为预训练模型 早就学到了大量通用的、可复用的东西 ：语言的语法结构、常识、基本推理，图像里的边缘纹理和形状。这些底层能力对几乎所有下游任务都有用。你要专精的那件事，往往只需要在这些通用能力之上 做小幅调整 ——把已有的表示「拨」向你的目标。这种「把一个领域学到的能力搬到另一个任务上」的思路，叫 迁移学习 。 输入是源任务中学到的参数表示和少量目标任务样本，输出是对目标任务更合适的决策边界或生成行为。梯度会优先调整当前样本最相关的表示与输出方向，而不是从零重新发现全部语言规律。目标数据越接近预训练覆盖、基础表示越可复用，迁移通常越省样本；若领域、模态或标签含义差异很大，还可能出现负迁移，表现甚至不如更简单的专用方案。 图示：迁移学习：在庞大的预训练能力上做小幅微调。 图 1 贵的那一步（预训练）别人已经替你做完了。微调只在这份庞大能力上，用少量数据推一小步——这就是它省数据、省算力的全部来源。 。 类比 一个已经博学的人转行，不必回炉重上小学，只要针对新岗位做一段 专项培训 就能上手。微调之于预训练模型，就是这段专项培训。

### 3.3.3 它能改什么、不能改什么

这是全页最实用、也最容易用错的一节：什么问题该用微调，什么问题不该？。 一句话分水岭 微调擅长改 「行为」 ——格式、语气、风格、做事方式；不擅长可靠地塞进 「大量新事实」 ——那更适合外挂检索（RAG）。 你的需求； 更该用； 为什么。 让它稳定只输出某种格式（JSON）； 微调； 这是行为习惯，示范多了就固化。 让它用某种固定语气/风格答； 微调； 同上，风格是可训练的行为。 让它掌握某专业领域的表达方式； 微调； 调的是「怎么说」，不是「记住哪条」。 让它知道我公司最新的文档/数据； RAG（检索）； 事实要可更新、可溯源；微调塞事实易学不牢又过时。 只是想让它这一次按要求做； 提示 / 上下文学习； 不用训练、迭代快，但仍有 token 与评测成本。 。 最常见的用错 「我想让模型知道我们公司的知识」——很多人第一反应是微调，其实多半该用 RAG ：知识会变，检索能随时更新、还能给出处；而把一堆事实硬塞进权重，既容易记不牢，又可能挤掉别的能力（见第 6 节的「遗忘」）。 记不住的事实交给检索，改不动的习惯交给微调。 。 做选择时，输入应是需求类型、知识更新频率、可追溯要求、调用量与延迟预算，输出是提示、RAG、微调或组合方案。格式通过率提高可证明行为更稳定；不能据此推断事实覆盖更完整。行为与知识常同时存在，因此实际系统可以用微调固定格式，再用 RAG 提供可更新证据。

### 3.3.4 指令微调：把「基座」调成「助手」

上一节说微调擅长「改行为」。有一个最重要的行为改造，你天天在用——它就是这么来的。 预训练完的 基座模型 只会「续写」，你问它问题，它可能续写出更多问题而不是回答。 指令微调（SFT） 就是用大量「指令 → 理想回答」的示范数据，对它做一次监督微调，教会它 「被问就答」 这个行为。 它就是监督学习 这里「指令」是输入、「理想回答」是标签，标准的监督学习一套（见「监督学习」深读页）。所以严格说： 指令微调 = 在预训练模型上做的一次监督学习 。 之后往往还有一步 偏好对齐（RLHF / DPO） ，用人类对「哪个回答更好」的偏好把它调得更有用、更安全。「预训练 → 指令微调 → 偏好对齐」这三步，就是今天所有对话助手的来路（详见「大语言模型」深读页第 8 节）。 SFT 样本输入指令和上下文，目标输出是示范回答的 token；交叉熵逐步提高示范回答的概率。指令遵循率上升表示模型更常复现训练规范，不代表回答事实必然正确。示范未覆盖、彼此冲突或把拒答标准写错时，模型会继承这些缺陷；偏好对齐也只是下一阶段，不能替代独立安全与事实评测。

### 3.3.5 不必改全部参数：参数高效微调

一个现实问题：模型有几千亿参数，微调一次是不是也得改动全部、也很贵？。 好消息是： 不用 。既然只是「推一小步」，那就没必要动全部权重。 参数高效微调（PEFT） 把绝大多数原参数 冻结不动 ，只训练一小撮新增的参数。最流行的做法是 LoRA ：在原权重旁边挂两个 低秩小矩阵 ，只训练它们，用来表示「该在原权重上加的那点改动」。“秩”可先理解为矩阵中彼此独立的变化方向数量；低秩假设任务适配只需少数方向，不必任意改变原权重的每个自由度。 图示：全量微调改动整块权重，LoRA 只训练旁挂的小矩阵。 图 2 全量微调更新整块权重（贵、每个任务存一整个模型）；LoRA 冻结原权重，只训练旁边两个低秩小矩阵。可训练参数常能降到不足 1%，显存大减，而且一个基座能挂多个「适配器」按需切换。 。 5.1 运行示例：一个秩 1 LoRA 怎样改写输出 用 2×2 玩具权重展示低秩更新。设基座矩阵 W=I ，LoRA 用列向量 B=[0.2,0.1]ᵀ 与行向量 A=[1,−1] 相乘：。 公式：权重增量 delta W 等于列向量 B 乘行向量 A，结果是一个秩至多为一的二乘二矩阵。 W 是冻结的基座权重， ΔW 是适配器学到的增量； A 把输入压到一个低维方向， B 再把该方向展开回输出空间。这里 A 只有一行、B 只有一列，所以乘积最多提供一个独立变化方向，记作 rank(ΔW)≤1 。 步骤； 输入 x=[3,1] 时的结果。 基座输出 Wx ； [3,1] 。 适配器增量 ΔWx ； [0.4,0.2] 。 合并输出 (W+ΔW)x ； [3.4,1.2] 。 。 训练只更新 A、B，W 保持冻结；部署时可动态挂载适配器，也可把 ΔW 合并进 W。真实 LoRA 还有缩放因子、目标层选择与 dropout，这些都会改变有效更新强度。 为什么这在实践里是默认 LoRA 这类方法省显存、训得快，还能 一个基座 + 多个可插拔适配器 ——切任务就换个小矩阵，不必各存一份满血大模型。对大多数团队，参数高效微调是起点，全量微调只在必要时才上。

### 3.3.6 三个最容易翻车的坑

微调看着简单，但翻车也集中在几个固定的地方。 过拟合 ：微调数据往往很少，模型容易把这几百条 背下来 、丢掉泛化。应对：低学习率、早停、正则化、别训太多轮（见「过拟合」「正则化」）。 灾难性遗忘 ：一门心思学新任务，把预训练学到的 通用能力忘了 （变得只会 JSON、别的都退化）。应对：用参数高效微调、更低学习率、在数据里 掺一些通用样本 。 数据质量 > 数量 ：微调的效果高度取决于示范数据的质量。 几百条高质量、格式一致的样本，常胜过一大堆噪声。 脏数据会被模型忠实地学下来。 一个反直觉点 微调不是「喂得越多越好」。数据脏、量大、训得久，往往比小而精更糟——因为你在教它「照着这些（不好的）例子办」。 先把几百条样本打磨干净，再谈规模。 。 风险检查的输入是训练曲线、独立任务集、通用能力基线和分层数据审计，输出是过拟合、遗忘或数据缺陷的定位。训练损失继续下降而验证集变差，是过拟合信号；目标任务提高但通用集下降，是遗忘信号；错误集中复制示范措辞，则应先修数据。低学习率、早停、通用样本混合和 PEFT 能降低风险，但不能替代独立留出集。

### 3.3.7 怎么选：微调，还是先别微调

面对一个真实需求，第一步该做什么？答案通常 不是 「马上微调」。 把三种手段看成一个 由轻到重的阶梯 ，从最省的试起，不够了再往上走：。 阶梯； 手段； 先试它，如果……。 ① 最轻； 提示 / 上下文学习； 调措辞、给几个示例就够 → 到此为止（无需训练、见「上下文学习」）。 ② 中； RAG 检索； 缺的是 事实/最新知识 → 外挂检索，别塞进权重。 ③ 最重； 微调； 要的是 稳定的行为/格式/风格 ，且提示压不稳、量也上来了 → 才微调。 。 务实顺序 先用提示/上下文学习 快速验证 「模型到底能不能做这件事」；缺事实就加 RAG；只有当你需要把某种 行为固化下来、且要长期稳定又省单次成本 时，微调才真正划算。 微调是终点，不是起点。 。 这条阶梯的输入是同一批代表性需求、质量门槛和总成本约束，输出是达到门槛的最轻方案。应在相同测试集上比较质量、延迟、单次 token、训练与维护成本；方案越重，版本管理和回归测试负担越大。它是默认试验顺序而非绝对规则：严格离线、极低延迟或大调用量场景，微调可能更早变得经济。

### 3.3.8 把整条因果链连起来

从预训练权重到稳定新行为，数据、更新范围和验证怎样共同约束迁移？。 从零训练太贵，于是拿预训练模型当起点、用少量数据继续训一小会儿——这就是微调。 （§1） 。 它有效，是因为预训练已学到通用能力，微调只需小幅调整（迁移学习）。 （§2） 。 所以微调擅长改「行为/格式/风格」，塞「大量新事实」则该交给 RAG。 （§3） 。 最重要的一次行为改造是指令微调（SFT）：用「指令→理想回答」把基座教成会听话的助手，本质是监督学习。 （§4） 。 既然只推一小步，就不必动全部参数——LoRA 冻结原权重、只训小矩阵，省显存又可插拔。 （§5） 。 常见翻车在过拟合、灾难性遗忘、数据质量差三处。 （§6） 。 因此面对需求，先提示、再 RAG、最后才微调——从轻到重。 （§7） 。 过关标准 如果你能讲清「微调为什么便宜（迁移学习）」，并准确说出「什么该微调、什么该用 RAG」，你就抓住了它最实用的内核。

### 3.3.9 常见误解

误解； 更准确的理解。 微调是从头训练一个新模型； 是在 预训练模型 上继续训、微调权重，成本低得多。 想让模型「知道」我的资料就该微调； 可更新的事实更适合 RAG ；微调擅长改行为而非记事实。 微调要改动全部参数； LoRA 等参数高效方法只训不到 1% 的参数就够。 数据越多微调越好； 质量与一致性常比数量更关键；脏数据会被忠实学下来。 微调只会变强、不会变弱； 可能过拟合，或 灾难性遗忘 丢掉原有通用能力。 有需求就该先微调； 先提示/上下文学习、再 RAG，微调是最后一档。 。

### 3.3.10 检查你是否真的理解

微调和「从零训练」最根本的区别是什么？为什么它便宜得多？。 用「迁移学习」解释：为什么用一小批数据继续训一会儿就够？。 「让模型稳定输出 JSON」和「让模型知道公司最新文档」，分别该用微调还是 RAG？为什么？。 指令微调（SFT）在做什么？为什么说它本质是监督学习？。 LoRA 是怎么做到「不改动全部参数」的？带来哪些好处？。 什么是灾难性遗忘？怎样缓解？。 面对一个新需求，为什么通常不该一上来就微调？正确的顺序是什么？。 参考答案 从零训练从随机初始化开始、要海量数据和算力；微调从预训练好的模型出发、只用少量数据轻微调整，因此便宜得多。 预训练已学到通用可复用的表示（语法、常识、底层特征），下游任务只需在此之上小幅调整，无需重头学。 JSON 是行为/格式，用微调固化；公司最新文档是会变的事实，用 RAG 外挂检索（可更新、可溯源），塞进权重易学不牢又过时。 用「指令→理想回答」示范数据把基座教成会回答；指令是输入、理想回答是标签，正是监督学习。 冻结原权重，只在旁边训练两个低秩小矩阵来表示改动；可训练参数常不到 1%，省显存、训得快，且一个基座能挂多个可插拔适配器。 为学新任务而丢掉预训练的通用能力；可用参数高效微调、更低学习率、在数据里掺通用样本来缓解。 因为提示/上下文学习无需训练、迭代快，往往就够；缺可更新事实时考虑 RAG。常见评估顺序是「提示/ICL → RAG → 微调」，但应按质量、延迟与维护成本选择。

## 3.4 PEFT / LoRA：冻结主干，只学习低秩权重增量（peft-lora）

### 3.4.1 任务适配为什么可能是低秩变化

一个 d×k 大矩阵为何不必让每个元素都独立变化？。 先把词说清：线性层的基座权重 W 把 k 维输入变成 d 维输出；微调想学的是它的改变量 ΔW 。矩阵的“秩”可先理解为它包含多少个彼此独立的变化方向。若任务只需少数方向，ΔW 就可以由两个更窄的矩阵相乘得到，而不必独立存下 d×k 个改变量。 预训练已学到通用表示，新任务可能只需沿少数方向调整注意力或特征。若 ΔW 的有效秩很低，可用 B(d×r)A(r×k) 表示，r 远小于 d、k。输入仍是原层的 k 维向量，输出仍是 d 维向量，只是额外叠加一条低秩分支。 这是经验假设，不是所有任务定理。复杂领域迁移、多任务冲突或从未学过的能力可能需要更高 rank、更多目标层或全量微调。 低秩的是增量，不是基座。 推理仍需完整 W；LoRA 只以小分支改变其输出。

### 3.4.2 前向公式与缩放

LoRA 分支怎样与原线性层相加？。 公式：输出 h 等于基座权重 W 乘输入 x，加 alpha 除以秩 r 再乘 B A x；A 是 r 乘 k，B 是 d 乘 r。 x 是 k 维输入， W 是冻结的 d×k 基座权重， h 是 d 维输出。 A 先把 k 维输入压到 r 维， B 再把 r 维展开到 d 维； ℝ 表示矩阵元素是实数。 r 是秩上限， α 是缩放系数，比例 α/r 控制低秩分支相对基座分支的强度。 常将 A 随机初始化、B 初始化为零，使训练开始时 ΔW=0，不改变基座行为。α/r 控制更新尺度；rank 增大若 α 不调，增量尺度会变化。dropout 是训练时随机丢弃部分分支信号的正则化手段，可只作用 LoRA 分支。 反向不更新 W，但梯度要穿过 W 传播到早层适配器和 A/B；所以基座计算与激活并未消失。若目标指标提高而通用能力下降，说明低秩分支改变了任务行为但产生回归，不能只按训练损失选择配置。 rank 不是“压缩比旋钮”而已。 它改变可表达增量子空间，必须和 α、层、数据一起消融。

### 3.4.4 省的是哪些内存，哪些仍然存在

只训练 0.39% 参数，训练显存为什么不会缩到 0.39%？。 不为冻结 W 保存梯度与 Adam 一、二阶状态，适配器检查点也小；但基座权重、前向激活、反向所需中间值、临时工作区仍在。激活常随 batch、序列和层数主导。 资源； 全量微调； LoRA。 基座权重； 需要； 需要且冻结。 基座梯度； 需要； 通常不存。 基座优化器状态； 需要； 不需要。 激活； 需要； 仍需要，可检查点。 适配器状态； 无； 小但需梯度/优化器。 。 训练速度也不会按参数比例加速，因为 W x 的大矩阵乘仍占主要 FLOPs。

### 3.4.5 目标模块决定任务能改哪里

只对 Q/V 投影加 LoRA 与覆盖所有线性层，有何结构差异？。 Transformer 注意力中的 Q（查询）、K（键）、V（值）和 O（输出）投影，分别参与“找谁、怎样匹配、取什么信息、怎样送回主干”；MLP 是每层随后进行特征变换的前馈网络，gate/up/down 是常见实现里的门控、升维和降维投影。这里的 降维 只表示把向量的坐标数量从较多变成较少，用于让 MLP 输出回到主干维度；它不是在这一节把样本特征压成二维图。对这些模块加 LoRA，就是选择允许任务数据改动哪些计算环节。 目标层少更省、更易控，可能容量不足；覆盖更多层提升适配能力也增加过拟合与部署开销。配置输入是候选模块、rank 和相同训练预算，输出是各方案的任务、通用、安全和未见分布指标。 做受控消融：固定数据与总训练 token，比较 QV、全部注意力、注意力+MLP；rank 可按层不同。不要只看训练 loss，需目标任务、通用能力、安全与未见分布。若加更多层后训练损失下降而留出收益停滞，应解释为容量没有转化为泛化，而不是继续无条件扩层。 模块名依架构而异。 配置匹配不到目标层可能静默训练零参数；启动时列出可训练参数和层路径并断言数量。

### 3.4.6 QLoRA 把冻结基座量化存储

基座是 4-bit，梯度怎样通过它到达 LoRA？。 QLoRA 是“量化后的冻结基座 + 可训练 LoRA”的组合。量化把基座权重用更少比特近似存储；4-bit 表示每个量化编码只有 16 种取值，而计算时会把编码还原成较高精度近似值。基座参数不更新，但这次矩阵运算仍把梯度传给 A/B。 NF4 是针对近似正态分布权重设计的 4-bit 编码；double quantization 连量化尺度本身也再压缩；分页优化器在内存紧张时分批迁移优化器状态。它们分别处理权重表示、量化元数据和峰值内存，并不是三种精度相同的名字。 QLoRA 组合了量化误差与低秩适配上限。输入是量化基座、LoRA 配置和任务数据，输出是适配器及其量化训练配方。训练完成后合并到高精基座再重新量化，与保持分离推理不是同一产物；若两种产物指标不同，应归因到合并和再量化路径并分别评测。 资源边界： 训练内存下降不等于训练 FLOPs 同比例下降；反量化与基座前向、反向仍然发生。

### 3.4.7 合并与动态切换有不同工程边界

将 ΔW 写回 W 后，为什么文件更简单却更难回滚？。 合并 W←W+(α/r)BA 可消除分支额外矩阵乘，适合固定单适配器；分离保存便于按租户/任务切换和回滚，但调度需将相同适配器批在一起，频繁加载会抖动。 适配器必须绑定基座哈希、tokenizer、目标模块、rank、α、dtype 和训练数据版本。错基座即使形状相同也会产生未验证行为。合并顺序与量化顺序影响结果，产物记录完整配方。 形态； 优势； 风险。 分离； 小文件、可切换/回滚； 额外算子、批调度、错配。 合并； 单权重、推理简单； 新大文件、失去独立开关。 多适配器组合； 尝试能力组合； 尺度/方向干扰，无保证。 。

### 3.4.8 小参数比例不代表小行为变化

只改 0.1% 参数，为什么能让模型学会新格式，也能破坏安全拒答？。 神经网络行为由参数方向与放大链决定，不按改动数量线性变化。少量低秩更新作用于多层和所有输入，能显著重排 logits；窄数据还会过拟合措辞、遗忘通用能力或形成触发器。 训练数据需许可、去重和防投毒；第三方适配器视为可执行模型制品，扫描来源、签名和行为。对目标、通用、长上下文、多语言、安全、工具和校准做回归；逐层/逐适配器消融定位问题。 适配器供应链： 小文件易传播，也易绕过完整模型审查；加载权限应等同模型代码/权重。

### 3.4.9 何时选 LoRA，何时选其他方案

任务只需要新知识、固定格式或深层能力改变时，方案相同吗？。 知识频繁更新优先 RAG/工具；少量格式和行为可先提示/约束；多租户任务适配、有限算力适合 LoRA；需要广泛能力重塑且数据/资源充分可考虑全量微调；端侧体积目标还需蒸馏/量化。 比较同预算基线：提示、检索、LoRA、全量微调和更强模型。计算训练、存储、适配器路由、延迟、评测与维护的每成功任务成本，而非只看 GPU 能否跑。 停止条件： rank/层数增加后真实留出增益平台而通用/安全退化上升，应停止扩适配器容量。

### 3.4.10 常见误区与概念依赖

LoRA 是低秩参数化的训练方法，不是“零成本微调”或“低风险补丁”。 误区； 更准确的理解。 训练参数少，全部显存同比少； 基座和激活仍在，主要省梯度/优化器。 rank 越大越好； 容量、过拟合、状态和尺度需平衡。 QLoRA 训练 4-bit 梯度； 低位基座冻结，计算时反量化，训练 LoRA。 适配器可配任何同形基座； 必须绑定精确基座与模块语义。 改 0.1% 参数风险也 0.1%； 小增量可全局改变 logits 和安全行为。 。 层级； 概念依赖与延伸学习。 先修； 矩阵秩、微调、反向传播与优化器状态。 本页核心 ； 低秩增量、rank/alpha、目标模块、合并/切换。 组合； 量化/QLoRA、模型合并、蒸馏。 生产； 模型路由、数据治理、评测与供应链安全。 。

### 3.4.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 确定任务是否需参数适配。 选择目标层/rank/alpha。 冻结基座并训练 A/B。 消融容量与数据覆盖。 分离或按配方合并部署。 回归目标/通用/安全并记录血缘。

### 3.4.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 4096×4096、r=8 的 LoRA 参数多少？。 LoRA 主要省哪些状态？。 QLoRA 的基座如何参与计算？。 合并后要记录什么？。 为何仍需安全回归？。 假设“PEFT / LoRA：冻结主干，只学习低秩权重增量”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 如何为“PEFT / LoRA：冻结主干，只学习低秩权重增量”设计一个最小对照实验，证明观察到的改善来自核心机制，而不是数据、提示、权限或评测口径同时变化？。 。 参考答案 8×4096+4096×8=65,536，约原矩阵 0.391%。 冻结基座的梯度、优化器状态和任务检查点。 低位存储、前向反量化，冻结不更新但梯度传到 LoRA。 基座哈希、适配器、目标层、rank、alpha、dtype、顺序和量化配方。 少量低秩更新可全局改变输出和拒答行为。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。 固定数据、模型版本、提示、权限、预算和评测，只改变一个与核心机制直接相关的因素，并在多个样本与随机种子上重复；同时保存中间状态和失败样本。若差异只在目标因素变化时稳定出现，才支持机制解释，否则应继续排查混杂变量。

## 3.5 知识蒸馏：让小学生逼近教师的条件分布与行为（distillation）

### 3.5.1 硬标签只给答案，软分布还给相对关系

同样正确答案是 refund，教师对 ask 仍给 35% 与只给 1% 有何不同？。 知识蒸馏 用一个较强或较大的教师模型，为较小学生模型产生训练信号。硬标签只给最终正确类别，例如 refund=1、其他=0；软分布则给每个候选的概率。输入是同一条退款案例，教师输出 refund、ask、reject 的整张概率表，学生再学习逼近这张表。 教师给 ask 35% 表示案例接近“信息不足、应先询问”的边界；只给 1% 则表示证据更明确。硬 one-hot 标签都写 refund，丢掉这种类别相似性和边界信息。学生拟合教师完整分布，可获得更平滑、样本效率更高的监督。 学生更接近教师只表示行为迁移成功，不表示教师判断是真值。但教师概率可能失准；“更暗的知识”不自动等于真理。硬真值与教师信号应组合，并在真实标签上校准。 蒸馏对象： 可拟合 logits、隐藏表示、注意力、序列示范、偏好或验证反馈；每种可见信息不同。

### 3.5.2 温度把次优类别从接近零处拉出来

为什么 T>1 能显示教师认为哪些错误“比较像”？。 公式：温度 T 下第 i 类概率等于 softmax 对第 i 个 logit 除以 T；总损失等于 alpha 乘硬标签损失，加一减 alpha 乘 T 平方和教师学生软分布的 KL 散度。 z 是各类别未经归一化的原始分数（logits）， i 是类别编号， T 是温度；softmax 把 z/T 变成总和为 1 的概率 pᵀᵢ 。 L 是学生的总训练损失， L硬标签 衡量学生与人工真值的差距， α 在 0 到 1 之间，控制真值监督与教师监督的比例。 KL(p教师∥p学生) 衡量学生软分布偏离教师软分布多少；它不是对称距离，交换两边会改变惩罚重点。 增大 T 缩小 logit 差，使分布更平；低概率类别产生可学习梯度。乘 T² 常用于补偿 softmax 导数随温度升高而缩小的梯度尺度。训练后推理通常恢复 T=1。 KL 方向也重要：经典方向对教师赋予非零概率而学生漏掉的类别惩罚更明显，鼓励学生覆盖教师分布；反向 KL 更容易集中于少数高概率模式。生成式模型也可改用序列级目标，因此不能只写“用了 KL”而不说明方向和样本单位。 温度不是校准修复。 它用于训练信号软化，不保证教师或学生的部署概率可信。

### 3.5.3 运行示例：三个退款动作的温度软化

教师 logits [4,2,0] 在 T=1 与 T=2 时怎样变化？。 图示：教师三个动作 logits 经温度一和温度二 softmax 后的概率柱状图。 图 1 温度 2 保持排序，却让 ask/reject 的相对信息更可见。 动作； logit； e^z / Σ（T=1）； e^(z/2) / Σ（T=2）。 refund； 4； .867； .665。 ask； 2； .117； .245。 reject； 0； .016； .090。 。 若学生输出 [.60,.30,.10]，T=2 分布能明确奖励它给 ask/reject 留概率；仅硬标签会只推动 refund 接近 1。

### 3.5.4 logit、特征与关系蒸馏要求不同接口

拿不到教师内部状态时，还能蒸馏什么？。 先区分四种信号： logit 是 softmax 前的候选原始分数； 特征 是教师中间层产生的向量； 关系 是样本或层之间的相似结构； 序列 是教师最终生成的一条回答。越靠内部，提供的信息越细，但越要求访问教师模型内部。 层级； 教师信号； 要求； 盲区。 Logit/token； 每类/词表分布； 可访问 logits、词表对齐； API 常不开放全量。 Feature； 隐藏层/注意力； 层映射和维度投影； 架构差异大。 Relation； 样本/层间相似关系； 批内对照； 目标间接。 Sequence； 回答/解释/偏好； 只需生成 API； 只见采样路径。 。 选择方法的输入是可用教师接口、学生架构和要保留的能力，输出是概率、特征、关系或示范数据以及相应学生损失。LLM 常用序列蒸馏：教师为多样提示生成示范，再 SFT/偏好训练学生。它更像行为克隆，无法看到教师对未采样 token 的概率，也容易复制教师文风和冗长。 若学生在示范风格上高度一致却在换措辞后失败，应解释为只复制了采样路径，不是完整迁移教师分布。不同架构还可能没有可直接对应的层，此时强行逐层匹配会限制学生自己的表示方式。

### 3.5.5 学生容量与架构决定可保留上限

教师能做的事情，为什么不能通过足够多示范全部塞进学生？。 学生的参数、层数、上下文、词表和计算深度限制表示与算法。蒸馏数据会让它优先保留高频、易拟合和目标函数权重高的行为；罕见推理、长上下文、校准、对抗鲁棒和工具恢复可能先丢。 若学生容量不足，增加教师样本会进入收益平台，甚至因互相冲突的任务产生干扰。应画能力—参数—延迟前沿，不把“教师全能力复刻”作为默认承诺。 学生在某基准超过教师不等于全面更强。 可能来自正则化、数据更匹配或评测污染。

### 3.5.6 数据覆盖比教师品牌更决定学生偏科

最强教师只在短英文 FAQ 上教学，会得到怎样的学生？。 它会在该分布逼近教师，却不会凭空获得长上下文、多语言、工具、拒答和故障恢复。用真实流量、困难样本、高风险和对抗集构造课程；对教师不确定或验证失败样本保留人工真值，不强制模仿。 按目标切片抽真实/合成提示。 教师多样采样，保留概率/版本/提示。 外部规则、执行器或人工验证。 去重并控制难度与教师风格。 在不含教师近邻的真实集验收。 教师查询有成本，可主动选择学生最不确定、教师可能有增益的样本，而不是均匀浪费。

### 3.5.7 教师错误、偏见和拒答会一并传递

学生更小、更便宜，是否也自然更安全？。 不会。序列示范可能包含幻觉、隐私、偏见或过度拒答；软分布会传递教师偏好。若教师与验证器同源，高通过率可只是共同盲点。敏感任务结合硬标签、独立规则、多教师分歧和人工审查。 还要关注反向影响：学生容量不足可能只学到表面安全措辞而失去条件判断，造成对危险请求漏拒或对正常请求全拒。按风险切片比较教师、学生与真实标签，不用教师一致率代替安全真值。 蒸馏可能洗掉不确定性。 单一教师贪心答案让学生看不到多模态分布，表现得比证据更确定。

### 3.5.8 蒸馏、量化、剪枝和 LoRA 在不同维度压缩

四种方法都说“更小”，它们各改变了什么？。 方法； 改变； 主要收益； 主要损失源。 蒸馏； 训练更小学生行为； 参数/FLOPs； 容量与覆盖。 量化； 数值位宽； 存储/带宽； 舍入/截断。 剪枝； 移除权重/结构； 稀疏/算力； 删去重要连接。 LoRA； 低秩任务增量； 训练状态/切换； 适配容量与干扰。 。 可以先蒸馏再量化学生，但误差会交互：量化可能加剧学生已脆弱切片；蒸馏教师若本身量化，分布已改变。最终组合必须重新端到端评测。

### 3.5.9 部署证据是质量—容量—成本前沿

学生参数少 70%，怎样证明它不是“更便宜但更常失败”？。 同时报告逐 token KL/困惑度、目标任务、长上下文、多语言、工具、安全、校准和分布外切片；系统侧测 TTFT/TPOT、吞吐、显存、能耗、人工接管和每成功任务成本。与同预算强模型路由/量化基线比较。 逐样本检查 teacher-only-correct、student-only-correct、both-wrong；能力损失集中在哪些切片。教师本身错误不能算学生“未模仿失败”。发布后流量漂移需重新蒸馏或路由升级。 可接受压缩： 硬风险门槛通过，目标硬件收益真实，且被牺牲能力明确、可路由或可回退。

### 3.5.10 常见误区与概念依赖

蒸馏是受容量和数据约束的行为迁移，不是完整知识复制。 误区； 更准确的理解。 软标签都是真实知识； 它们包含教师关系，也包含失准和偏见。 温度越高越好； 过高会抹平有用差异，需调参与验证。 序列示范等于完整分布； 只观察被采样路径。 示范足够多可复制全部能力； 学生容量和覆盖决定上限。 小模型天然安全； 安全判断也可能蒸馏失败或表面化。 。 层级； 概念依赖与延伸学习。 先修； softmax、KL、监督学习、模型容量。 本页核心 ； 温度软标签、logit/feature/sequence 蒸馏、课程覆盖。 数据； 合成数据、训练数据治理、后训练。 压缩部署； 量化、LoRA、模型路由与应用评测。 。

### 3.5.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 定义学生需保留的能力切片。 教师产生分布/表示/示范。 独立验证并构造覆盖课程。 学生联合拟合硬标签与教师信号。 比较逐样本能力迁移与丢失。 系统收益/风险联合门禁并保留升级。

### 3.5.12 误区与自测

## 3.6 分布式训练：沿数据、张量、流水线和状态四个轴拆分（distributed-training）

### 3.6.1 权重能放下，不代表训练能放下

一个 7B FP16 模型约 14GB，为何 24GB GPU 仍不能全量 Adam 微调？。 7B 表示约 70 亿个参数，FP16 每个权重通常占 2 bytes，所以只存推理权重约需 14GB。全量训练还需要更高精度主权重、每个参数的梯度，以及 Adam 为每个参数维护的两组历史统计；“激活”则是前向各层为反向传播暂存的中间结果。混合精度粗略每参数可能需要 12–20 bytes 状态，7B 远超单卡；长序列激活也可主导。 内存账的输入是参数量、数值精度、优化器、batch、序列长度和临时缓冲，输出是各类状态的峰值及每卡能否容纳。分片策略分别解决不同对象：数据并行复制模型，ZeRO/FSDP 分片状态，张量并行拆单层，流水线并行拆层，激活检查点用重复计算换较少存储。 “权重能加载”只证明推理主体可放下，不证明反向传播能运行。内存估算还会受实现、碎片和通信缓冲影响，必须用实测峰值留出安全余量。 先做内存账： 权重、梯度、优化器、激活、通信缓冲和碎片逐项估算，再选并行轴。

### 3.6.2 数据并行的语义是同步同一更新

每卡看不同样本，为什么最后参数仍保持一致？。 每个 rank （一个参与训练的进程/设备编号）有完整模型副本，计算不同样本的本地梯度； all-reduce 是让所有 rank 共同求和并把结果发回每一方的集合通信。归约后，各 rank 用相同全局平均梯度更新，所以参数保持同步。 公式：全局批量等于每卡局部批量 b 乘数据并行设备数 n 乘梯度累积步数 a；平均梯度等于各设备梯度之和除以 n。 B全局 是一次参数更新实际使用的样本数， b 是每卡每个微步的局部 batch， n 是数据并行副本数， a 是累计多少个微步才更新。 r 是 rank 编号， gᵣ 是第 r 个 rank 的累计梯度， ḡ 是 all-reduce 后每个副本共同使用的平均梯度。 扩设备但不调 b/a 会增大全局批量，改变梯度噪声、学习率和训练 token 语义；不能把收敛变化归咎于硬件。梯度归约精度和顺序也影响数值。 loss 看似相同不代表实验相同。 数据顺序、随机流、dropout 和归约非结合性会改变轨迹。

### 3.6.3 运行示例：8 卡全局批量与强扩展效率

每卡 4 样本、累积 8 步，8 GPU 的一次优化步看了多少样本？。 图示：八个数据并行 GPU 各做局部微批和梯度累积后通过 all-reduce 同步。 图 1 累积期间不必每个 micro-step 通信；第 8 步同步后才进行一次全局更新。 若单卡处理固定工作耗时 800ms，8 卡同样总工作理想 100ms，实测 140ms，则强扩展效率 800/(8×140)=71.4% 。额外 40ms 来自通信、同步和负载不均。 设备； 同一总工作时间； 加速； 效率。 1； 800ms； 1×； 100%。 8 理想； 100ms； 8×； 100%。 8 实测； 140ms； 5.71×； 71.4%。 。

### 3.6.4 张量并行拆一层，通信发生在层内

单个 4096×16384 MLP 放不下一张卡，怎样沿行列拆？。 张量并行（TP）把同一层矩阵或注意力头分给多张卡共同计算。列并行把输出列分给设备，输入共享，各卡算局部输出；后续行并行可消费局部特征并用 all-reduce 汇总。 collective 是 all-reduce 等多设备共同参与的集合通信；NVLink 是同一服务器内常见的高速 GPU 互连。 输入是同一批激活和被分片的层权重，输出要经过集合通信拼回与单卡计算语义一致的层结果。TP 降低每卡权重与部分激活，却使小 batch、慢链路和跨节点延迟显著。度数太高时局部矩阵太小，GPU 利用率下降。通信/计算需通过算子融合和异步重叠隐藏。 轴； 拆什么； 通信频率； 适合。 数据并行； 样本； 每次梯度同步； 模型单卡可放/状态可分片。 张量并行； 单层矩阵/头； 几乎每层； 单层太大、高速互连。 序列并行； 序列维激活； 与 TP 配合； 长序列激活。 。 每卡内存下降而 tokens/s/GPU 也下降，通常说明通信或局部算子太小抵消了收益；张量并行更适合高速互连域，不应仅为“多用几张卡”跨慢网络扩大。

### 3.6.5 流水线并行拆层，气泡由 micro-batch 填充

4 个阶段、8 个 micro-batch 的理想气泡比例是多少？。 流水线并行把连续模型层分成 p 个阶段；一个大 batch 再拆成 m 个 micro-batch，依次在阶段间前向和反向。“气泡”是某阶段等待数据、没有有效计算的时间。最简单同步 GPipe 调度中，单方向直觉下效率近似 m/(m+p−1)；p=4、m=8 为 8/11≈72.7%，气泡约 27.3%。 公式：理想流水线气泡比例约等于阶段数 p 减一，除以 micro-batch 数 m 加阶段数 p 减一。 f气泡 是理想化空闲时间比例， p 是流水线阶段数， m 是一个批次拆出的 micro-batch 数。式子只描述阶段成本相近的简化调度，不包括通信、前后向差异和交错调度细节。 增加 m 减气泡但增加激活驻留、调度开销和过小 micro-batch 的内核低效；1F1B 表示稳定阶段交替执行一次前向和一次反向，可降低峰值激活。阶段算力不均时最慢 stage 决定节拍，应按层成本而非层数平均切。 流水线状态有版本。 异步或交错调度可能让不同 micro-batch 使用不同权重版本，需要明确一致性语义。

### 3.6.6 ZeRO / FSDP 分片数据并行冗余状态

数据并行每卡都复制 Adam 状态，怎样按 rank 分摊？。 ZeRO 与 FSDP 都让数据并行 rank 不再各自长期保存完整训练状态。ZeRO-1 分片优化器状态，ZeRO-2 再分片梯度，ZeRO-3/FSDP 再分片参数；计算某层前用 all-gather 从各卡收集本层所需参数，反向后用 reduce-scatter 求和梯度并只把不同分片留在各卡。 阶段； 优化器； 梯度； 参数。 普通 DP； 复制； 复制； 复制。 ZeRO-1； 分片； 复制； 复制。 ZeRO-2； 分片； 分片； 复制。 ZeRO-3/FSDP； 分片； 分片； 分片/按需聚合。 。 输入是按 rank 分片的参数与状态，输出仍应等价于一次同步数据并行更新。参数 all-gather 的粒度、预取和重计算需匹配网络与层大小；offload 是把部分状态移到 CPU 内存或 NVMe 存储，能容纳更大模型却可能被搬运带宽限制。 每卡峰值下降而集合通信占比上升，是用通信换内存的预期结果；若恢复检查点或不同 world size 时无法重分片，则部署弹性仍不合格。

### 3.6.7 3D 并行是按拓扑组合，而非随意相乘

64 GPU 怎样分成 DP=8、TP=4、PP=2，通信域如何不同？。 DP、TP、PP 分别表示数据并行、张量并行和流水线并行的度数。总设备 8×4×2=64。TP 组内每层频繁通信，优先放同节点；PP 相邻阶段传激活；DP 组同步梯度或状态，频率相对低但数据量大。专家并行还可能加入 all-to-all，让每个设备同时向多方发送并接收 token。 rank 映射必须拓扑感知，避免 TP 跨慢网。全局 batch 只由 DP 副本、局部 micro-batch 与累积步数决定，不乘 TP/PP；因为 TP/PP 合作处理同一批样本。 公式：全局批量等于局部微批量乘梯度累积步数乘数据并行度，不乘张量并行度或流水线并行度。 B微批 是每个数据并行副本一次处理的样本数， a 是梯度累积步数， N数据并行 是处理不同样本的数据副本数。TP 与 PP 只是共同完成同一副本的模型计算，因此不增加本次更新看过的样本。 输入是设备拓扑、三种并行度和 batch 配置，输出是 rank 分组、通信域与不变的优化器语义。64 GPU 全乘入 batch 会把全局批量算大 8 倍或更多，并错误改变学习率和训练轨迹。

### 3.6.8 检查点与故障恢复是规模化的一部分

训练两周后一个节点故障，怎样保证不是从头再来或恢复出错？。 保存模型、优化器、调度器、随机数、数据游标、损失缩放和并行元数据。分片检查点需支持在不同 world size 重分片或明确限制；写入采用临时产物+原子清单，避免一半 rank 成功的损坏快照。 checkpoint 间隔在写入开销与丢失计算间取舍；大规模故障率随设备数上升。定期执行真实恢复演练，比较恢复后 loss/样本序列，而不只检查文件存在。弹性训练还需处理成员变化的 batch 与随机流。 数据恰好一次语义很难。 恢复可能重复或跳过样本，必须持久化 sampler 状态和全局 step。

### 3.6.9 扩展评测要区分强扩展和弱扩展

GPU 翻倍，应该保持总问题大小还是每卡问题大小？。 强扩展固定总模型与总工作，测增加设备后同一任务加速多少；弱扩展固定每卡工作，让总问题随设备增加，测单位效率能否保持。输入是不同设备数下的同一实验协议，输出是速度、效率、内存、功耗、恢复与最终质量的联合报告。 tokens/s 是集群每秒处理 token 数， tokens/s/GPU 是每卡效率；MFU 是实际有效模型计算相对硬件理论峰值的比例；collective 占比是集合通信占 step 时间的比例。还应报告数据等待、气泡、重计算、显存峰值、功耗和恢复时间。 同时验证训练语义：global batch、学习率、token 数、数据顺序、dropout 随机流、loss scaling 与归约精度。吞吐提高但最终质量下降不是成功扩展。MFU 低也只说明硬件未充分用于模型计算，不能单独判断瓶颈来自数据、通信还是小算子。 瓶颈定位： 用 trace 将一个 step 拆成数据读取、前向、反向、集合通信、优化器和检查点，再把时间占比与等待依赖对应起来；GPU 利用率低只是症状。

### 3.6.10 常见误区与概念依赖

分布式训练的核心是数据与状态语义，而不只是设备数量。 误区； 更准确的理解。 GPU 翻倍速度翻倍； 通信、同步、输入和小矩阵限制效率。 权重放下即可训练； 梯度、优化器、激活和缓冲常更大。 所有 GPU 都乘入全局批量； 只乘数据并行副本，不乘 TP/PP。 ZeRO 只省内存无代价； 按需聚合增加通信与检查点复杂度。 loss 连续即可证明恢复正确； 还需数据游标、随机流和状态一致。 。 层级； 概念依赖与延伸学习。 先修； 反向传播、优化器、集合通信与 GPU 内存。 本页核心 ； DP/TP/PP、ZeRO/FSDP、全局批量、拓扑和恢复。 架构； MoE 专家并行、长上下文、梯度检查点。 规划； 缩放定律、训练数据治理与可观测性。 。

## 3.7 合成数据：生成候选容易，增加有效信息很难（synthetic-data）

### 3.7.1 合成的是样本，不是自动产生新知识

大模型写出一百万条问答，为什么有效信息可能只相当于几千条？。 合成数据 是由模型、程序或模拟器产生，而非直接从目标世界观察并人工记录的训练样本。生成器会复述训练中常见模式，采样之间高度相关；数量不代表独立性、新颖性或正确性。输入是待补的真实失败切片与生成规则，输出可以是输入、标签、推理轨迹、偏好对、代码结果或模拟轨迹。 样本只有覆盖真实缺口并通过独立验证，才可能增加有效信息。退款助手可合成政策边界组合、口语改写和工具错误轨迹，但真实政策事实必须来自权威规则，不能让教师凭记忆创造。模型在合成集上更准也只说明适应了该集，最终要看真实隔离测试。 正确起点： 先从真实失败切片定义缺什么，再选择生成机制；不要先生成海量数据再寻找用途。

### 3.7.2 四种来源拥有不同真值结构

教师模型、程序、伪标签和数据增强为什么不能共用一套信任假设？。 来源； 生成什么； 真值来自； 主要失败。 教师蒸馏； 示范、解释、偏好； 教师能力/外部核验； 传递偏差与风格。 程序/模拟器； 题目、标签、轨迹； 规则、执行、求解器； 模拟与现实差距。 自训练； 未标注输入伪标签； 模型置信/一致性； 确认自身错误。 数据增强； 改写、扰动、变换； 标签应保持不变； 变换偷偷改标签。 。 输入是缺口类型、可用生成器和可获得的真值来源，输出是带来源类型和验证要求的数据管线。程序骨架适合规则明确任务，教师适合语言多样性，自训练依赖模型已有可靠区域，增强则要求变换不改变标签。 最强组合常是程序构造可验证骨架，再让教师增加语言多样性，最后以规则和人工抽样复核。 数据谱系（provenance） 就是记录样本由哪个输入、生成器、版本和验证步骤产生；不同来源必须保留谱系，不能混成“synthetic=true”一个标签，否则出现错误时无法撤回或区分信任强度。

### 3.7.3 生成器、验证器和配比共同定义训练分布

为什么验证通过率很高，保留集仍可能充满简单重复题？。 公式：最终保留样本 x y 的相对密度，正比于生成器产生该样本的密度，乘验证器接受概率，再乘覆盖权重。 x 是合成输入， y 是标签、回答或轨迹； q生成(x,y) 表示生成器多常产生该候选， a(x,y) 是验证器接受它的概率， w(x,y) 是为主题、难度、语言或风险设置的保留权重。符号 ∝ 表示“成比例”：三项相乘后还要对所有保留候选归一化，才得到总和为 1 的最终分布 q保留 。 生成器决定候选能到哪里，验证器决定谁能通过，配比权重决定通过者各保留多少。若验证器只会检查最终金额，错误理由偶然算对也会被接受；若简单题通过率更高，筛选会把分布进一步推向简单。 因此同时报告候选数、接受率、去重后数量、难度与切片覆盖、验证器误差和与真实目标分布的距离。高接受率可能只是生成器迎合了弱验证器。 验证器也是选择器。 它不仅去掉坏样本，还定义哪些风格和解法能存活，必须独立评测。

### 3.7.4 运行示例：10 万候选最后为何只保留 1.2 万

退款边界数据经过规则、去重和覆盖采样，每一步损失与收益是什么？。 图示：十万条合成退款样本经过规则验证、语义去重、覆盖配额和人工抽样形成训练混合。 图 1 漏斗的目标不是最大保留，而是留下可验证、非重复且覆盖目标切片的数据。 阶段； 数量； 相对上一步； 需抽查的问题。 生成； 100k； 100%； 是否真的覆盖缺口。 规则验证； 60k； 60%； 验证器漏错/误拒。 语义去重； 24k； 40%； 是否误删稀有表达。 覆盖采样； 12k； 50%； 真实目标权重与长尾。 。 管线先按资格、金额和证据规则去掉明显错误，再用语义近邻删除重复措辞，最后按语言、难度和风险配额纠正剩余分布。每一步都要抽查误拒和误删，不能把数量减少本身当作质量提升。 总体接受率 12%。若训练混合共 60k 样本，12k 合成占 20%；不能因为候选免费就把比例提高到 90%，真实锚点用于保留语言尾部和外部世界约束。

### 3.7.5 可执行验证强，但只强在写出的断言

代码通过单测、数学答案代入正确，为什么训练样本仍可能有毒？。 执行器能证明特定性质：程序在给定测试通过、方程结果满足、JSON 可解析。它不能证明测试覆盖未写边界、推理过程无错误、需求本身正确或代码无安全漏洞。生成器还会寻找验证器漏洞，形成 reward hacking。 使用多重验证：静态规则 + 执行 + 独立模型/人工；对验证器做 mutation test，故意制造错误看能否拒绝；维护隐藏测试和定期更新，避免生成器过拟合公开断言。高风险数据需要来源证据而非多数模型投票。 同源偏差： 同系列教师和裁判可能共享盲点；“两个模型都同意”不等于独立证据。

### 3.7.6 多样性、难度与真实性必须分别测

embedding 距离看起来很多样，为什么真实用户输入仍可能覆盖不到？。 embedding 距离 是把文本变成向量后测量两段文本在表示空间相隔多远，常用于找语义近邻；距离大只说明当前表示认为它们不同，不保证任务结构或用户群体真的新颖。词面、语义、结构、解法和群体多样性是不同维度；随机高温可增加措辞却不增加任务结构。 输入是合成候选、真实失败分类和目标切片，输出是重复率、难度、覆盖、真假可分性和下游增益等互补指标。按真实失败分类建立覆盖矩阵：语言、政策边界、缺失字段、冲突证据、攻击和工具故障；在每格设置目标量与真实锚点。 指标； 回答； 不能证明。 n-gram/语义重复率； 是否近邻太多； 任务结构新颖。 难度分层； 验证/模型成功分布； 现实相关性。 切片覆盖； 预定义组合是否出现； 未知长尾已覆盖。 真实/合成分类器； 分布可分程度； 哪一边更正确。 下游增益； 训练后任务变化； 无副作用与因果唯一。 。 单项指标高不能互相替代：语义多样不证明现实相关，切片齐全不证明未知长尾覆盖。最终证据来自真实隔离测试和消融：真实基线、加合成、等量真实、打乱标签等对照。

### 3.7.7 模型坍缩取决于替换、累积和筛选方式

模型学习模型输出是否必然一代比一代差？。 若每代用生成样本替换真实数据，生成器欠采样尾部，稀有模式会逐代消失；系统错误和风格被放大。若持续累积原始真实数据、限制合成比例、引入独立验证和多样性配额，退化路径会显著不同，因此不能简化成“合成必崩”或“筛选就安全”。 公式：第 t 代训练分布等于一减 alpha 乘真实数据分布，加 alpha 乘第 t 代合成数据分布。 Dₜ 是第 t 代模型看到的训练分布， D真实 是保留的原始真实数据分布， D合成,t 是第 t 代生成数据分布， α 是合成数据所占比例。这个式子只描述混合权重；真实数据是否跨代累积、生成器漏掉哪些尾部以及验证器误差，都会改变实际反馈强度。 监控尾部覆盖、熵、重复、真实与合成可分性、跨代错误相关和真实留出表现。平均准确率稳定时，少数语言与罕见场景可能已坍缩；只有在真实隔离切片上持续验证，才能区分整体稳定与尾部消失。 来源标签不可丢。 互联网中的模型生成内容若未标识，会使团队误把合成回流当新真实数据。

### 3.7.8 谱系、污染和授权仍适用于合成数据

自己生成的文本是否天然没有版权、隐私或测试污染问题？。 教师可能复述训练内容或个人信息，提示中可能包含受限文档，生成的改写可能与评测题近邻。PII 是可用于识别个人的信息，例如姓名与联系方式；评测污染是训练数据包含测试题或近似答案，使成绩虚高。 治理输入是种子数据、生成器、模板、验证器和混合计划，输出是带稳定 ID、来源谱系、许可和撤回路径的样本。记录生成器快照、提示模板、采样、种子、输入来源、验证器版本、拒绝原因和最终混合。 生成前检查种子数据用途和敏感性。 生成后扫描记忆式片段、PII、恶意内容与评测近邻。 语义去重并保留簇与代表样本。 按来源/难度/群体设上限，防单一教师支配。 隔离真实留出集，禁止其题目和派生答案进入提示。 发现问题可沿谱系撤回数据并定位训练运行。 扫描通过只说明当前规则未发现问题，不是版权、隐私或授权结论。“模型生成”也不是权利结论，具体法律与合同判断需按地区和用途处理。

### 3.7.9 何时值得用，何时应优先收集真实数据

合成数据最适合补哪类缺口，又在哪些任务上最容易自欺？。 适合：规则真值明确、模拟器可靠、可执行验证、隐私安全的边界组合、真实样本极少但结构已知。谨慎：开放世界事实、文化偏好、罕见伤害、真实用户意图和验证器与教师同源的任务。后者应投资真实观察、专家标注与参与式评估。 在小规模试验中比较“加合成”与“等预算真实/人工/工具改进”，按切片看边际收益；若合成只让模型更像教师而真实指标不升，应停止扩量。生成成本便宜不代表筛选、治理和错误成本便宜。 停止条件： 新增批次去重后新颖性、真实留出增益或边际覆盖接近零时，不应继续为数量 KPI 生成。

### 3.7.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 从真实失败定义可量化缺口。 选择带合适真值结构的生成机制。 用独立规则/执行/人工验证。 语义去重并按难度/群体配额。 限制混合比例并保留真实锚点。 在真实隔离集消融并沿谱系迭代。

### 3.7.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 为什么十万候选示例最后只保留 1.2 万？。 q_keep 由哪三部分共同决定？。 执行验证为何不是完整真值？。 合成回流何时易坍缩？。 为何必须保留真实隔离集？。 假设“合成数据：生成候选容易，增加有效信息很难”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 如何为“合成数据：生成候选容易，增加有效信息很难”设计一个最小对照实验，证明观察到的改善来自核心机制，而不是数据、提示、权限或评测口径同时变化？。 。 参考答案 规则验证、语义去重和覆盖配额依次删除错误、重复与过量切片。 生成分布 q_gen、验证接受概率 a 和覆盖/难度权重 w。 只证明写出的测试或约束，可能漏边界、过程错误和现实差距。 生成数据替换真实数据、尾部欠采样、错误同源且缺独立筛选时。 避免生成器/验证器自洽地高分，却偏离真实用户与世界。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。 固定数据、模型版本、提示、权限、预算和评测，只改变一个与核心机制直接相关的因素，并在多个样本与随机种子上重复；同时保存中间状态和失败样本。若差异只在目标因素变化时稳定出现，才支持机制解释，否则应继续排查混杂变量。

## 3.8 量化：把连续参数压到有限格点（quantization）

### 3.8.1 有限位宽为什么会丢信息

把任意浮点数塞进 16 个 INT4 格点，哪些差异必然消失？。 量化 把原本可取很多连续小数的数值，映射到有限个离散格点。INT4 表示每个编码使用 4 bit，因此只有 2⁴=16 种编码；具体是 −8…7、−7…7 还是别的范围，还取决于有符号约定与保留值，不能只看“INT4”猜范围。 一个区间内落在同一格的连续值会变得不可区分，区间外的值被截断；更低位宽减少模型读取的字节，却增大舍入或饱和误差。输入是浮点权重、激活或 KV 缓存，输出是整数编码、尺度元数据和计算时还原的近似值。 量化不是压缩文件后无损解压。推理使用近似权重或激活，误差会沿网络传播；神经网络冗余和合适尺度让许多任务能够容忍，但关键决策边界仍可能翻转。 先问对象： 权重量化省模型带宽；激活量化影响中间算子；KV 量化影响长上下文容量。三者不能用“INT4”一词概括。

### 3.8.2 线性量化的 scale 与 zero-point

浮点范围怎样对应整数范围？。 公式：整数编码 q 等于浮点值 x 除以尺度 s 后舍入，加零点 z，再截断到整数上下限；反量化值 x hat 等于 s 乘 q 减 z。 x 是原浮点值， s 是相邻整数格点代表的浮点步长， round 取最近整数， z 是让某个整数格点对应浮点零的 zero-point。 clip 把超范围结果限制在整数下限 q最小 与上限 q最大 ；最终编码是 q ，反量化近似值是 x̂ ，它通常不再与 x 完全相等。 非对称量化可用完整范围覆盖偏移分布；对称量化通常 z=0、范围围绕零，内核更简单但可能浪费一侧格点。输出误差应解释为范围与步长共同选择的结果，而非仅由位宽决定。 选择； 优势； 代价。 对称； 零点简单、乘加高效； 偏移分布浪费范围。 非对称； 贴合任意 min/max； 零点修正更复杂。 截断极值； 主体格点更细； 异常值饱和。 覆盖全部极值； 不截断； 主体量化粗糙。 。

### 3.8.3 运行示例：四个数怎样落到 INT3 格点

对称 INT3 范围 −4…3，浮点最大绝对值 1.2，量化后误差多大？。 图示：四个浮点权重映射到对称 INT3 格点并反量化。 图 1 s=1.2/3=0.4；舍入造成小误差，超出范围的 1.25 被截断。 x； round(x/.4)； q； x̂=.4q； |误差|。 −1.10； −3； −3； −1.20； .10。 −.35； −1； −1； −.40； .05。 .31； 1； 1； .40； .09。 1.25； 3； 3； 1.20； .05（截断）。 。 若为覆盖 1.25 把 s 调到 .4167，其他格点更粗。真实校准就是在主体误差与极值截断之间选择。

### 3.8.4 粒度越细，误差低但元数据与内核更复杂

为什么整张矩阵一个 scale 常被少数异常通道支配？。 per-tensor 为整张张量共用一个尺度， per-channel 为每个输出通道单独设尺度， group-wise 则把若干连续权重分为一组。细粒度让每组适配自己的范围，通常减少误差，代价是更多 scale、索引和专用内核开销。 元数据账： 4096×4096 权重使用 per-tensor 时只有 1 个 scale；per-channel 有 4096 个；若每 128 个权重一组，约有 131072 个 scale。 输入是权重矩阵、分组轴和组大小，输出是各组整数编码与尺度元数据。scale 元数据相对权重通常仍小，但反量化和布局决定速度。不同库的 group size、轴和打包格式不同，模型文件“4-bit”不可直接横比。 粒度更细而误差更低，不代表目标硬件更快；若内核不支持该布局，元数据读取和反量化可能抵消收益。

### 3.8.5 异常值决定范围，也可能决定能力

少量大激活为什么让大多数普通值挤在零附近？。 统一 scale 为覆盖极值而变大，主体值会挤入少数格点。LLM.int8 把检测出的异常通道留在较高精度；SmoothQuant 把一部分激活尺度迁移到权重；GPTQ 用近似曲率衡量不同权重误差对层输出的影响，AWQ 则用真实激活识别更重要的权重。它们分别处理异常通道、权重激活平衡和权重重要性，优化目标并不相同。 输入是待量化层与代表性校准激活，输出是范围、保留高精度通道或经过补偿的权重。盲目剪裁异常值可能伤害稀有 token、长上下文或特定语言，因为“异常”可能承载重要特征。校准集必须覆盖真实长度、领域和难例，不能只用短英文百科。 平均误差小不代表行为安全。 少数关键 logits 排序翻转即可改变工具动作或拒答。

### 3.8.6 PTQ、QAT 与量化基座训练

什么时候只用校准数据，什么时候需要重新训练？。 PTQ （训练后量化）在模型训练完成后估计尺度和补偿； QAT （量化感知训练）在训练前向中模拟舍入与截断，让权重适应误差； QLoRA 保持低位基座冻结，只训练高精度低秩适配器。三者的输出分别是量化模型、适应量化误差的新模型和可挂载适配器，不应混成同一产物。 方法； 做法； 成本； 适合。 PTQ； 训练后估尺度/补偿； 低； 权重 8/4 bit 起点。 QAT； 训练中模拟量化； 高； 低位宽/激活敏感。 QLoRA； 低位冻结基座+高精 LoRA； 中； 节省微调显存。 。 PTQ 不等于零数据：需要代表性校准或逐层优化。QAT 能适应误差但会引入训练数据与过拟合问题。QLoRA 训练时反量化基座参与计算，最终部署是否合并和重新量化要另做评测。应先从低成本 PTQ 基线开始，只有关键切片无法达标时再承担训练成本。

### 3.8.7 省显存不保证更快

INT4 文件只有 FP16 四分之一，为什么端到端吞吐可能不升？。 量化要在目标 GPU 或 CPU 上有匹配的打包格式、低位矩阵乘和融合内核；否则每步反量化、格式转换、kernel launch（启动一个计算内核的固定开销）或小 batch 会抵消带宽收益。权重下降也不等于 KV、激活和框架开销下降。 prefill 是一次处理整段输入提示，常更偏计算受限；decode 是逐 token 生成，常更偏权重读取带宽受限。输入是目标硬件、batch、提示与输出长度以及量化产物，输出应包括首 token 延迟、每 token 延迟、吞吐、峰值显存、功耗和加载时间。 SLO 是服务承诺的延迟、可用性等目标。“能装进显存”只通过容量门，不等于延迟满足 SLO。CPU offload 把部分状态移到主机内存，虽能运行，PCIe 搬运仍可能让交互不可用。

### 3.8.8 量化误差会与后续优化叠加

量化模型再做推测解码、LoRA 合并或 KV 压缩，能把单项测试相加吗？。 不能。草稿/目标量化会改变接受率；LoRA 合并后权重范围变化，旧 scale 可能失效；KV 量化与长上下文注意力误差耦合；张量并行的量化布局影响通信。应按真实最终产物重新量化或校准，并端到端消融。 保留配方：基座哈希、权重/激活/KV 位宽、对称性、粒度、group size、校准集、算法、计算 dtype、内核和硬件。否则“同为 INT4”无法复现。 不可把压缩损失用更多重试隐藏。 重试可能提高最终成功却增加成本、延迟和选择偏差。

### 3.8.9 评测要抓排序翻转和长尾退化

平均困惑度只升 0.2%，为什么工具调用和安全仍可能明显变差？。 输出由局部 logits 排序决定，小误差在接近决策边界时会翻转 token。按通用能力、目标任务、稀有 token、语言、长上下文、结构化输出、校准、拒答和对抗切片比较逐样本差异。 系统指标中，TTFT 是从请求到首 token 的时间，TPOT 是生成阶段平均每个后续 token 的时间；p50、p95、p99 是分别有 50%、95%、99% 请求不超过的延迟分位数。输入必须保持相同提示、采样、内核和负载，输出量化前后质量差、延迟区间、吞吐、显存、能耗与每成功任务成本。 平均困惑度小幅变化只表示整体 token 预测接近，不能排除少数关键动作排序翻转。保存逐样本失败并查看哪些切片退化，才能区分随机波动和系统性长尾损伤。 发布门槛： 只有硬风险切片不退化、系统收益在目标硬件成立，量化配置才是可行方案。

### 3.8.10 常见误区与概念依赖

量化是一套数值表示与硬件共同设计，不是把文件后缀改成 INT4。 误区； 更准确的理解。 位宽越低一定越快； 取决于内核、硬件、batch 和瓶颈。 INT4 是完整配置； 还需对象、粒度、算法、校准和计算 dtype。 PTQ 不需要数据； 通常需代表性校准/优化数据。 平均误差小即可； 关键 logits 排序和长尾行为可能翻转。 权重缩四倍总显存也缩四倍； KV、激活、工作区和框架不同比缩放。 。 层级； 概念依赖与延伸学习。 先修； 线性代数、数值精度、神经网络与推理瓶颈。 本页核心 ； scale/zero-point、粒度、异常值、PTQ/QAT、硬件内核。 组合； LoRA/QLoRA、蒸馏、推理优化、KV cache。 部署； 模型选型、应用评测与可观测性。 。

### 3.8.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 确定量化对象与目标硬件。 用代表性数据选择范围/粒度。 PTQ 或 QAT 生成候选。 检查误差与关键 logits 翻转。 目标负载测显存/延迟/吞吐。 质量风险和每成功任务成本联合门禁。

### 3.8.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 示例中 scale 为什么是 .4？。 per-channel 为何通常误差更低？。 PTQ 是否完全不需数据？。 INT4 为何可能不快？。 为什么要测逐样本排序翻转？。 假设“量化：把连续参数压到有限格点”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 。 参考答案 对称 INT3 正上限为 3，最大绝对值 1.2，所以 s=1.2/3。 每通道可用独立范围，不被其他通道异常值支配。 通常仍需代表性校准或逐层优化数据。 缺低位内核、反量化/转换开销或当前瓶颈不在权重带宽。 小数值误差可能改变关键 token、工具动作或安全决策。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。

## 3.9 混合专家 MoE：让每个 token 只激活少数前馈网络（moe）

### 3.9.1 总参数大，不等于每个 token 全部计算

一个有 8 个专家的模型，为什么 token “退款”可能只经过其中 2 个？。 混合专家（MoE） 把 Transformer 中每个 token 都会经过的前馈网络 FFN，替换为多个可选 FFN“专家”。路由器读取当前 token 的上下文向量，只选分数最高的一个或两个专家执行；这就是 top-1 或 top-2。未选专家本次不计算，但注意力、嵌入、归一化和其他共享层仍为稠密计算。 输入是每个 token 的上下文表示，输出仍是与原 FFN 相同维度的更新表示。报告要区分 total parameters（模型存储的所有参数）、active parameters per token（该 token 实际经过的共享层和专家参数）与 FLOPs（执行的浮点运算次数）。总参数增加存储、加载和训练状态；激活参数更接近单 token 计算，但不包含路由与通信。 总参数大说明可供条件选择的容量多，不表示每个 token 调用了全部能力，也不保证墙钟速度更快。 MoE 的交换： 用参数容量与通信复杂度换取条件计算，不是把一万亿参数“免费”变成稠密一万亿能力。

### 3.9.2 路由器如何选择并组合专家

top-2 路由时两个专家输出怎样合成？。 公式：路由概率 g 等于 softmax 对路由权重 W r 乘 token 向量 x；集合 S 是概率最高的 k 个专家；输出 y 等于集合 S 内各专家输出按重新归一化权重加权求和。 x 是当前 token 的上下文向量， Wᵣ 是路由器权重，softmax 输出每个专家的概率向量 g 。 k 是选几个专家， S 是概率最高的 k 个专家编号集合， e 是其中一个专家。 Eₑ(x) 是专家 e 的 FFN 输出， ĝₑ 是只在已选集合 S 内重新归一化后的权重， y 是加权合成的最终专家输出。 top-1 计算和通信少但单一路径脆弱；top-2 增加冗余与表达，专家分支成本也近似翻倍。硬 top-k 是离散选择，未选专家收不到当前 token 的任务梯度，因此训练还需可微路由分数和均衡目标。 有的架构使用 shared expert 加 routed experts，使通用模式总有共享路径；细节因实现而异，不能只看“MoE”标签。

### 3.9.3 运行示例：6 个 token 的 top-2 分发

4 个专家、6 个 token、每 token 选 2 个，容量因子 1.0 时每专家能接多少？。 图示：六个 token 通过 top-2 路由分发到四个专家并显示专家一过载。 图 1 平均负载为 12/4=3，因此 CF=1 的容量是 3；E1 的 5 路中有 2 路必须处理溢出。 公式：每个专家容量等于向上取整容量因子 c 乘 token 数 N 乘每 token 专家数 k，再除以专家总数 E；示例结果为三。 C 是单个专家在这一批最多接收的路由数， ceil 表示向上取整； c 是容量因子， N 是 token 数， k 是每个 token 选择的专家数， E 是专家总数。容量按平均路由数乘安全系数分配，因此热点专家仍可能溢出。 策略； E1 溢出处理； 质量； 资源。 drop； 丢 2 路； 可能伤 token 表示； 固定。 second/backup； 转其他专家； 可恢复但语义变； 通信增加。 CF=2； 容量 6； 少丢弃； 缓冲与最坏计算增。 。

### 3.9.4 为什么路由会坍缩到少数专家

如果 E1 早期稍强，后续为什么可能越来越热门？。 更多 token 进入 E1→E1 获得更多任务梯度→表现更好→路由器更偏 E1，形成正反馈；其他专家几乎收不到样本和梯度，这叫专家饥饿。输入是路由概率和实际分配，输出要同时优化任务质量与专家负载。 辅助损失惩罚“少数专家概率或实际 token 占比过高”；路由噪声在训练时增加探索；z-loss 约束路由 logits 不要无限变大，以免 softmax 过尖和数值不稳；专家容量则限制单个专家最多接收多少路由。 均衡过强会把本应进入专业专家的 token 硬摊开，损害语义路由。应同时看任务 loss、专家熵、每专家 token、溢出率和质量，而非追求绝对均匀。负载均匀只是计算分配信号，不能证明不同语言或群体获得同等质量。

### 3.9.5 all-to-all 让通信成为第一等成本

专家分散在 GPU 上，token 怎样到达被选专家再返回？。 每个设备先按目的专家打包 token，all-to-all 交换到持有专家的设备，专家计算后再 all-to-all 返回原顺序。小批量、路由偏斜、跨节点链路和不均匀消息使网络难以饱和。 瓶颈； 表象； 缓解。 专家热点； 部分 GPU 等待/溢出； 均衡、复制热门专家。 跨节点带宽； all-to-all 占比高； 拓扑感知放置/分组路由。 小消息； 延迟主导； 增大 token batch/融合。 长尾序列； 动态批不均； 容量和调度策略。 。 每 token FLOPs 下降不保证墙钟延迟下降；MoE 特别依赖高速互连与批量。

### 3.9.6 训练与推理的热点分布可能不同

训练时均衡良好，生产为何仍可能某专家爆满？。 训练混合语言/领域和 batch 大，推理流量可能突然集中某主题，且 batch 小、逐 token 生成会让路由分布更尖。专家并行还需将所有专家权重驻留或分层加载，总参数影响显存和启动。 推理监控每层/专家负载、路由熵、溢出、all-to-all 时间、批量和切片质量；对峰值主题压测。可做 expert parallel + tensor/data parallel 组合，但拓扑和故障恢复更复杂。 稀疏计算不等于稀疏存储。 未激活专家当次不算，但通常仍需驻留或可快速访问。

### 3.9.7 专家“专业名称”需要因果证据

某专家常接代码 token，就能叫“代码专家”吗？。 路由可能按词频、位置、标点、语言或计算平衡分工；少量高频 token 例子容易拟人化。互信息在这里衡量“知道 token 属于某切片后，能多大程度预测专家编号”，它能发现统计关联，但仍不能证明因果。 验证输入是路由日志和能力切片，输出是关联统计及交换、屏蔽专家后的能力变化。只有移除或交换某专家后代码能力选择性下降，且其他混杂因素受控，才有更强的“代码相关功能”证据；同一专家在不同层含义也可能不同。 专家并非独立模块：共享注意力先混合上下文，多个层的路由共同形成行为。不能据某层专家标签推断整条回答为何生成，更不能把它当权限边界。路由日志显示“用了谁”，不等于证明“因为这个语义理由”。

### 3.9.8 MoE 与应用模型路由和多智能体不同

它们都叫 routing，决策粒度有何不同？。 机制； 选择单位； 候选； 主要目标。 MoE； 每层每 token； 模型内部 FFN 专家； 参数容量/稀疏计算。 模型路由； 每请求/阶段； 完整模型或服务； 质量约束下成本。 多智能体； 子任务； 角色/工具/上下文； 分工、并行、隔离。 。 应用路由可观测并由产品规则控制；MoE 路由是模型内部学得参数。两者可叠加，评测需区分到底哪一层造成错误或延迟。

### 3.9.9 评测要同时看容量、质量与系统效率

总参数翻 8 倍、激活 FLOPs近似不变，如何判断这次扩展值得？。 输入是 MoE 与相同激活 FLOPs 的稠密基线，以及同一任务、硬件、网络和批量。质量侧比较验证损失、任务、语言、安全、校准与稳定性；系统侧测 tokens/s、TTFT、TPOT、显存、all-to-all 占比、溢出、功耗和恢复。 专家负载 CV 是各专家负载标准差除以平均值，零表示完全均匀，越大表示相对偏斜越强；但 CV 低不等于语义路由或群体质量更好。做专家消融和路由扰动，检查少数专家故障是否让能力崩溃，并按训练与生产分布比较热点。 输出报告必须列出 total 与 active parameters、top-k、容量因子和并行拓扑，避免参数数字误导。只有目标网络和批量上质量—成本前沿可复现改善，且没有靠丢 token 或少数切片退化换吞吐，才算值得。

### 3.9.10 常见误区与概念依赖

MoE 是条件计算系统，瓶颈从矩阵乘转移到路由、容量和网络。 误区； 更准确的理解。 每 token 使用全部总参数； 只激活共享层与 top-k 专家。 激活 FLOPs 少就一定快； all-to-all、热点和小批量可能主导。 负载越均匀质量越好； 过强均衡会破坏专业路由。 专家编号天然对应领域； 需统计与消融，分工可能按频率/位置。 MoE 等于应用模型路由； 前者每 token 选内部专家，后者每请求选完整模型。 。 层级； 概念依赖与延伸学习。 先修； Transformer FFN、softmax、稀疏计算。 本页核心 ； top-k router、capacity factor、均衡损失、all-to-all。 系统； 分布式训练、推理优化、部署。 对比； 模型路由、多智能体、可解释性与缩放定律。 。

### 3.9.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 token 表示进入路由器。 选择 top-k 并分配容量。 all-to-all 发送至专家。 专家并行计算并加权返回。 均衡/溢出控制热点。 质量、通信、容量和切片联合验收。

### 3.9.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 6 token、top-2、4专家、CF=1 的容量是多少？。 E1 收到5路时发生什么？。 总参数与激活参数差什么？。 MoE 主要集合通信是什么？。 为何不能直接给专家命名领域？。 假设“混合专家 MoE：让每个 token 只激活少数前馈网络”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 如何为“混合专家 MoE：让每个 token 只激活少数前馈网络”设计一个最小对照实验，证明观察到的改善来自核心机制，而不是数据、提示、权限或评测口径同时变化？。 为什么不能只用一个平均分判断“混合专家 MoE：让每个 token 只激活少数前馈网络”已经可靠？应怎样按场景切片并设置失败边界？。 。 参考答案 ceil(6×2/4)=3 路/专家。 2路需丢弃、重路由或提高容量。 总参数包含所有专家，激活参数只含当前 token 的共享层和 top-k 专家。 将 token 发往专家并返回的 all-to-all。 路由可能按其他统计分工，需干预和消融证据。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。 固定数据、模型版本、提示、权限、预算和评测，只改变一个与核心机制直接相关的因素，并在多个样本与随机种子上重复；同时保存中间状态和失败样本。若差异只在目标因素变化时稳定出现，才支持机制解释，否则应继续排查混杂变量。 平均分会隐藏少数类别、极端输入、成本、延迟和安全失败。至少按难度、输入类型、长度或规模、风险等级及已知边界切片，同时报告质量、资源和失败率；高风险硬约束不能被其他切片的高分抵消。

## 3.10 模型合并：在共享坐标系里组合权重增量（model-merging）

### 3.10.1 权重平均为何偶尔有效、偶尔彻底崩坏

两个都能工作的模型取均值，为什么中间模型不一定能工作？。 模型合并 直接对两个或多个模型检查点的参数做运算，产生一个新检查点，而不再用联合数据训练。输入是源模型权重与合并配方，输出是必须重新评测的新模型。 神经网络函数对参数是非线性的：参数各减半不等于功能各保留一半。“低损失连通区域”可直观理解为两个参数点之间存在一条路径，沿途模型损失都不高；若源检查点来自同一初始化附近，平均可能位于这类区域并平滑噪声。独立训练则可能让隐藏单元排列和表示基底不同，同一坐标不代表同一特征，平均会把功能抵消。 因此先确认共同基座、架构、词表、tokenizer、位置编码、归一化和参数命名。形状相同只表示数组能相加，不表示数组中同一位置承担相同功能。 合并前提： 先证明参数在可比较坐标系，再讨论加权公式；否则数字能相加但语义不能。

### 3.10.2 检查点平均与模型汤

同一训练轨迹或同一基座微调，怎样做最简单组合？。 公式：合并参数 theta merge 等于所有源模型参数 theta i 按系数 alpha i 加权求和，且全部系数之和等于一。 θᵢ 是第 i 个源检查点的完整参数， αᵢ 是它的合并权重，所有权重和为 1 时得到加权平均， θ合并 是新模型参数。公式只保证每个坐标完成算术平均，不保证源坐标功能对齐，也不保证平均后损失低。 SWA 是对同一次训练后期多个检查点做简单平均；EMA 是让近期检查点拥有更高指数衰减权重。模型汤则平均从同一预训练初始化出发、以不同超参数微调得到的多个模型。uniform soup 全部等权，greedy soup 只逐个加入能改善验证集的候选。 输入是兼容检查点、系数和验证集，输出是加权检查点及其泛化评测。它们主要整合相近任务或数据的解，不是任意能力拼装；greedy 选择过多查看同一验证集还会造成验证集过拟合。 方法； 源模型关系； 目标； 主要风险。 轨迹平均； 同一次训练不同步； 平滑解； 跨越坏区域。 模型汤； 同基座同任务超参； 泛化/鲁棒； 验证集过拟合。 线性插值； 两个兼容检查点； 折中能力； 中点损失障碍。 任务算术； 同基座不同任务； 组合增量； 任务冲突。 。

### 3.10.3 任务向量把共同基座消掉

为什么先减同一基座比直接平均两个微调模型更可解释？。 公式：第 i 个任务向量 delta i 等于任务模型参数 theta i 减共同基座参数 theta base；合并参数等于共同基座加各任务向量按 alpha i 加权求和。 θ基座 是所有任务微调共同出发的精确检查点， θᵢ 是第 i 个任务模型，二者逐坐标相减得到任务增量 Δᵢ 。 αᵢ 控制第 i 个增量加入多强，最后再把加权增量加回共同基座得到 θ合并 。 任务向量使比较聚焦“微调改变了什么”，而不是重复平均共同基座。若更新在同一坐标方向相反，会抵消；若都很大且同向，叠加可能过冲。负系数有时被用来尝试削弱某方向，但不是可验证删除某项知识的保证。 任务向量不是独立语义模块：同一参数参与多个能力，线性组合会产生交叉干扰和分布外行为。系数需在独立验证集搜索并限制范围。 减基座要求精确相同。 不同 revision、量化、词表扩展或再训练基座产生的 Δ 没有统一原点。

### 3.10.4 运行示例：两个三维任务向量怎样冲突

退款任务 ΔR=[.6,−.4,.1]，安全任务 ΔS=[−.5,.3,.2]，直接相加留下什么？。 图示：两个三维任务向量在前两维符号冲突并经冲突处理后合并。 图 1 坐标抵消并不表示任务冲突已“解决”；可能只是两种有用更新都被删除。 维度； ΔR； ΔS； 和； 诊断。 1； +.6； −.5； +.1； 强冲突。 2； −.4； +.3； −.1； 强冲突。 3； +.1； +.2； +.3； 同向增强/可能过冲。 。 真实模型有数十亿维，单坐标大小也不直接对应功能重要性；示例只解释为何符号与尺度干扰需要处理。

### 3.10.5 置换对称让独立模型坐标不对齐

两个两层网络交换隐藏神经元顺序，函数不变，权重坐标发生什么？。 若同时交换前一层输出行和后一层输入列，网络函数可完全相同，但参数向量不同。这叫置换对称：神经元编号变了，组合功能没变。独立训练会选不同排列或表示基底，直接平均就可能把一个模型的“特征 A”与另一个的“特征 B”混合。 输入是两个源模型的权重或同一校准输入下的激活，输出是神经元、通道或注意力头的对应关系。weight matching 按权重相似寻找排列，激活匹配按响应相似配对，permutation alignment 再按配对重排坐标。即便局部对齐，也不保证两模型之间的参数路径保持低损失。 余弦相似衡量两个参数向量夹角是否接近，但大量普通坐标可掩盖少数关键层不对齐。高相似只能作为筛查信号，最终仍需插值路径损失和任务评测。

### 3.10.6 TIES、DARE 等处理的是经验冲突

更新密集且符号冲突时，剪枝和随机丢弃为何可能帮助？。 TIES 通常先剪除小幅更新，再按聚合符号解决冲突，最后只合并与主符号一致的值；DARE 随机丢弃任务向量元素并重标度，减少密集干扰。它们假设许多增量冗余或噪声。 步骤； 希望解决； 可能伤害。 剪小更新； 去噪/稀疏； 许多小值合成重要功能。 统一符号； 防相互抵消； 少数任务必要反向更新。 随机丢弃+重标； 减少干扰； 方差与不可复现。 层级系数； 细调能力； 搜索空间过大。 。 这些都不是解析保证。阈值、密度、随机种子和系数必须进入配方与验证。

### 3.10.7 LoRA/适配器组合与全权重合并不同

多个 LoRA 线性相加是否天然等于多任务模型？。 共享精确基座时可组合 ΔWᵢ=(αᵢ/rᵢ)BᵢAᵢ，或先合并每个适配器再处理任务向量。不同 rank/scale 和目标模块导致大小不可直接比较；适配器也会在同一层冲突。 保持分离并路由，可按请求选择能力且易回滚；合并减少推理分支但固定干扰。并行激活、多适配器加权与融合均需端到端评测。不要把路由（选择一个）和合并（同时改变权重）混为一谈。 先解量化再运算。 对打包整数坐标直接平均通常没有正确浮点语义；合并后需重新校准量化。

### 3.10.8 兼容性清单是硬门槛

哪些元数据不一致时应该直接停止，而不是“先试试”？。 架构、层数、隐藏维度和参数命名一致。 tokenizer、词表大小/顺序、特殊 token 一致。 位置编码、归一化、chat template 一致。 精确共同基座与 revision 可验证。 权重 dtype/量化恢复方式明确。 许可允许产生与分发合并产物。 保存源模型哈希、基座、系数、层级规则、剪枝阈值、随机种子、代码版本和结果哈希。合并是新的模型发布，不应沿用任一源模型名称/安全声明。 词表同大小仍可能错序。 token id 语义不同会直接破坏嵌入与输出头。

### 3.10.9 评测要寻找能力干扰而不只看各自基准

退款与安全基准都维持，为什么组合提示仍可能失败？。 输入是源模型、合并候选和独立的单任务、交叉组合、冲突指令、通用、长上下文、工具与安全测试。输出不仅有每项分数，还应保存逐样本能力迁移、硬风险结果、系统成本和可回滚配方。 比较源模型、简单平均、任务向量、冲突方法、联合微调和路由基线；按系数画帕累托前沿，即无法在不牺牲另一项指标时继续改善某项的候选边界。单任务分数都维持而组合提示失败，表示能力交互没有被单项评测覆盖。 检查插值路径损失：若从 θA 到 θB 的中间模型出现高损失峰值，直接平均风险大。逐层或模块消融可定位干扰。不能用两个平均分掩盖同一高风险样本从安全变不安全。 成功定义： 合并产物在目标组合上提供真实质量/成本收益，硬风险不退化，并有可复现配方与回滚。

### 3.10.10 常见误区与概念依赖

模型合并是坐标兼容性和经验评测问题，不是“文件相加就继承能力”。 误区； 更准确的理解。 两个好模型平均仍好； 需参数对齐和低损失连通。 形状相同就兼容； 词表、语义坐标和基座也需一致。 冲突抵消是自动折中； 可能让两项能力同时丢失。 TIES/DARE 保证组合成功； 是经验启发式，需超参搜索和评测。 合并源模型安全声明可继承； 合并产物是新模型，行为需重新验证。 。 层级； 概念依赖与延伸学习。 先修； 参数空间、微调、线性代数和神经元置换。 本页核心 ； 权重平均、任务向量、对齐、符号冲突、系数搜索。 组合； LoRA/适配器、量化、模型路由。 验证； 模型评测、数据治理、部署与安全回归。 。

### 3.10.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 验证共同基座与参数语义。 计算权重/任务增量。 诊断置换、尺度与符号冲突。 搜索合并方法和系数。 源任务/交叉/基础/安全联合回归。 保存配方与新模型发布/回滚。

### 3.10.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 为什么独立训练模型难直接平均？。 任务向量是什么？。 示例直接相加结果是什么？。 TIES/DARE 是否提供保证？。 合并后为何要重新安全评测？。 假设“模型合并：在共享坐标系里组合权重增量”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 如何为“模型合并：在共享坐标系里组合权重增量”设计一个最小对照实验，证明观察到的改善来自核心机制，而不是数据、提示、权限或评测口径同时变化？。 。 参考答案 隐藏单元排列、表示基底和参数盆地可能不对齐。 某任务微调权重减去精确共同基座。 [.1,−.1,.3]，前两维因反向更新几乎抵消。 不提供，是处理密集/冲突增量的经验方法。 非线性交互可改变拒答和组合行为，源声明不能继承。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。 固定数据、模型版本、提示、权限、预算和评测，只改变一个与核心机制直接相关的因素，并在多个样本与随机种子上重复；同时保存中间状态和失败样本。若差异只在目标因素变化时稳定出现，才支持机制解释，否则应继续排查混杂变量。

## 3.11 缩放定律：用幂律规划参数、数据与算力（scaling-law）

### 3.11.1 缩放定律描述的是可约损失

曲线为什么不断下降，却不会自动降到零？。 缩放定律 是在固定模型族、数据与训练配方附近，用经验曲线描述“资源增加时验证损失怎样变化”。它不是由物理定律推导出的常数，而是对一组训练实验的统计拟合。 公式：规模 x 下的损失 L 等于不可约下限 L 无穷，加常数 A 乘 x 的负 alpha 次方。 L(x) 是规模为 x 时测得的目标损失，x 可以是参数数 N、训练 token 数 D 或计算量 C。 L∞ 是在当前任务、数据和模型族中单靠继续扩大 x 难以消除的下限； A 决定可约部分在参考尺度上的大小， α 是正的缩放指数。因为 x 位于负指数上，x 增大时 A·x⁻ᵅ 会下降，但逐次增加相同倍数只能按固定比例减少剩余可约损失。 输入是多个规模点及其同口径验证结果，输出是拟合参数与带不确定性的附近规模预测。先问纵轴是训练损失、验证交叉熵还是能力分数；不同指标不能直接共用一条曲线。

### 3.11.2 为什么 log-log 图上会出现直线

幂律的指数如何从图上读出来？。 对数把乘法变成加法，也把幂指数变成系数。先从总损失减去下限，只保留可约损失，再对两边取相同底数的对数：。 公式：损失减下限的对数，等于 A 的对数减 alpha 乘规模 x 的对数。 log 是对数函数；只要横纵轴使用同一对数底，斜率结论不变。横轴是 log x ，纵轴是 log(L−L∞) ，直线斜率为 −α ，截距为 log A 。若 L∞ 估错，纵轴就不是正确的可约损失，图会弯曲并误估指数。 图示：普通坐标中的递减曲线与对数坐标中的直线。 图 1 同一幂律在两种坐标系中的形状；只有减去 L∞ 后，log-log 线性关系才严格对应公式。 实际输入是多个 x 与损失点，输出是斜率、截距、下限估计和置信区间。点只在有限区间近似成直线时，不能把它无限外推。

### 3.11.3 数值例子：十倍资源只减少约五分之一可约损失

若 α=0.10，把计算量扩大十倍能得到多少改善？。 公式：十倍计算后可约损失与原可约损失之比，等于十的负零点一次方，约为零点七九四。 R=L−L∞ 是可约损失， R₁ 和 R₂ 分别是扩算力前后剩余的可约部分， C 是原计算量，指数 −0.10 来自假设的 α=0.10。比值 0.794 表示剩余 79.4%，所以本轮只减少 20.6%，不是损失变为原来的十分之一。 若 L∞=1.50、当前 L=2.00，则 R=0.50，十倍算力后的预测是 1.50+0.50×0.794≈ 1.897 ，并不是 1.59。再扩大十倍，仍只是把当时剩余的可约部分乘以 0.794。 计算倍数； 可约损失比例； 若 L∞=1.50、起点 L=2.00。 1×； 1.000； 2.000。 10×； 0.794； 1.897。 100×； 0.631； 1.816。 。 这个结果只是在 α 与 L∞ 估计可信、且十倍规模仍处于拟合区间时的外推，不是实际训练保证。

### 3.11.4 固定算力迫使参数与数据互相权衡

模型做大以后，为什么可训练 token 会变少？。 对稠密 Transformer，一次 token 的前向加反向计算大致与参数量成正比，因此预训练总浮点运算数常粗略写成：。 公式：训练计算量 C 约等于六乘模型参数量 N 乘训练 token 数 D。 C 是训练总 FLOPs，FLOPs 指执行的浮点运算次数； N 是模型参数数量， D 是训练中处理的 token 总数。系数 6 是常见稠密 Transformer 前向与反向成本的粗略近似，不是所有架构的固定常数。 预算 C 固定时，N 翻倍，D 就约减半。参数太少会容量不足；参数太多却只见少量 token，会训练不足。计算最优点是两类瓶颈的经验平衡，不是“把参数堆到最大”。 同一预算下的方案； 参数 N； token D； 典型风险。 A：偏小模型； 1×； 8×； 容量瓶颈。 B：平衡点； 2×； 4×； 需实验确认。 C：偏大模型； 4×； 2×； 数据不足、推理昂贵。 。 输入是计算预算与候选 N、D，输出是等计算实验前沿。注意力长度、稀疏结构、重计算和硬件利用率都会改变实际墙钟成本，所以 FLOPs 相同也不保证时间或质量相同。

### 3.11.5 Kaplan 与 Chinchilla 不是互相矛盾的口号

为什么早期结论偏向更大模型，后来研究又强调更多数据？。 两项研究使用的模型范围、训练点、拟合方法与约束不同。Kaplan 等人的实验支持平滑幂律，并给出较偏向增大参数的预算分配；Chinchilla 用更多规模点联合拟合后指出，许多大模型训练 token 不足，固定计算下应同步增加参数与数据。 真正可迁移的方法是：用当前架构、数据与优化器做一组小规模等计算实验，拟合自己的前沿，而不是把“每参数多少 token”当成永恒常数。 经验指数会漂移。 模型族、tokenizer、数据过滤和上下文长度改变后，应重新测量；跨论文直接抄指数可能比不拟合更危险。

### 3.11.6 名义 token 不等于有效数据

一万亿个重复、污染或低质量 token，是否等价于一万亿个新信息 token？。 重复内容的边际信息低，错误内容可能教会错误规律，评测污染会制造虚假能力。过滤与去重提高单 token 价值，却也可能缩窄覆盖面、放大语言或群体偏差。数据混合比例变化会让同一 D 对应不同“有效数据量”。 变化； 可能收益； 必须监控。 去重； 减少记忆与浪费； 稀有样本是否误删。 质量过滤； 提高平均信号； 领域/语言覆盖偏移。 重复多轮； 榨取有限数据； 过拟合与记忆。 合成数据； 补足目标技能； 模型坍缩和错误回流。 。

### 3.11.7 损失平滑下降，能力分数仍可能跳变

“涌现”一定意味着模型内部突然出现了全新机制吗？。 交叉熵是连续平均量，而准确率、pass@1 或“全部步骤正确”带有阈值。模型对正确答案的概率从 0.45 升到 0.55，损失连续改善，但 argmax 准确率会突然从错变对；样本混合也会制造台阶。反过来，平均损失变好不保证事实性、安全性或罕见能力同步改善。 因此应同时画连续指标、离散指标和分组结果，并在阈值附近增加规模点。所谓涌现可以是真实机制变化，也可能是测量方式的产物；仅凭一条离散曲线无法区分。

### 3.11.8 训练最优不一定是产品全生命周期最优

为什么多训练一个较小模型，反而可能让总成本更低？。 若服务海量请求，模型每次推理的显存、延迟和能耗会重复支付。一个参数较少、训练 token 更多的模型，预训练可能更贵，却可能在生命周期中更便宜。反之，一次性研究模型的推理量很小，训练前沿可能更重要。 公式：全生命周期总成本等于一次训练成本，加请求总数乘单次推理成本，再加运维与失败成本。 K总 是规划期内全部成本， K训练 是一次性训练与实验成本， N请求 是预计请求数量， K单次推理 包含每次服务的硬件、能耗和延迟代价， K运维与失败 包含部署、监控、回退和错误处理。各项必须使用同一时间范围和质量门槛。 输入是训练候选、请求规模、上下文、并发、量化、硬件和质量约束，输出是满足质量条件的生命周期成本前沿。只优化训练 FLOPs，会把成本转移到部署阶段。

### 3.11.9 外推何时会失效

从小模型拟合的直线，为什么不能无限延长？。 断点来源； 表现； 应对。 架构/配方改变； 新点离开旧直线； 分段拟合并重做消融。 数据耗尽或分布变更； 收益提前饱和； 报告数据混合与有效 token。 优化不稳定； 大规模点异常变差； 先排查学习率、并行与数值问题。 指标触顶/阈值； 损失与任务分数脱钩； 换连续指标并做切片。 超出拟合区间； 置信区间迅速扩大； 加入中间规模锚点。 。 缩放定律是地图，不是保证书。 它预测“相似系统在附近规模”的趋势，不能证明安全、可靠、可控，也不能替代目标任务评测。

### 3.11.10 常见误区与学习路线

会套公式只是起点，可靠决策还需要实验设计与指标意识。 误区； 更准确的理解。 规模翻倍，能力也翻倍； 幂律意味着边际收益递减。 一条直线适用于所有模型； 指数依赖模型族、数据和配方。 token 数相同，训练价值相同； 质量、重复和分布决定有效信息。 验证损失能代表全部能力； 具体能力、安全和事实性要独立评测。 训练最优就是部署最优； 高请求量时推理成本会改写最优点。 。 层级； 概念依赖与延伸。 先修； 交叉熵、对数、模型训练、FLOPs。 本页核心 ； 幂律、计算最优、有效数据、外推边界。 系统； 分布式训练、推理优化、量化。 研究； 数据配比、涌现测量、生命周期优化。 。

### 3.11.11 把因果链连起来

这个概念怎样从问题一路连接到可验证的实践？。 选择同一模型族与稳定训练配方。 在多个 N、D、C 点训练。 拟合 L∞、A 与 α。 固定预算寻找 N–D 前沿。 用中间规模检验外推。 以任务切片和生命周期成本验收。

### 3.11.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 α=0.1 时，十倍资源使可约损失变为多少？。 为什么要先减去 L∞ 再取对数？。 固定 C≈6ND 时，N 翻倍意味着什么？。 为什么名义 token 数不能直接跨数据集比较？。 何时训练计算最优不等于产品最优？。 假设“缩放定律：用幂律规划参数、数据与算力”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 。 参考答案 乘以 10⁻⁰·¹≈0.794，即减少约20.6%。 幂律作用于可约损失 L−L∞；直接对 L 取对数通常不会得到严格直线。 在近似成立时 D 约减半，因此可能从容量瓶颈转为数据不足。 重复、质量、污染和分布让每个 token 的有效信息不同。 推理请求很多，或延迟、显存、能耗约束主导全生命周期成本时。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。

## 3.12 模型家族：从信息流与训练目标理解能力边界（model-families）

### 3.12.1 “模型家族”至少包含四个互相独立的轴

为什么“它是 Transformer”远远不够？。 模型家族 在这里不是品牌集合，而是一套描述模型机制与交付方式的坐标。输入是一个具体模型版本或任务需求，输出是架构、训练目标、模态接口和后训练/产品层四项说明。 轴； 回答的问题； 例子。 架构； 信息怎样读取、保存与混合？； 编码器、因果解码器、扩散、SSM。 训练目标； 模型被奖励去预测什么？； 掩码词、下一个 token、去噪、对比学习。 模态/接口； 输入输出是什么结构？； 文本、图像、音频、动作、多模态。 后训练/产品； 原始模型外又加了什么？； 指令对齐、RAG、工具、记忆、安全策略。 。 先消除一个最常见的混淆： “Transformer”“大语言模型”和“聊天产品”不是同一层。Transformer 是信息流骨架，大语言模型还包含训练目标与数据，聊天产品又叠加后训练、检索、工具和权限。看到其中一个名称，不能自动推出另外两层的能力与边界。 同一个 Transformer 骨架可以训练成分类编码器、文本生成器或视觉模型；同一个生成模型又可被包装成完全不同的产品。四轴帮助解释“为什么擅长”，却不能只凭家族标签保证质量、隐私或安全，仍要查具体版本并实测。

### 3.12.2 编码器、解码器与编码器—解码器的信息流不同

同样使用注意力，为什么适合的任务不同？。 家族； 注意力可见范围； 常见目标； 天然强项。 Encoder-only； 双向看完整输入； 掩码 token； 分类、检索表示、抽取。 Decoder-only； 只看当前位置之前； 下一个 token； 开放式生成、续写、上下文学习。 Encoder–decoder； 输入双向；输出因果； 条件序列生成； 翻译、摘要、结构化转换。 。 编码器输入完整序列并输出每个位置的双向表示；因果解码器输入提示与已生成前缀，逐步输出下一个 token；编码器—解码器先编码输入，再让输出端条件生成。“天然强项”不是排他能力，区别在于训练信号与计算路径是否贴合任务。 公式：给定输入 x 时输出序列 y 的概率，等于每个位置 t 的 token y t 在输入 x 和先前输出 y 小于 t 条件下的概率乘积。 x 是条件输入，例如待翻译原文； y 是完整输出序列， t 是当前生成位置， y<t 是此前已生成的 token。乘积符号表示整段输出概率由每一步条件概率相乘得到，因此早期选择会改变后续条件。

### 3.12.3 扩散模型学习逐步去噪，不是从左到右续写

为什么图像生成常从噪声开始，并经过很多步？。 前向过程逐步向干净数据加入噪声，训练输入是带噪样本、时间步和可选条件，输出是模型预测的噪声、速度或干净样本。生成时从噪声出发，反复使用这些预测恢复结构，而不是逐像素从左到右续写。 公式：时间 t 的带噪样本 x t，等于 alpha bar t 的平方根乘干净样本 x zero，加一减 alpha bar t 的平方根乘噪声 epsilon；模型根据 x t、t 和条件 c 预测 epsilon。 x₀ 是干净样本， xₜ 是时间步 t 的带噪样本， ᾱₜ 控制还保留多少原信号， ε 是加入的随机噪声。 εθ 是参数为 θ 的去噪网络， c 是文本等条件；训练让网络预测实际噪声，生成再按调度器逐步反推。 这里的“高维”是什么意思？ 高维表示一个样本需要由很多个数值坐标共同描述；例如图像潜变量包含大量位置与通道，所以去噪不是只改一个数字，而是要协调许多坐标。维度多并不自动代表信息更丰富：若数据类型主要是离散规则或要求逐字精确，扩散的连续去噪优势未必适用。 扩散可以同时修正整幅潜变量，适合连续高维信号；传统采样需要多步，精确文字、离散逻辑与实时延迟常需额外设计。扩散是机制，不等同于图像模态，也可用于音频、视频、动作或离散序列。

### 3.12.4 状态空间与递归家族用压缩状态换线性扫描

不做所有位置两两比较，模型如何携带历史？。 公式：时间 t 的隐藏状态 h t 等于状态转移 A 乘上一状态 h t 减一，加输入映射 B 乘当前输入 x t；输出 y t 等于读出 C 乘 h t。 xₜ 是当前位置输入， hₜ₋₁ 是此前历史压缩成的状态；矩阵 A 更新旧状态， B 写入当前输入，得到新状态 hₜ ，矩阵 C 再把状态读成输出 yₜ 。实际 RNN 或 SSM 会加入非线性、门控或输入依赖参数，公式只给出最小信息流。 对长度 n，注意力分数矩阵有 n² 个位置对：n=1000 时约一百万，n=4000 时约一千六百万；递归或状态空间扫描步数只增加约四倍。但实际速度还取决于硬件并行、状态维度与内核。 压缩状态会丢掉部分细节：需要精确随机访问、原样复制早期片段时，完整注意力或外部记忆可能更合适。现代系统常做混合，而非二选一。

### 3.12.5 多模态模型关键在“在哪里融合”

图像加文本输入，是否就形成了统一理解？。 多模态融合把图像、音频等表示与文本表示放进能够相互影响的计算路径。输入是两种或更多模态，输出可以是共享表示、文本、图像或动作；关键不是接口能接收文件，而是哪一层开始允许跨模态信息交互。 常见路线包括：视觉或音频编码器先提取向量，投影器把向量变成语言模型可读 token；不同模态各自编码后用交叉注意力互相查询；或从头训练统一 token 空间。融合位置决定哪些层能做跨模态交互，数据配对质量决定表示是否真正对齐。 方案； 优点； 限制。 冻结编码器 + 投影器； 训练便宜、复用成熟模型； 底层表征难共同适配。 交叉注意力融合； 保留模态专长； 接口与训练更复杂。 统一 token/骨架； 交互深入、接口统一； 数据与计算需求高。 。 输出流畅地描述图片只证明生成路径可用，不证明 OCR、空间关系、计数和细粒度定位都可靠；这些能力需要分别设计输入输出明确的测试。

### 3.12.6 运行示例：为退款助手拆分任务，而非先挑品牌

分类工单、读小票、生成回复和执行退款，需要同一个模型包办吗？。 图示：退款助手按任务约束选择模型家族的决策图。 图 1 模型家族选择发生在任务拆解之后；高风险动作交给有权限边界的工具，而非让生成模型“凭语言执行”。 一个小编码器可低成本路由，视觉模型只处理带附件请求，解码器起草解释，退款 API 负责真实状态变化。组合系统通常比“最大模型全包”更便宜、可测、可控。

### 3.12.7 把硬约束先过滤，再比较质量—成本前沿

排行榜第一为什么可能不是你的最佳模型？。 定义任务单位与失败代价：每封邮件、每张小票还是每次会话。 先筛硬约束：数据驻留、许可、模态、上下文、硬件、最大延迟。 在真实切片上评测候选家族和规模，包含拒答与失败回退。 比较质量—成本—延迟的 Pareto 前沿，不把异质指标随意加成总分。 灰度上线，记录模型、提示、检索库与工具版本。 候选； 字段 F1； P95 延迟； 每千件成本； 结论。 小编码器 + OCR； 0.94； 180 ms； ¥2； 适合标准票据。 多模态生成器； 0.96； 1.8 s； ¥28； 适合复杂长尾。 规则模板； 0.88； 25 ms； ¥0.2； 只覆盖固定版式。 。 数字是教学算例，不代表真实厂商性能；重要的是用同一数据、同一成功定义测量。

### 3.12.8 后训练改变行为，但不会抹去基础机制

“推理模型”“聊天模型”“工具模型”是新架构吗？。 监督微调、偏好优化、强化学习和蒸馏可显著改变回答风格、遵循指令、推理时计算与工具调用，但底层仍可能属于同一解码器家族。产品还可在模型外加入系统提示、RAG、过滤器、缓存和工作流。 观察到产品能引用资料，不能直接推断基础模型“记住了数据库”；它可能只是运行时检索。观察到产品会调用工具，也不能推断模型拥有权限——真正权限在执行层。 诊断顺序： 先定位错误发生在基础生成、后训练策略、上下文检索、工具参数还是执行权限，再选择修复层。

### 3.12.9 开放权重、API 与品牌属于交付层，不是架构家族

“开源模型更隐私”或“闭源模型一定更强”为什么都不成立？。 权重许可、训练代码、数据开放程度、托管位置和 API 数据政策是不同问题。开放权重允许自托管，但若部署在第三方云上，数据仍可能外发；API 服务也可能提供零保留与区域选项。品牌下会同时存在多代、多尺寸、多模态和不同上下文版本。 不能从名称直接推出； 必须查什么。 隐私与数据保留； 部署拓扑、合同、日志策略。 可商用性； 权重/代码/数据许可证。 工具可靠性； 函数调用评测、权限和重试。 知识新鲜度； 知识截止、检索源与更新时间。 真实版本； 模型 ID、日期、参数和服务档。 。

### 3.12.10 常见误区与学习路线

先用四轴定位，再深入具体家族与系统层。 误区； 更准确的理解。 Transformer 就等于聊天大模型； 同一骨架可配多种目标与模态。 参数更多必然更适合； 任务切片、延迟和约束决定前沿。 多模态就是每项模态都强； 需分别测 OCR、定位、关系和生成。 线性复杂度一定更快更好； 常数、并行性与随机访问能力同样重要。 品牌名可推出隐私与许可； 这些属于具体版本、合同和部署。 。 层级； 学习方向。 先修； 监督学习、自监督学习、神经网络。 本页核心 ； 架构 × 目标 × 模态 × 产品层。 深入架构； Transformer、扩散、RNN、SSM、MoE。 落地； 模型选择、评测、部署、RAG、工具调用。 。

### 3.12.12 误区与自测

你能否不用背术语，解释它的机制、边界与验证方法？。 为什么 Transformer 不是完整的模型家族说明？。 长度从1000增至4000，注意力位置对约增多少倍？。 退款助手为何不应让生成模型直接执行退款？。 开放权重为什么不自动等于隐私？。 模型选择的第一步是什么？。 假设“模型家族：从信息流与训练目标理解能力边界”在离线示例上表现正常、上线后核心结果却下降，你会怎样按输入、内部变换、输出反馈和适用边界定位问题？。 。 参考答案 它只说明部分架构；还需说明编码/解码信息流、训练目标、模态与后训练/产品层。 从约100万到1600万，增16倍；线性扫描步数约增4倍。 语言生成不提供鉴权、幂等和审批保证；状态变化应交给有权限边界的确定性工具。 隐私取决于实际部署、日志、数据流和合同；开放权重也可能托管在第三方环境。 定义任务单位、失败代价和硬约束，而不是先看品牌排行榜。 先保存同一失败样本及环境，确认输入、权限和前置条件没有漂移；再记录关键中间状态，检查机制是否按本页描述完成变换；随后把原始输出与独立指标、人工终验对照；最后用边界样例和对照实验复测。只有定位到首次偏离预期的环节，才能判断应修改数据、机制、评测还是使用边界。

## 3.13 多模态（multimodal）

### 3.13.1 为什么要「多模态」

本节回答：为什么要费劲让一个模型同时处理图、文、声，而不是各任务各训一个专用模型？。 两个理由。其一， 现实任务本就是跨模态的 ：看图说话、听声辨物、读带插图的文档——把图文声完全割裂会丢失联系。其二，把不同模态接入 同一模型系统 后，可以联合条件化并做跨模态推理。这里的“同一系统”可能是端到端统一模型，也可能由专用编码器、投影器、适配器和语言模型模块组成。 本页所说的多模态系统 ，输入是一种或多种模态的数据与任务指令，输出是文本、图像、声音、动作或跨模态判断。它先把各模态编码成可计算表示，再建立跨模态信息通道。结果应按具体任务解释，例如“猫趴在键盘上”是一次图文问答结果，不代表模型所有视觉能力都可靠；若任务不需要跨模态联系，专用模型通常更简单、更便宜。 一句话 多模态不是「把几个模型拼在一起」，而是让 一个模型 在一个统一的表示里，同时容纳并关联不同模态——这才有「1 + 1 > 2」。

### 3.13.2 第一块基石：Transformer 对模态无感

Transformer 是为语言设计的，凭什么能拿来处理图像和声音？。 因为它 不关心输入是什么，只关心「能不能切成一串 token（向量）」 。把一张图切成一个个小方块、每块当作一个「词」，把音频切成一帧帧，同一套 Transformer 就能照单处理（见「Transformer」深读页第 6 节）。这块基石解决了「 能不能一起算 」的问题。 这一层的输入是图像块、音频帧或文字经过编码后得到的向量序列，输出是 Transformer 更新后的 token 表示。自注意力让 token 彼此交换信息，因此同一计算骨架可以处理不同来源的序列。输出表示只能说明模型完成了数值变换；没有配对训练或其他对齐信号时，不能把两个模态中距离相近的 token 解释为同一概念。 但「能一起算」不等于「懂它们是一回事」 把猫的图切成 token、把「猫」这个字也变成 token，塞进同一个模型——它们此刻只是两串各说各话的数字。模型凭什么知道 这串图 token 和那个字，指的是同一个东西 ？这就要第二块基石。

### 3.13.3 第二块基石：用数值例子理解跨模态对齐

核心的一节：怎么让「猫的图」和「猫」这个词，在模型眼里对应上？。 一种重要方法是学习 可比较的跨模态表示 ：让配对的图文向量靠近、不配对的推远，这正是 CLIP 的路线。但多模态系统不一定把所有 token 永久压进单一共享空间；也可以保留视觉特征，再通过投影器或交叉注意力把它们接入语言模型。共同目标是 建立可学习的模态对齐与信息通道 。 图示：图像和文本被映射到同一个语义空间并对齐。 图 1 对齐：不同模态各有自己的编码器，但都被映射进 同一个 语义空间，让「猫的图」和「猫」这个词落在相近的位置。有了对齐，图 token 和字 token 才「说同一种语言」。 。 CLIP 就是干这个的 用海量「图 + 对应文字说明」的配对，训练两个编码器（一个看图、一个读文）， 让配对的图和文向量靠拢、不配对的推开 ——正是「嵌入」里那套对比训练，只不过跨了模态。训练完，图和文就共享了一个空间。这也是文生图能「按文字找到对应画面」的地基（见「CLIP」「图像生成」节点）。 数值例子：对齐如何变成可比较分数 设猫图向量 v=(0.8,0.6) ，文本“猫”向量 t₁=(1,0) ，文本“键盘”向量 t₂=(0.6,0.8) ，三者长度都为 1。余弦相似度为点积： v·t₁=0.8 ， v·t₂=0.96 。这张“猫趴键盘”的局部视觉表示会更匹配“键盘”。训练会提高正确图文配对相对批内错误配对的分数；但单个相似度不是概率，也不保证模型能数清键帽或理解空间关系。 对齐训练的输入是成对或带对应关系的图文样本，输出是可比较的表示或可跨模态查询的特征。训练目标提高正确配对的相似度、降低错误配对的相似度；检索时，相对分数越高表示“在当前候选中更匹配”，不是事实概率。若配对数据含偏差、候选集改变，或任务要求计数和空间推理，单靠全局对齐并不够。 对齐是多模态的灵魂 Transformer 让不同模态 能一起算 ，对齐让它们 说同一种语言 。没有对齐，多模态就只是几串互不相干的 token 硬凑在一起。

### 3.13.4 怎么把「看」接到「说」上

具体到一个已经很会说话的大语言模型，怎么让它长出「眼睛」？。 一种主流做法很直接：用一个 视觉编码器 把图像变成一串「视觉 token」，再用一个投影层把它们 对齐进大模型的词向量空间 ，当成一些特殊的「词」 拼在文字 token 前面 ，一起喂给大模型。于是大模型能像「读文字」一样「读」这张图，然后照常自回归地生成回答。 图示：视觉编码器把图变成视觉token，和文字token一起喂给大模型。 图 2 给大模型装眼睛的常见做法：图像 → 视觉编码器 → 视觉 token（投影进词向量空间）→ 和文字 token 拼在一起 → 喂给大模型。模型于是能「边看图边答话」。 。 这条接入链的输入是一张图和文字问题，输出是语言模型生成的答案。视觉编码器提取图像特征，投影层把特征变成语言模型可接收的视觉 token，语言模型再结合文字 token 逐步生成回答。答案中的词是条件生成结果，不是视觉传感器的直接读数；细小文字、空间定位和超高分辨率图像可能因编码压缩而丢失，必须用对应切片验证。

### 3.13.5 模态打通，解锁了什么

把图文声接进同一个模型后，哪些以前做不到的事成为可能？。 能力； 靠什么。 图文问答、读懂文档里的图表； 同一模型里图文对齐、联合推理。 文生图 / 文生视频； 文本与图像在共享空间对齐，才能「按文字找到画面」（见「图像生成」）。 Agent 看屏幕、操作界面； 把界面截图当作视觉输入来理解（见「计算机操作」「AI Agent」）。 无障碍：读图给视障者、语音交互； 跨模态转换（图→文、文→声）。 。 这张能力表的输入是一个跨模态业务任务，输出是应该采用的转换方向与验收结果：图文问答输出答案，文生图输出图像，屏幕 Agent 输出受控动作。选择能力时先判断哪些模态提供条件、哪种模态承载结果，再沿对齐与生成链验证。结果只能解释为该任务切片上的能力；“支持图像”不能推出 OCR、图表推理、定位和视频理解全部达标。 它是 LLM 的自然扩展 多模态大模型，可以看成给大语言模型 加装了处理其它模态的入口和对齐 ——核心的「理解与生成」还是那套（见「大语言模型」深读页）。这也是为什么今天主流模型几乎都是原生多模态的。

### 3.13.6 代价与挑战

它有什么新的坑，是纯文本模型没有的？。 本节把多模态系统新增的失败来源分成对齐、计算与生成三类。诊断输入是失败样本、模态原件和中间表示，输出是首次出错的环节及相应处置。按“原始输入是否清楚—编码是否保留关键信息—跨模态对应是否正确—生成是否忠于证据”逐层检查；单看最终回答无法区分模型没看清、没对齐还是语言模型脑补。 对齐质量决定上限 ：图文对齐得不好，模型就会「看错」；多模态的成败，很大程度取决于对齐训练的数据与质量。 信息密度差异大 ：一张高清图的信息量远超一句话，切成 token 后又长又贵，处理长视频尤其吃算力。 幻觉在图上照样有 ：模型可能把图里 根本没有 的东西说得有鼻子有眼（「图中有只狗」——其实没有）。它描述的仍是「最可能的说法」，不是「看到的事实」。 别把它当「客观的眼睛」 多模态模型「看图说话」，本质还是在生成最可能的文本，只不过多了图像作为条件。它 会看错、会脑补 ，关键场景仍需核对，别把它的描述当成对图像的客观读数。

### 3.13.7 把整条因果链连起来

现在从“现实任务跨模态”一路推到“为什么统一 token 之后仍需要对齐和验证”。 现实任务跨模态，且一个模型统一处理能让不同模态互相印证——所以要多模态。 （§1） 。 第一块基石：Transformer 对模态无感，什么都能切成 token 一起算。 （§2） 。 但「能一起算」不等于「懂它们是一回事」，所以需要第二块基石。 （§2→3） 。 第二块基石：建立跨模态对齐；可以是 CLIP 式共享表示，也可以是投影器或交叉注意力连接。 （§3） 。 工程上，用视觉编码器把图变成视觉 token、投影进词向量空间，和文字 token 一起喂给大模型。 （§4） 。 模态打通后解锁图文问答、文生图、看屏幕操作、无障碍等。 （§5） 。 但对齐质量决定上限、信息密度差异大、图上也会幻觉。 （§6） 。 过关标准 如果你能说清「多模态靠哪两块基石成立」，尤其能讲明「为什么‘对齐到同一个语义空间’才是灵魂」，你就抓住了它的内核。

### 3.13.8 常见误解

下面这些说法分别混淆了统一计算接口、共享表示、模块化系统和客观感知。 误解； 更准确的理解。 多模态就是把几个专用模型拼起来； 是让 一个 模型在统一表示里容纳并关联多种模态。 能把图切成 token 就算多模态了； 还必须把模态 对齐 到同一语义空间，否则各说各话。 它像人一样「看到」图像； 它把图像当条件来生成最可能的文本，会看错、会脑补。 多模态是全新的架构； 多是给大语言模型加装模态入口与对齐，核心仍是那套理解与生成。 看图描述可当作客观读数； 图上也有幻觉，关键场景需核对。 。

### 3.13.9 检查你是否真的理解

为什么要用一个模型处理多模态，而不是各模态各训一个？。 Transformer 凭什么能处理图像和音频？这解决了多模态的哪一半问题？。 「能一起算」为什么不等于「懂它们是一回事」？还差什么？。 什么是模态对齐？CLIP 是怎么做对齐的？。 工程上，怎么给一个大语言模型「装上眼睛」？。 模态打通后，举出至少三种被解锁的能力。 为什么说多模态模型「看图说话」时仍会幻觉？该如何对待它的描述？。 参考答案 现实任务跨模态；一个模型统一处理能让不同模态互相印证、补充、做跨模态推理，比拼装更强。 因为它只要求输入能切成 token 序列、对模态无感；这解决了「能不能一起算」的问题。 因为不同模态的 token 此刻只是各说各话的数字，模型不知道它们指同一事物；还差把它们对齐到同一语义空间。 让不同模态描述同一事物的向量落到同一空间且靠近；CLIP 用海量图文配对做对比训练，让配对的图文向量靠拢、不配对的推开。 用视觉编码器把图变成视觉 token，投影进词向量空间，和文字 token 拼在一起喂给大模型，模型便能边看边答。 图文问答/读图表、文生图或文生视频、Agent 看屏幕操作界面、读图给视障者等无障碍应用。 因为它本质是把图当条件生成最可能的文本、而非客观读取图像，会把图里没有的东西说得有；关键场景需核对，别当客观读数。
