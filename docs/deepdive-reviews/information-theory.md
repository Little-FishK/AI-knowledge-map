# 信息论与熵理解原理页审查记录

审查日期：2026-07-25  
页面：`data/deepdive/information-theory.js`  
官方学习路径：`1.1 · 信息论与熵`

## 记录目的

本记录不是普通修改日志，而是后续统一优化 L1/L2/L3 门禁规范的缺陷样本。每条问题需要同时保留用户理解障碍、自动门禁漏检原因、候选自动检查和必须由人工判断的边界。

## 发现与修复

### 1. 交叉熵只有关系式，没有核心定义

- 用户影响：页面直接给出 `H(P,Q)=H(P)+KL(P∥Q)`，却没有定义 `H(P,Q)=−ΣP(x)logQ(x)`，读者不知道为什么 P 在外面加权、Q 在对数里面，也无法理解后续表格。
- 漏检原因：L3 检测到“交叉熵”、公式、表格和手算案例便给分，没有验证关键概念是否在第一次参与推导前完成定义。
- 修复：新增 P/Q 角色表、单次对数损失、四步计算流程和完整交叉熵定义，再说明 Q=P 时交叉熵退化为熵。

### 2. KL 无铺垫突然出现

- 用户影响：读者只看到一个新缩写和结论式，不知道 KL 在测什么、为什么非负、为什么有方向，也无法把它和交叉熵联系起来。
- 漏检原因：门禁只识别术语和关系式，不验证新量是否由已知量推导，也不检查符号首次出现处的信息完备性。
- 修复：先比较最优平均代价 `H(P)` 与模型平均代价 `H(P,Q)`，通过逐项相减推出 `ΣPlog(P/Q)`，再命名为 `KL(P∥Q)`；补充非负、方向和零概率边界。

### 3. 提到“不是欧氏距离”却没有介绍欧氏距离

- 用户影响：用一个尚未讲解的概念解释另一个新概念，不能形成有效对比。
- 漏检原因：现有门禁能识别“KL 非对称”等边界关键词，却不会检查用于类比或反例的参照概念是否已定义。
- 修复：新增欧氏距离公式、几何含义、对称性和数值例子，并用表格逐项比较它与 KL 回答的问题。

### 4. 困惑度定义过短且直觉可能被字面化

- 用户影响：“有效候选规模”没有解释指数从何而来，容易被理解成模型真的只在固定数量的 token 中选择。
- 漏检原因：公式或关键词存在即可得分，没有检查类比是否声明适用边界。
- 修复：从平均 bit/token 指数化得到 PPL，改称“熵等效分支数”；明确它不是词表大小，并分别说明 bit 与 nat 下应使用的指数函数。

### 5. P 与 Q 的介绍晚于依赖它们的内容

- 用户影响：第 7 节例题数值正确，但前文未充分说明 P 是事件频率、Q 是模型概率，导致读者看不懂为什么用 P 加权 Q 的码长。
- 漏检原因：门禁不建立符号的定义—使用依赖图。
- 修复：把 P、Q、事件、概率分布、期望和对数底数集中放在第一节；例题表头改为角色完整的自然语言，并逐步对应前文定义。

### 6. 官方早期节点存在循环先修

- 用户影响：1.1 把 tokenization 等后续内容列为先修，初学者会认为自己遗漏了必备课程。
- 漏检原因：单页审计未读取官方推荐路径的拓扑顺序。
- 修复：把 token 作为明确标注的提前直觉，并指向 2.8；本页直接补齐概率分布、加权平均、对数和 P/Q 所需的最低知识。

### 7. 总体交叉熵与经验训练损失混淆

- 用户影响：“训练交叉熵下降等价于 KL 下降”可能被理解为训练集损失下降必然改善真实分布。
- 漏检原因：门禁无法识别总体量、样本估计量和因果结论之间的限定条件。
- 修复：分开定义总体交叉熵、训练损失和验证损失，明确经验平均只是未知 P 下总体量的估计。

### 8. 自测被通用工厂题污染

- 用户影响：原有前五题停留在术语复述，随后自动出现与本页无关的线上指标、权限、预算和安全切片，难度与主题断裂。
- 漏检原因：生成器按题量和高阶疑问词补题，没有检查题目术语是否来自正文，也没有验证答案是否覆盖本页学习目标。
- 修复：提供八道主题专属问题，覆盖符号角色、手算、推导、欧氏距离、PPL、经验与总体量、跨 tokenizer 比较；题目自身满足工厂的场景题和高阶题条件，不再触发通用补题。

### 9. 对数底数和单位出现不一致

- 用户影响：自信息使用 `log₂`，后续公式只写 `log`，读者可能以为 bit、nat 以及 PPL 的指数形式可以混用。
- 漏检原因：门禁只检查公式存在，不执行跨公式的单位一致性分析。
- 修复：本页理论推导统一使用 `log₂` 和 bit；语言模型部分单独说明自然对数对应 nat 与 `exp(loss)`。

### 10. 裸文本根号没有覆盖完整被开方表达式

- 用户影响：普通字符 `√` 只是固定宽度字形。在 `√((2−1)²+(110−100)²)`、`√[Σₓ(P(x)−Q(x))²]` 等表达式中，根号横线只覆盖开头，读者无法从排版确认哪些项属于根号内部。
- 漏检原因：原门禁只拦截 `sqrt(...)` 这类编程记法，没有区分“出现根号字符”和“建立了带明确被开方范围的根式结构”；浏览器审计也没有检查根式容器、横线和内容溢出。
- 修复：迁移全项目 16 个页面文件中的 58 处裸根号；核心复杂公式使用 MathML `<msqrt>`，历史正文短根式使用带可访问名称的 `.dd-radical > .dd-radicand` 结构。L3 新增 `notation.plain-text-radical` 阻断项，浏览器门禁检查语义角色、被开方内容、横线和溢出。

## 候选门禁改进

| 缺陷模式 | 候选自动检查 | 误报与人工边界 |
|---|---|---|
| 核心量先参与关系式、后定义 | 建立公式符号首次出现索引；学习目标中的核心符号在首次推导前应有定义或显式预览标记 | 公认符号可能无需重复定义，适合作为审校告警而非仅凭一次出现硬阻断 |
| 新概念用另一个未定义概念作对比 | 抽取“不同于、不是、相比、类似”等比较句，检查参照概念附近是否有定义、公式或链接 | 常识性参照无需展开，是否属于目标受众常识仍需人工判断 |
| 定义、公式和案例之间缺少角色映射 | 对手算表中的符号检查前文是否解释其语义，并要求关键计算具备定义、代入、结果、解释四类证据 | 自动语义映射可能漏掉自然语言同义表达 |
| 类比没有边界说明 | 对“可理解为、相当于、类似”等类比句检查邻近段落是否包含“不代表、不是、仅”等边界语句 | 有些严格等价不需要警告，需区分类比和数学恒等式 |
| 官方路径中的后续节点被列为先修 | 把“先修”声明与推荐路径拓扑比较；后序节点必须标为预览或后续学习 | 非线性学习路线允许提前使用，只有未做降阶解释时才应阻断 |
| 总体量与经验估计混用 | 对“经验、训练集、样本平均”与总体恒等式同段出现的情况检查是否包含“估计、近似、条件” | 是否足够严谨依赖上下文，适合作为人工复核项 |
| 自测包含正文从未出现的专有术语 | 计算题目术语对正文的覆盖率，并标记多页高度重复的通用题 | 迁移题允许引入新场景，但不应依赖未教授的新机制 |
| 对数底数、信息单位与指数函数不一致 | 建立 `log₂→bit→2^loss`、`ln→nat→exp(loss)` 的单位规则 | 省略底数可能来自已声明的全局约定，应读取页面级约定后判断 |
| 裸 `√` 没有表达被开方范围 | 静态阻断页面中的裸根号；真实浏览器检查根式语义容器、横线及内容溢出 | 多行根式、分式和矩阵必须直接使用 MathML，不能依赖短根式包装 |

## 验收边界

本轮修复和自动测试不等于 L4 认证。正式 L4 仍需独立审校者复算案例、核对来源、检查桌面与移动端证据，并登记当前页面内容哈希。
