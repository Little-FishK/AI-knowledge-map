# 损失函数理解原理页审查记录

审查日期：2026-07-25  
页面：`data/deepdive/loss-function.js`  
官方学习路径：`1.2 · 损失函数`  
状态：已修复本轮发现的问题；尚未进行 L4 独立人工认证

## 记录目的

本记录用于积累后续统一优化 L1/L2/L3 门禁规范的真实缺陷样本，而不是只陈列文字修改。每条问题需要保留用户的实际理解障碍、现有门禁漏检原因、可能的自动检查，以及自动规则不能替代的人工判断。

## 发现与修复

### 1. 经验风险公式主题正确，但符号一次出现且没有解释

- 用户影响：`J(θ)=1/n·ΣL(fθ(xᵢ),yᵢ)+λR(θ)` 同时引入 θ、n、f、L、λ、R 和 J，初学者无法知道每个符号扮演什么角色。
- 漏检原因：L3 检测到经验风险公式、正则化和文字说明即可得分，不检查公式符号是否逐项完成语义绑定。
- 修复：拆成“单样本损失 → 数据平均目标 → 可选正则目标”三步，逐项解释 θ、xᵢ、yᵢ、n、J、R 和 λ，并把正则化标为后续预览。

### 2. 交叉熵主题正确，但表达没有形成可读过程

- 用户影响：原例只比较真实类别概率 0.9 与 0.01，却声称解释“犹豫地错”和“自信地错”；前者通常是正确预测，证据与结论不匹配。公式中的 `pθ(y|x)` 和对数单位也没有解释。
- 漏检原因：门禁会核对数字、公式和关键词是否存在，却不会验证两个对照样本是否同时满足题干条件。
- 修复：逐项解释条件概率符号，声明使用自然对数和 nat；用 0.49 与 0.01 两个都预测错误的样本比较准确率和交叉熵，并保留 0.9 作为正确预测参照。

### 3. “成交率、满意度、可微代理”没有铺垫

- 用户影响：第 5 节的推理方式本身成立，但连续引入产品和优化术语，读者不知道它们是什么、为何出现在损失函数页。
- 漏检原因：术语都属于机器学习常见词，关键词门禁无法判断它们是否超出当前目标读者的已知词汇。
- 修复：先定义真实目标、成交率、满意度、代理和可微，再解释延迟、稀疏和外部混杂因素为什么使产品目标难以直接提供梯度。

### 4. 手算突然设定 `w=2`

- 用户影响：读者不知道 w 是参数、为什么是 2、它与 `y=3x` 有什么关系，后面的更新表只能机械照算。
- 漏检原因：自动门禁能识别输入、目标、参数和更新数字，但不验证案例变量是否在第一次赋值前建立了自然语言含义。
- 修复：把 `ŷ=wx` 解释为直线模型，定义 x、ŷ、w；说明理想参数是 3，并明确 `w=2` 是故意选择的错误初始值。

### 5. MSE、MAE、Huber 没有兑现“误差假设”学习目标

- 用户影响：原页只用简表概括三者，Huber 没有公式和阈值；高斯噪声、条件中位数等结论没有形成对称解释。
- 漏检原因：门禁只检查三种损失名称和比较表，不检查学习目标中的“解释假设”是否有公式、例子和边界支撑。
- 修复：补充条件均值/中位数、Gaussian/Laplace 两组互补解释，给出 Huber 分段公式、δ 的含义以及同一数值下的计算。

### 6. “损失必须是标量”过度绝对

- 用户影响：容易让读者误以为系统从一开始就不能保留分样本、分群体或多任务损失，忽略标量化本身的权重选择。
- 漏检原因：绝对化表述符合大量入门教材的简化措辞，关键词门禁无法判断是否掩盖关键边界。
- 修复：改为普通梯度更新最终需要明确的标量目标，但此前可以且应保留损失向量和分项证据。

### 7. 批量损失与梯度估计混为一谈

- 用户影响：表格称批量损失回答“梯度估计是什么”，让读者误以为损失值本身就是梯度。
- 漏检原因：损失和梯度术语同时出现即可满足机制覆盖，门禁不验证二者之间的运算关系。
- 修复：明确批量损失是当前小批样本的平均目标，对它求梯度后才得到总体梯度的估计。

### 8. 梯度与链式法则早于官方学习顺序

- 用户影响：第 7 节直接给出偏导和 `e·x`，但梯度下降位于 1.3，读者尚未学过导数和链式法则。
- 漏检原因：单页门禁奖励完整训练闭环，却不检查当前节点是否把后续节点当成未说明的先修。
- 修复：把梯度计算明确标为 1.3 的预览，用“w 改一点时预测按 x 倍变化”的语言解释 `e×x`，避免要求读者先掌握正式链式法则。

### 9. 对数底数与 1.1 不一致

- 用户影响：1.1 区分了 bit 与 nat，1.2 的交叉熵使用自然对数数值却只写 `log`，连续学习时单位断裂。
- 漏检原因：现有门禁只在单页内检查公式数量，不做相邻官方节点的符号和单位连续性检查。
- 修复：统一写成 `−ln pθ(y|x)`，声明单位为 nat，并解释改用 `log₂` 时单位为 bit。

### 10. 最终自测被通用题追加污染

- 用户影响：源码的主题题之后被追加上线均值、权限、预算、评分器和通用切片问题，难度与正文不连续。
- 漏检原因：生成器按题量和高阶疑问词补题，不检查题目术语是否在正文出现。
- 修复：将本页移出通用追加名单，改为八道主题专属题，覆盖公式符号、回归损失、交叉熵、可微代理、手算、校准和目标错位。

## 候选门禁改进

| 缺陷模式 | 候选自动检查 | 误报与人工边界 |
|---|---|---|
| 单个公式首次引入大量符号 | 提取公式标识符，检查邻近段落是否逐项出现解释、表格映射或前文定义 | 通用数学符号无需每页重复；应结合官方目标读者和路径位置 |
| 对照案例不满足声称的共同条件 | 对“两个都、同样、均为”等比较句，检查案例标签或判定结果是否一致 | 复杂自然语言条件需要人工确认，自动工具适合给出审校线索 |
| 新术语成组出现但无定义 | 对当前路径此前未出现的名词建立术语首次出现审计，要求定义、括注或明确预览 | 常识词与专业词边界随受众变化，不宜只按词频硬阻断 |
| 学习目标提到“解释/推导”，正文只有术语表 | 建立学习目标到公式、数值例子、边界说明的证据映射 | 有些概念适合纯直觉解释，所需证据类型仍需人工判断 |
| 变量先赋值、后说明语义 | 检查案例中首次出现的变量赋值附近是否包含“表示、参数、输入、目标、初始”等角色词 | 简短复习题可省略已定义变量，应读取前文作用域 |
| 损失值和梯度估计混用 | 检查“损失是梯度/回答梯度”等近邻表述，要求存在“求导、梯度 of loss”等关系 | 自动语义判断可能误报比喻表达，适合人工复核 |
| 当前节点依赖后续公式 | 对官方路径拓扑做引用检查；后续概念必须标成预览并提供降阶直觉 | 提前展示闭环可能有教学价值，不应一律禁止 |
| 相邻页面对数底数与单位断裂 | 沿官方路径追踪 log/ln/log₂、nat/bit 和指数函数约定 | 页面可声明局部约定；规则应允许显式切换 |
| 自测出现正文未教授的术语 | 对最终渲染后的题干做正文术语覆盖和跨页题干相似度检测 | 真正的迁移题允许新场景，但不能依赖新的未教机制 |
