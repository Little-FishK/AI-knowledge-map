# 监督学习理解原理页审查记录

审查日期：2026-07-25  
页面：`data/deepdive/supervised-learning.js`  
官方学习路径：`1 · 监督学习`  
状态：已修复本轮发现的问题；尚未进行 L4 独立人工认证

## 记录目的

本记录不仅用于解释页面为什么修改，还要作为后续优化 L1/L2/L3 门禁规范的真实缺陷样本。每条问题都应回答：

1. 用户实际遇到了什么阅读、理解或验证障碍；
2. 现有自动门禁为什么仍然让页面通过；
3. 哪类规则、静态分析或浏览器检查可能提前发现它；
4. 新规则可能产生什么误报，哪些部分仍必须人工判断。

后续汇总多页记录时，应优先提炼能够跨页面复现的模式；只对单一页面成立的写作判断不应被机械升级为全局阻断规则。

## 发现与修复

### 1. “常见误解”出现超长重复斜体正文

- 发现：第 9 节表格前出现一段从第 1 节开始、跨越多个章节的重复文字，占据大量篇幅。
- 证据：用户截图 `codex-clipboard-20c1c801-86eb-4d47-83d4-e37856840598.png`。
- 根因：`zz-deepdive-quality-completion.js` 的 `addMissingLeads()` 使用可跨章节匹配的正则；当早期章节已有 `.dd-lead`、后续章节缺少时，匹配会从前一章节开始一直延伸到后续标题，再把整段正文压成引导语。
- 修复：把补写逻辑改为先逐个限定在单一 `<section>` 内，再只处理缺少 `.dd-lead` 的章节；监督学习页的第 9、10、11 节改为显式编写主题专属引导语，并移出通用补写名单。

### 2. 3.1 二分类手算叙述不连续

- 发现：先声明“垃圾邮件为标签 1”，随后直接写 `p=0.80`，没有解释 `p` 表示什么；两个样本对同一概率采用不同说法；表格直接使用 `−ln(p)`，没有给出交叉熵公式或化简过程。
- 修复：
  - 固定 `y=1` 为垃圾、`y=0` 为正常；
  - 全程统一 `p=P(y=1|x)` 为垃圾邮件概率；
  - 引入 `q` 表示模型分给真实类别的概率；
  - 从 `L(y,p)=−[y ln(p)+(1−y)ln(1−p)]` 分别化简到 `−ln(p)` 与 `−ln(1−p)`；
  - 解释负对数会轻罚高真实类别概率、重罚自信错误；
  - 明确损失函数与梯度下降将在官方路径 1.2、1.3 再正式展开。

### 3. 自测后三题难度跳变且答案没有回应题目

- 发现：通用质量补丁自动追加三道系统诊断题，突然引入模型版本、提示、权限、预算和评分器等尚未在本页建立的概念；最后一题要求设计三个切片，答案却没有逐项给出三个具体切片。
- 根因：`addAssessment()` 对不同概念统一追加同一组高阶问题，题目与监督学习页的垃圾邮件案例和知识依赖不匹配。
- 修复：监督学习页移出通用追加题名单，改为三道逐步递进的主题题：
  1. 类别不平衡下 99% 准确率为什么失真；
  2. 重复邮件跨训练/测试集合造成的数据泄漏；
  3. 按真实类别、来源/语言、时间设计三个验收切片。
  每道答案都直接完成题目要求，第三题明确列出三个切片及对应指标。

### 4. 标签被反复写成“正确答案”

- 风险：容易让初学者误以为标签天然等于客观真相，忽略误标、主观分歧、测量误差与代理目标。
- 修复：统一改为“目标值/监督信号”，增加“标签不等于真相”提示，并补充标签噪声来源。

### 5. 官方第 1 页存在循环先修

- 发现：页面把损失函数和梯度下降列为先修，但它们分别位于官方路径 1.2 和 1.3。
- 修复：进入本页前只要求函数与向量直觉；损失函数、交叉熵和参数更新明确标成预览，并把 1.2、1.3 列为下一步。

### 6. 自监督归类和评测表述过度绝对

- 发现：
  - “自监督是监督学习的变体，区别只在标签不用人标”忽略了不同教材的分类体系和学习目标差异；
  - “带标准答案的评测本质都是监督学习测试集”混淆了训练范式与测量过程。
- 修复：
  - 分开说明自监督的计算形式与监督信号来源，并承认它常被归入无监督表示学习；
  - 改为“带参考答案的评测借鉴留出测试思想，但评测不等于训练”。

### 7. 缺少类别不平衡、阈值和部署分布

- 风险：垃圾邮件案例若只讲准确率和随机切分，不能教会读者识别真实系统最常见的验收失败。
- 修复：增加 99% 准确率反例、精确率/召回率、分类阈值的错误代价，以及按来源、语言和时间切片的验收方法。

## 验收边界

本记录证明问题已被发现并在源码层修复，不等于 L4 认证。正式 L4 仍需：

- 独立审校者复核事实、公式和认知顺序；
- 重新计算并登记页面内容哈希；
- 绑定浏览器桌面/移动端证据；
- 对交叉熵数值、类别不平衡案例和自测答案进行独立复算；
- 在 `docs/deepdive-quality-reviews.json` 中登记完整证据。

## 候选门禁改进

以下是本页暴露出的门禁盲区，暂作为候选规则，不在本轮直接改变评分标准。

| 缺陷模式 | 现有门禁为何漏过 | 候选自动检查 | 误报与人工边界 |
|---|---|---|---|
| `.dd-lead` 跨章节吞入大段正文 | L2/L3只检查引导语存在和关键词，没有限制其长度及章节边界 | 浏览器或最终HTML检查单个 `.dd-lead` 的纯文本长度、表格内容串入、章节编号密度；对异常值阻断 | 某些复杂章节可能需要较长引导，应以明显异常阈值和相对正文比例为主 |
| 同一概率在连续句子中采用不同未定义表达 | 公式和数字存在即可获得结构分，无法判断符号是否先定义、是否保持一致 | 检查公式附近的符号首次出现是否有定义；把符号一致性列入L4人工复算模板 | 自然语言符号解析容易误报，短期适合生成审校线索而非L3硬阻断 |
| 使用 `−ln(p)` 却没有说明从何而来 | L3能识别公式与手算表，但不验证推导链是否完整 | 要求手算中的关键公式具备“定义/化简/数值代入/结论”四段证据映射 | 并非每个概念都需要完整推导，应由页面声明的学习目标决定是否阻断 |
| 自动追加题与正文难度、词汇不匹配 | 门禁只检查题量、高阶词和答案配对，通用题也能得分 | 检查题目中新术语是否在前文出现；检测大量页面共享的高相似题干与答案 | 合理的通用实验原则可能跨页复用，相似度只能生成告警，不能单独判错 |
| 问题要求“三个切片”，答案未逐项给出 | 只检查题目和答案数量相等，没有检查答案是否满足题目约束 | 提取明确数量、比较项和设计要求，验证答案中是否存在对应数量的可识别条目 | 语义满足性最终仍需人工判断；自动检查适合作为L2/L3审校提示 |
| 官方第1页把后续节点列为先修 | 单页门禁不读取推荐学习路径顺序 | 对“先修”表和正文中的明确依赖节点进行路径拓扑检查，发现引用后续节点时要求标记为“预览/下一步” | 提前提及后续概念不一定错误，只有声明为先修或未做降阶解释时才应阻断 |
| 标签、评测和自监督归类使用绝对化表述 | 关键词和来源数量检查无法判断概念边界 | 增加“必然、就是、只、所有、本质”等绝对词审计，并要求快速变化或有争议分类给出限定语 | 绝对词不一定错误，应作为人工复核线索，不能按词直接判定事实错误 |
| 垃圾邮件案例只报告总体准确率 | 教学制品数量足够，但门禁不判断指标是否适配数据分布和错误代价 | 对分类案例要求至少出现类别分布、混淆矩阵派生指标或错误代价中的一项 | 平衡且低风险的教学玩具例子可不展开全部指标，适合按案例风险分级 |
