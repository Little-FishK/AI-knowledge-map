# AI 知识地图 — 规格文档 v0.1（草案，待讨论/审批）

> 状态：草案。文中标 **【待定】** 的地方是需要你拍板的设计岔路，见文末《开放决策》。

## 1. 目标与非目标

### 目标
1. 整理对我（用户）有用的 AI 概念与知识，**核心价值在于展现概念之间的联系**，而不只是一堆卡片。
2. 半自动捕捉与更新：把网址/视频/文档丢进来，系统抽取概念+连线，生成可审核的入库提案。
3. 分层：**基础层**（AI 基础知识，稳定、少变）与**活跃层**（前沿信息，高频变动）。
4. 形态：纯静态网页——双击即开，也能部署分享（个人用 + 对外展示）。

### 非目标（至少 v1 不做）
- 不做多人协作/账号系统。
- 不做常驻后端服务（入库是离线构建步骤，不是在线服务）。
- v1 不做全自动定时抓取（先半自动，验证后再升级）。

## 2. 核心设计原则

1. **稳定骨架 + 动态卫星**，不做"一张全景大图"。基础层是人工审校的稳定骨架；活跃层是自动挂载、带时间衰减的卫星。
2. **联系是一等公民**：边（关系）是有类型、有方向的，不是无意义的连线。
3. **展示与入库分离**：静态页只读 `graph.json` 渲染；入库是把资料变成 `graph.json` 的 diff，两者解耦，便于以后升级自动化而不动展示层。

## 3. 知识结构（本项目的核心）

### 3.1 节点（概念）粒度
一个节点 = **一个可命名、有独立身份、值得单独一张卡片、能与其他概念连线的概念**。
- 合适：注意力机制、Transformer、RAG、扩散模型、PPO、梯度下降、过拟合、词嵌入。
- 太粗（拆开）：整个"深度学习"——应作为**域/分区**而非单节点。
- 太细（合并进父节点）：softmax 的温度参数——并入"softmax/采样"节点。

### 3.2 域 / 分区（给地图划"大区"）—— 按用途/场景（D3 已定）
**大区按"我怎么用 AI"来分，不按学科。** 关键洞察：用途分区与树骨架会打架——像 Transformer/嵌入这种概念是所有用途共享的，不属于任何单一用途。用**分层**化解：设一块**共享基础区**当公共底座，其余为**用途大区**，用途节点用跨边连回基础区。

初版大区（可增减/改名）：
1. 🧱 **基础/共享** (foundations)：跨用途的稳定底座——Transformer、注意力、嵌入、训练、梯度下降… 基础层主要住这里。
2. 💻 **编程与 Agent** (coding)：代码辅助、工具调用、Agent 编排、MCP…
3. 🔧 **应用搭建** (building)：RAG、微调、提示工程、评测、部署、量化…
4. 🎨 **内容生成** (generation)：文本/图像/音频/视频生成…
5. 📰 **追前沿** (frontier)：新模型/新论文/新项目——活跃层重灾区。
6. ⚖️ **安全与对齐** (safety)：对齐、越狱、评测、可解释性——横切关注点。

> `domain` 字段取以上标识（foundations/coding/building/…）。用途大区里的节点，其 `primary_parent` 可指向本区入口或直接指向基础区的某概念。

### 3.3 边（关系）类型 —— 精而少
关系类型保持 6~8 种，否则无法维护。建议集合【待定，见开放决策 D1】：

| 类型 | 方向 | 含义 | 例子 |
|---|---|---|---|
| `is-a` | 有向 | 是一种 | Transformer —is-a→ 神经网络架构 |
| `part-of` | 有向 | 是…的组成部分 | 注意力 —part-of→ Transformer |
| `prerequisite` | 有向 | 前置知识（学习路径用） | 线代 —prereq→ 反向传播 |
| `uses` | 有向 | 使用/依赖 | RAG —uses→ 词嵌入 |
| `variant-of` | 有向 | 是…的变体/改进 | GRPO —variant-of→ PPO |
| `enables` | 有向 | 使…成为可能 | Transformer —enables→ 大语言模型 |
| `contrast` | 无向 | 常被对比/替代关系 | RAG —vs→ 微调 |
| `related` | 无向 | 弱相关（慎用兜底） | — |

方向性很重要：`is-a`/`part-of`/`prerequisite`/`variant-of`/`enables` 是有向的，渲染时用箭头。

**D1 已定：全部类型都展示。** 8 种边全渲染，用**颜色区分类型**（而非隐藏某些），每种类型可单独开关过滤。默认视图仍只画基础层主干上的边，防毛线球靠"逐层揭开"而非"隐藏边类型"。

### 3.4 分层机制 —— 叠层模型（按稳定度纵向堆叠）
**层级不是话题的属性，而是"稳定度"的属性。而且不是二分，是纵向叠层：越上层越新、越易变。活跃层不排斥基础层，而是"高于"它。**

```
   ▲ 越上层越新、越易变
   │  活跃层-L2   最新新闻 / 项目 / 案例（天~周）
   │  活跃层-L1   已站稳的新技术 / 新概念（月~季）
   │  基础层      教科书级稳定知识（年）
   └───────────────────────────
```

- **基础层 (base)**：教科书级、以"年"为尺度才变化。人工审校，数量克制（首版 30~60 个）。默认全程可见的骨架。
- **活跃层-L1 (emerging)**：已站稳的新技术/新概念（月~季）。多以**新节点**形式出现，挂在基础节点上。
- **活跃层-L2 (news)**：最新新闻/项目/案例（天~周）。多以**动态条目**形式附着在某概念的详情页里，不一定成节点。带 `timestamp` + `heat`，随时间衰减（变暗/下沉/归档）。

字段上用 `layer: base | emerging | news` 表达三层。

**关键机制：层级会向下沉淀（升/降级）**
- 新捕捉的内容默认进**活跃层**（news 或 emerging）。
- 若被证明持久（多次复现、成为公认基础），可**下沉**为更稳定的一层（news→emerging→base；如 RAG 从 2020 前沿→今天近似基础）。
- 升级/降级是**人工确认**的动作（系统只给建议）。【待定，见开放决策 D2：升级触发规则】

### 3.5 节点数据模型
```jsonc
{
  "id": "transformer",                 // 稳定唯一 id（kebab-case）
  "title": "Transformer",
  "aliases": ["自注意力网络", "self-attention network"], // 供入库去重匹配
  "layer": "base",                     // base | emerging | news
  "domain": "architectures",
  "primary_parent": "neural-networks", // 主干树的唯一父节点（借鉴 aiknowledgemap 的层级导航）
  "summary": "基于自注意力的序列建模架构…", // 一句话，卡片正面
  "body": "（可选）更长的说明，markdown",
  "tags": ["nlp", "attention"],
  "sources": [                          // 来源，可点开
    { "type": "url|video|doc", "title": "Attention Is All You Need", "ref": "https://…" }
  ],
  "heat": 0.0,                          // 活跃度/重要度，驱动亮度与排序
  "status": "active",                   // active | archived
  "createdAt": "2026-07-13",
  "updatedAt": "2026-07-13"
}
```
边：
```jsonc
{ "from": "attention", "to": "transformer", "type": "part-of", "label": "（可选）" }
```
存储：首版单文件 `data/graph.json`（`{ nodes: [], edges: [] }`）。规模变大后可拆 `base.json` + `active.json`。

## 4. 半自动入库流程
1. 你提供资料（网址/视频链接/文档路径）。
2. 抽取（用 Claude）：识别概念 → 与现有节点做**去重匹配**（title/aliases + 语义相似）→ 判定层级（默认活跃）→ 生成到现有节点的候选边。
3. 产出**可审核的 diff 提案**（新增哪些节点/边、更新哪些字段、附来源），而非直接写库。
4. 你审核（改/删/确认）→ 合并进 `graph.json`。
5. 静态页重新加载即生效。

> 去重匹配是技术难点：同一概念不同叫法要能合并，避免图里长出重复节点。首版用"标题+别名精确/模糊匹配"，不够再加嵌入向量。

## 5. 视觉与交互
**结构：树骨架 + 跨边（借鉴 aiknowledgemap 的树，补上它缺的联系）**
- **主干树**：每个节点有唯一 `primary_parent` → 干净、可导航、天然形成"地图大区"（这是 aiknowledgemap 的长处）。
- **跨边**：在主干之上叠加 3.3 的有类型跨分支连线 → 这才是"概念间的联系"（这是 aiknowledgemap 缺的）。默认淡显/可开关，避免糊成毛线球。

**交互（你的 D4 决定）：点击 → 卡片 → 详情页**
1. 点节点 → 弹出**概念卡片**：概念定义、信息来源、用途、"查看详情"入口。
2. 卡片 →**详情页**：更丰富内容，含相关新闻 / 项目 / 案例（活跃层-L2 的主要落脚点）。

**视图控制**
- 默认视图：只显示**基础层骨架**（主干树 + 淡显跨边），按域分区着色，布局稳定。
- 逐层揭开：可切换显示 emerging / news 层；聚焦某概念时突出它挂载的活跃内容（亮度=recency/heat）。
- 顶部：搜索、按层过滤（基础/L1/L2）、按域过滤、跨边开关、时间轴（活跃层"最近 N 天"）。
- 防毛线球：默认只渲染 base 主干；跨边与活跃层按需揭开；域给出"地图大区"。

## 6. 技术选型
- 单个/少数几个静态文件，**Cytoscape.js** 做图渲染（同时支持树布局与网状跨边、聚焦展开、可离线内嵌）。
  - 备选：aiknowledgemap 用的 **D3.js v7**。D3 树很适合纯层级，但我们要"树+跨边+分层"，Cytoscape 更省事。
- 无构建工具亦可（原型可单 HTML 内嵌 JS/JSON）；若后续复杂可加轻量打包。
- 数据 = 本地 JSON 文件。入库脚本以后可做成 Python/Node 离线脚本。

### 6.1 先例参考：aiknowledgemap.org（已调研）
- 开源：`github.com/gustavomartinellidev/aiknowledgemap`，Vanilla JS + D3.js v7 + 单个 `data.json`，GitHub Pages 托管。
- 结构：**严格层级树**（`AI → Machine Learning → Data → …`），节点 schema 极简：`name` + `type`(folder/category/…) + `short_definition` + `children[]`。
- **可借鉴**：静态形态、简洁节点 schema、人工审校的干净层级、按 type 着色。
- **它的短板（正是我们要补的）**：纯树 = 一个节点只有一个父亲，**无法表达跨分支联系**（违背需求#1）；无分层、无来源流、无自动更新；内容偏学术 ML 管线、横向窄。
- **我们的改进**：主干树（继承其长处）+ 跨边（补其短板）+ 叠层（基础/活跃）+ 卡片→详情页（放来源/新闻/项目/案例）。

## 7. 里程碑
- **M0 原型**：手填 15~20 基础节点 + 若干活跃卫星，跑通"分区骨架 + 点击展开 + 详情面板"，验证结构好不好用。
- **M1 入库半自动**：单条资料→diff 提案→合并流程跑通。
- **M2 打磨/分享**：视觉打磨、时间衰减、搜索过滤完善，可对外展示。
- **M3（可选）升级**：定时抓取 → 全自动活跃层更新。

## 8. 决策记录
- **D4 ✅ 已定**：叠层模型（基础层在底，活跃层在其上再分 L1/L2），非二分；交互为 点击→卡片→详情页，详情页放新闻/项目/案例。（见 3.4 / 5）
- **D3 ✅ 已定**：大区按**用途/场景**分（基础/共享 + 编程与Agent + 应用搭建 + 内容生成 + 追前沿 + 安全对齐）；用共享基础区化解"用途分区 vs 树骨架"的冲突。（见 3.2）
- **D1 ✅ 已定**：8 种边**全部展示**，颜色区分类型、可单独开关；防毛线球靠逐层揭开而非隐藏边。（见 3.3）
