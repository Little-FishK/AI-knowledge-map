# AI 知识地图 — 规格文档 v1.0

> 状态：**已实现，2026-07-23 对齐当前版本**。历史设计取舍保留用于解释原因；D1–D7 均已闭合。发布状态见 [STATUS.md](STATUS.md)。

## 1. 目标与非目标

### 目标
1. 整理对我（用户）有用的 AI 概念与知识，**核心价值在于展现概念之间的联系**，而不只是一堆卡片。
2. 半自动捕捉与更新：把网址/视频/文档丢进来，系统抽取概念+连线，生成可审核的入库提案。
3. 用 `maturity: stable | evolving` 标记知识成熟度；具体新闻和版本信息只作为详情内容，不形成结构层。
4. 形态：纯静态网页——双击即开，也能部署分享（个人用 + 对外展示）。

### 非目标（至少 v1 不做）
- 不做多人协作/账号系统。
- 不做常驻后端服务（入库是离线构建步骤，不是在线服务）。
- v1 不做全自动定时抓取（先半自动，验证后再升级）。

## 2. 核心设计原则

1. **核心入口 + 可展开知识网**，不把全量关系网作为默认入口。核心节点负责导航，完整网络保留全部概念和关系。
2. **联系是一等公民**：边（关系）是有类型、有方向的，不是无意义的连线。
3. **展示与入库分离**：静态页只读 `data/graph.js` 渲染；入库是把资料变成可审核 diff，两者解耦，便于以后升级自动化而不动展示层。

## 3. 知识结构（本项目的核心）

### 3.1 节点（概念）粒度
一个节点 = **一个可命名、有独立身份、值得单独一张卡片、能与其他概念连线的概念**。
- 合适：注意力机制、Transformer、RAG、扩散模型、PPO、梯度下降、过拟合、词嵌入。
- 太粗（拆开）：整个"深度学习"——应作为**域/分区**而非单节点。
- 太细（合并进父节点）：softmax 的温度参数——并入"softmax/采样"节点。

### 3.2 域 / 分区（给地图划"大区"）—— 按用途/场景（D3 已定）
**大区按"我怎么用 AI"来分，不按学科。** 关键洞察：用途分区与树骨架会打架——像 Transformer/嵌入这种概念是所有用途共享的，不属于任何单一用途。用**分层**化解：设一块**共享基础区**当公共底座，其余为**用途大区**，用途节点用跨边连回基础区。

初版大区（可增减/改名）：
1. 🧱 **基础/共享** (foundations)：跨用途的稳定底座——Transformer、注意力、嵌入、训练、梯度下降… 基础层主要住这里。
2. 💻 **编程与 Agent** (coding)：代码辅助、工具调用、Agent 编排、MCP…
3. 🔧 **应用搭建** (building)：RAG、微调、提示工程、评测、部署、量化…
4. 🎨 **内容生成** (generation)：文本/图像/音频/视频生成…
5. 📰 **追前沿** (frontier)：新模型/新论文/新项目——活跃层重灾区。
6. ⚖️ **安全与对齐** (safety)：对齐、越狱、评测、可解释性——横切关注点。

> `domain` 字段取以上标识（foundations/coding/building/…）。结构关系全部由边表达，不再使用唯一父节点。

### 3.3 边（关系）类型 —— 精而少
当前固定使用 11 种关系类型：

| 类型 | 方向 | 含义 | 例子 |
|---|---|---|---|
| `is-a` | 有向 | 是一种 | Transformer —is-a→ 神经网络架构 |
| `part-of` | 有向 | 是…的组成部分 | 注意力 —part-of→ Transformer |
| `prerequisite` | 有向 | 前置知识（学习路径用） | 线代 —prereq→ 反向传播 |
| `uses` | 有向 | 使用/依赖 | RAG —uses→ 词嵌入 |
| `variant-of` | 有向 | 是…的变体/改进 | GRPO —variant-of→ PPO |
| `enables` | 有向 | 使…成为可能 | Transformer —enables→ 大语言模型 |
| `constrains` | 有向 | 约束/限制了… | 上下文窗口 —constrains→ Agent 记忆 |
| `mitigates` | 有向 | 缓解/减轻了… | RAG —mitigates→ 幻觉 |
| `threatens` | 有向 | 威胁/攻击… | 提示注入 —threatens→ Agent |
| `contrast` | 无向 | 常被对比/替代关系 | RAG —vs→ 微调 |
| `related` | 无向 | 弱相关（慎用兜底） | — |

方向性很重要：`is-a`/`part-of`/`prerequisite`/`variant-of`/`enables`/`constrains`/`mitigates`/`threatens` 是有向的，渲染时用箭头。

**D1 已定（2026-07-19 修订）：11 种边全部展示。** 原定 8 种，在 M0 梳理跨边种子时发现最有价值的一批关系无法表达（"RAG 缓解幻觉"、"上下文窗口约束 Agent 记忆"、"提示注入威胁 Agent"），用 `related` 兜底等于丢掉信息，故扩为 11 种。全部渲染，用**颜色区分类型**（而非隐藏某些），每种类型可单独开关过滤。防毛线球靠聚焦模式与过滤，而非隐藏边类型。

### 3.4 成熟度标签 —— 取代三层结构（D4 于 2026-07-19 再次修订）

> **为什么取消三层结构**：原设计是 base / emerging(L1) / news(L2) 三层叠层，层级会 gate 默认视图、并隐含"先学基础层"的路径。
> 讨论后发现它的作用要么是弱的、要么已被别的机制替代：
> - **更新效率**（冻结 base 少扫描）——其实由 M1 的「增量 diff」实现，不依赖冻结 base；冻结反而带来 base 与新内容脱节的风险。
> - **默认视图入口**——已由**核心视图**（§5，`core` 列表）接管。
> - **学习路径**——已由**边类型**（`prerequisite`/`enables`/`part-of`）精确表达，比粗糙的三层好。
> - **历史证据**：取消前的 53 个节点里有 51 个 base、2 个 emerging、0 news——三层结构在实际内容上几乎不承重。当前 129 个节点直接使用 maturity 标签，其中 stable 107、evolving 22。
>
> 唯一真正不可替代的作用是**「这个知识有多确定/多易过时」**（core=重要度、边=关系、heat=活跃度都表达不了）。故把它从「结构层」降为一个**轻量标签**。

- **`maturity: stable | evolving`**（可选，缺省 = stable）。
  - `stable`：教科书级、已成共识、以"年"为尺度才变。**不特殊标记**（默认态）。
  - `evolving`：较新、仍在演进的概念。图上用**虚线琥珀色描边**标出，详情页显示「演进中」小标签。
- **它不 gate 视图、不排学习顺序**，只是节点上的一个信号。
- **news（时效性新闻/项目/案例）不进节点**：一直以来都作为节点详情页里的 `activity` 条目存在（带 `date`），与 maturity 无关。
- 成熟度的升降级仍是**人工确认**动作（入库提案给建议，见 `docs/INGEST.md`）。**原开放决策 D2 至此闭合**——不再需要"层级沉淀规则"，只需在审核时改一个标签。

### 3.5 节点数据模型
```jsonc
{
  "id": "transformer",                 // 稳定唯一 id（kebab-case）
  "title": "Transformer",
  "aliases": ["自注意力网络", "self-attention network"], // 供入库去重匹配
  "maturity": "evolving",              // 【可选】stable(缺省) | evolving，仅作成熟度标记（见 3.4）
  "domain": "architectures",
  "summary": "基于自注意力的序列建模架构…", // 一句话，卡片正面
  "body": "按是什么→机制→影响→用法组织的正文",
  "cases": [{ "title": "案例", "text": "…" }],
  "sources": [                          // 来源，可点开
    { "type": "url|video|doc", "title": "Attention Is All You Need", "ref": "https://…" }
  ],
  "heat": 0.0,                          // 活跃度/重要度，驱动亮度与排序
  "createdAt": "2026-07-13",
  "updatedAt": "2026-07-13"
}
```
边：
```jsonc
{ "from": "attention", "to": "transformer", "type": "part-of", "label": "（可选）" }
```
存储：单文件 `data/graph.js`（`window.GRAPH = { meta, core, positions, domains, edgeTypes, nodes, edges }`）。用 `graph.js` 而非 `graph.json` 是为了 `file://` 双击即开（浏览器禁止 fetch 本地文件）。

## 4. 半自动入库流程
1. 你提供资料（网址/视频链接/文档路径）。
2. 抽取（由当前协作 AI 完成）：识别概念 → 与现有节点做**去重匹配**（title/aliases + 语义判断）→ 建议成熟度 → 生成到现有节点的候选边。
3. 产出**可审核的 diff 提案**（新增哪些节点/边、更新哪些字段、附来源），而非直接写库。
4. 你审核（改/删/确认）→ 合并进 `data/graph.js`。
5. 静态页重新加载即生效。

> 去重匹配是技术难点：同一概念不同叫法要能合并，避免图里长出重复节点。首版用"标题+别名精确/模糊匹配"，不够再加嵌入向量。

## 5. 视觉与交互
**结构：网状图（D6，2026-07-19 修订 —— 原为"树骨架 + 跨边"）**

> **为什么改**：原设计继承自 aiknowledgemap 的严格树，每个节点必须有唯一父节点，跨边只是"叠加在树之上、默认淡显"的补充。
> 但这与本项目的核心目标（§2.2 联系是一等公民）直接冲突——**我们要的就是联系，却把联系当成需要藏起来的东西**。
> 且 2026-07-19 的调研证实：aiknowledgemap（树）、roadmap.sh（线性路线图）、llm-course（课程目录）三个源**全无跨边**，
> 它们缺的正是网。没有理由继承它们的形状。

- **图就是网**：概念可以有多个"上级"，多父关系用 `part-of` / `is-a` 边直接表达，不再强行选一个父亲。
- **布局**：力导向（Cytoscape `fcose`），大区靠**颜色 + 聚类**区分，而不是靠树的分叉。
- **自动排布门禁**：新增节点缺少坐标时，全图重新参与 fcose，再执行确定性的碰撞修正；同区节点的视觉框不得重叠，任意节点不得被另一个节点遮挡超过 3/4。浏览器与 Node 共用 `assets/layout-quality.js`，由 `tools/validate.js` 阻断违规提交。
- **默认视图 = 核心视图**（D7，2026-07-19；2026-07-21 扩充）：只显示 `core` 列表里的 28 个骨干概念，点任一节点揭开其邻居、逐层展开。全量图当前有 129 个节点、411 条边；核心视图既保持清爽，又给出阅读入口。

**防毛线球的手段**（从"默认藏边"换成"核心视图 + 主动降噪"）：
1. **核心视图**：默认只显示骨干，点击逐层展开。主力手段。
2. **聚焦模式**（默认开）：点中一个节点 → 只显示它的 N 跳邻域，其余淡出。
3. **按边类型过滤**：11 种边各自可开关。
4. **按大区过滤**：整个大区可开关。

> 当前规模：核心视图 28 节点；「全部」129 节点依赖聚焦和过滤使用。相关交互已实现。

**交互（D4 决定）：点击 → 详情页**
1. 点节点 → 右侧**详情页**：定义、详细说明（是什么/机制/约束/对策四段）、案例、带类型的相关知识、动态（`activity`）、来源。
2. 正文里的概念用 `[[node-id]]` 内联链接，可直接点跳。
3. 每个理解原理页可标记“已学习”，学习状态仅保存在浏览器本地；“官方推荐”用 9 个学习前置层级覆盖全部 129 个节点，层级不等同于六大区。

**视图控制**
- 默认：核心视图 + 聚焦开 + 全部大区/边类型可见。
- 顶部搜索（标题/别名/摘要）；左栏：核心/全部切换、大区过滤、边类型过滤、聚焦跳数。
- `evolving` 节点用虚线琥珀描边标出（成熟度标签，见 3.4），不 gate 视图。

## 6. 技术选型
- 纯静态文件，**Cytoscape.js** + fcose 做网状图渲染、聚焦与展开，依赖全部本地内嵌。
- 无构建步骤、无后端，`index.html` 可直接打开。
- 数据 = 本地 `data/graph.js` 与 `data/software.js`。入库目前是会话内、人工审核的离线流程。

### 6.1 先例参考：aiknowledgemap.org（已调研）
- 开源：`github.com/gustavomartinellidev/aiknowledgemap`，Vanilla JS + D3.js v7 + 单个 `data.json`，GitHub Pages 托管。
- 结构：**严格层级树**（`AI → Machine Learning → Data → …`），节点 schema 极简：`name` + `type`(folder/category/…) + `short_definition` + `children[]`。
- **可借鉴**：静态形态、简洁节点 schema、人工审校的干净层级、按 type 着色。
- **它的短板（正是我们要补的）**：纯树 = 一个节点只有一个父亲，**无法表达跨分支联系**（违背需求#1）；无分层、无来源流、无自动更新；内容偏学术 ML 管线、横向窄。
- **我们的改进**：用途分区的网状图 + 有类型的跨边 + 核心视图与聚焦降噪 + 详情页/深读页 + 软件目录。
