# AI 知识地图 · 软件目录收录标准

> 概念地图有 [NODES.md](NODES.md) 定「什么该成为节点」；软件模式（`data/software.js`）此前只有一句「少而精、门类全面」，缺一份明确判据，导致 DeepSeek 这类旗舰被埋进分组卡、Codex/Antigravity 这类新工具漏收。此文补上这份判据，是软件侧的唯一权威口径。

## 一、目的与边界

软件目录回答的是「**要做某件事，用什么工具**」。它和概念地图互补：概念解释「是什么、为什么」，软件指向「拿什么上手」，每张卡的 `concept` 字段链回相关概念节点。

一条贯穿始终的规矩（沿用旧约定）：**只记不易过时的判断——它是什么、最擅长什么、和同类的区别；不记版本号、价格、榜单名次、参数**。软件迭代快，把易变的东西写进去等于给自己挖坑。

## 二、什么进「独立卡」

一句话测试：**「要做这门类的事，绕不绕得开它？它有没有一句话能说清的独特定位？」**

**判定顺序：先过①②③三道闸门——命中任一即必收一张独立卡；三条都不命中，再看④由编辑自行判断。** （`concept` 能指向真实节点是技术前提，不是收录理由。）

**闸门（命中任一即必收）**

1. **① 品类定义者 / 开创者**（最强信号）：某门类里绕不开的名字，或开创、定义了一种玩法。例：ChatGPT、Cursor、Perplexity、Midjourney。
2. **② 有独特定位**：能一句话说清「它和同类不一样在哪」。例：DeepSeek＝开源强推理、opencode＝模型无关的开源编程 Agent、Ideogram＝图里能准确写字。没有差异化的跟随者不靠这条进。
3. **③ 门类覆盖需要**：这门类还缺一个代表，它补得上（哪怕不是最大牌）。例：编程门类缺 agentic 一路 → Codex / Antigravity。

**佐证信号（不是闸门，由编辑判断）**

4. **④ 持久影响力 / 使用广度**：被广泛使用或讨论、且已经站住。用它在候选里排优先级、把「昙花一现」筛掉——但**它不单独决定收不收**：用户众多却毫无独特定位的套壳，不因人多而进；用户不多却绕不开的专业工具，不因人少而删。

> **不拿「使用人数」当硬门槛**：它测不准（无可比的公开 MAU、中外口径不一）、变太快（按人数排名就得频繁重排，违背「只记不易过时的判断」）、且偏向消费级规模而埋没品类定义者与专业工具。人数只在 ④ 当软信号。

## 三、什么只作「分组卡」或正文提及

- **同品类的一串近似产品**：合成一张分组卡，卡名用 `A / B / C 等`，正文点出各自侧重（如 `Windsurf / Cline / Aider`、`可灵 / 即梦 / Pika 等`）。这是控制规模、又不丢信息的主力手段。
- **某旗舰的次要产品线**：写进该公司主卡的正文，不单列（如 MiniMax 的语音/音乐并入海螺卡正文）。
- **一款产品的具体功能**：写进它自己的卡正文，不拆成新卡。

## 四、什么不收（无论多热）

| 类别 | 例子 | 说明 |
|---|---|---|
| 纯套壳 / 无差异 | 又一个「AI 写作助手」 | 没有独特定位，收了是噪声 |
| 昙花一现 / 未成气候 | 上线三个月、几乎无人用 | 等它站稳再收，避免频繁增删 |
| 纯基础模型本身 | GPT-5、Claude 4.x 这类**模型**而非**产品** | 模型归概念侧 `model-families`；面向用户的产品才进目录 |
| 价格 / 榜单名次 | 「某模型登顶某榜、每月 $20」 | 易过时，不进正文；真要提，作背景一句带过 |

> **型号版本是例外（2026-07-20 用户定）**：单一厂商、有清晰型号线的卡，用 `models` 字段列**当前主要型号**（`{name, note}`，note 是一句定位如「旗舰/高性价比/推理」），详情页会标「截至 YYYY-MM」。它明知会过时——所以要**定期按官方页面重刷、淘汰的老型号删掉**，且只加在单厂商卡上（分组卡/聚合类/单模型工具不加）。价格和榜单仍不进。

> 方向性原则（和概念侧一致）：门类要**齐全**，每个门类收**最具代表性的几个**；宁可把跟随者合成分组卡，也不漏掉品类里的定义者。目标是"少而精、门类全"，不是"越多越好"——软件比概念更易过时，克制是特性不是缺点。

## 五、门类

软件模式用自己的 12 个门类（不复用概念地图六大区），见 `data/software.js` 的 `categories`：对话助手 / AI 搜索与研究 / AI 编程 / Agent 与自动化 / 图像生成 / 视频生成 / 音频·语音·音乐 / 写作与文本 / 设计·创意·演示 / 生产力与办公 / 开发者基础设施 / 本地运行与开源。

## 六、写法约定

- 每张卡：`summary` 一句话定位；`body` 一小段讲「是什么 + 最擅长什么 + 和同类的区别」，介绍文字**一律原创**。
- 可选 `models`（仅单厂商卡）：`[{ name, note }]` 列当前主要型号，详情页自动标「截至 2026-07」。重刷时对照官方型号页，删淘汰款。
- 正文提到概念节点用 `[[node-id]]` 内联链接（点击跨模式跳转到概念）；提到本目录其他软件也可用 `[[software-id]]`。
- `concept` 必须指向一个真实存在的概念节点（改完用 `tools/validate-software.js` 校验，拦悬空 `concept` 和坏 `[[引用]]`）。

## 七、使用教程页

软件可在 `data/tutorials.js` 注册独立“使用教程”页；注册后，软件详情顶部自动出现教程按钮。教程资源按 Bilibili、小红书、YouTube、GitHub、文章与文档分类，写作与复核规则见 [TUTORIALS.md](TUTORIALS.md)。教程页记录的是可迁移的方法和来源，不把易变的按钮、价格或第三方配置写成永久事实。
