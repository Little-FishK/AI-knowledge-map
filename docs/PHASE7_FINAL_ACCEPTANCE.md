## 2026-09-09 OTP 错误提示修复

用户确认第二设备重新获取验证码后仍出现 `Token has expired or is invalid`，不能归因于复用或过期。后台只读核对：OTP 长度 6，有效期 3600 秒。Supabase Auth 的 `verifyUserAndToken` 将令牌不匹配与过期统一返回 `otp_expired`；前端提示“验证码无效或已过期，服务端未区分具体原因”，不伪造更精细结论。

新增重发、更换邮箱、目标邮箱展示、发送后 60 秒冷却、请求期间禁用及重复提交防护；限流、连接/超时、输入格式错误分别解释。浏览器回归覆盖失败后保留表单、重复验证只发一次、冷却、重发清空旧输入和限流分类。`npm run test:app`、`npm run test:website` 与生产产物验证通过。发布回归中的 canonical 断言已跟随实际自定义域名更新。

### 登录成功后验证码框残留

随后用户报告第二账号其实显示已登录且“读过”已保存。代码确认：旧 UI 等待 verifyCode 内部的云端进度读取才关闭验证码框，认证已成功时，慢读取或失败仍可留下验证码框。此前版本允许再次提交，由此可能产生已消耗验证码的错误；无法仅凭当前证据断定这就是用户那一次请求的全部经过。

修复：认证状态建立立即隐藏验证码框；显示“已登录，正在读取云端进度”；进度读取失败保留已登录状态并显示同步错误，不作为 OTP 错误抛出。同账号 SIGNED_IN 与 verifyOtp 返回不重复启动云端读取。已登录状态禁止再次提交残留验证码表单。
