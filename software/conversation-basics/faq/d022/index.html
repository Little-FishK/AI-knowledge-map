怎样在开始前约定投入时间、费用、尝试次数和输出深度？

D022 · D 组织复杂过程 · 资源预算与停止条件

回答要点完整解答引用文献

回答要点

只约定与你有关的资源限制，并区分“希望控制在多少”与“系统必须在何处停止”。 时间、费用、尝试次数和输出深度不是同一个指标；答得短也可能经过很多搜索，限制字数不能代替限制成本。

完整解答

开始前可以明确：先完成哪些必需成果、可用的时间或费用上限、怎样计算一次尝试，以及到达上限时交付什么。截止时间要给日期和时区；次数要区分“修改一轮”与“调用一次工具”，否则同一个数字会产生不同理解。

官方功能也体现了这种区别。Claude 的 task budgets 是供模型自我安排的建议性 token 预算；Managed Agents 的 session budgets 则由平台在模型请求之间检查消费，达到上限后停止新增请求，已经在途的请求及相应工具动作仍可能完成。因此，预算功能的计量范围和执行时机也需要看清。任务预算文档；会话预算文档

例如：

本次先完成能交付的一页方案和关键依据，不做全面综述。资料搜集最多两轮；一轮指针对当前缺口的一批查询。已有依据足以支持方案就进入写作，第二轮后仍未解决的点列为待核实。不得启动付费服务；交付时说明实际完成范围和剩余缺口。

这里限制的是搜集范围，AI 仍应完成整理、核对与交付，而不是用完查询次数就留下散乱材料。若必须严格控制费用，需要在付费平台设置实际限额；若工具不能读取时间或用量，应明确哪些只能估算。

结束时看实际用量记录与成品质量，不用模型自报的“投入很多”衡量工作量。增加预算前，也应说明新增投入预计解决哪个具体缺口，避免把“再试一次”变成没有停止条件的循环。
