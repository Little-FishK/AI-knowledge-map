阅读说明

本章面向已经会用自然语言描述需求的用户，目标是完成接入，让 Agent 直接操作 Photoshop。接通后，可以在对话中要求它检查图片、整理图层、修改文字、调整画面和导出文件，再根据结果继续提出修改意见。主要需要掌握的是接入与使用方法。

选择接入方式

有 Photoshop 内置助手和外部 Agent 两条路线：

  • Photoshop 官方 AI Assistant：在 Photoshop 内直接输入要求，无需自行搭建 MCP。核对时，Adobe 仍将桌面端功能标为 Photoshop（Beta）早期测试功能。可在 Creative Cloud 中安装 Photoshop（Beta），打开图片后，点击应用右上角的 AI Assistant 图标进入对话；具体开放情况以当前版本与账户中的入口为准。官方介绍与入口说明
  • 外部 Agent + MCP：在支持本地 MCP 工具调用的 AI 客户端中对话，由连接程序把操作传给 Photoshop。这里的 MCP 可以理解为让 Agent 调用 Photoshop 工具的接口。外部接入可选择下面任意一个项目。
项目控制方式项目说明中的能力
drmedia/photoshop-mcpPhotoshop UXP 插件桥接文档、图层、选区、截图、保存与导出等操作
airtaxi/PhotoshopMcpServerWindows COM 自动化向支持 MCP 的 Agent 暴露 Photoshop 自动化操作，包括文档与图层信息、导出，以及执行 Photoshop 脚本

下面给出 Windows 接入步骤。两套外部方案选一套即可；它们都是第三方项目，版本要求与操作范围分别以各自说明为准。

接入方案 A：drmedia/photoshop-mcp（UXP 插件）

1. 准备运行环境

需要 Git、Node.js 22.12 或以上、Photoshop，以及 Adobe UXP Developer Tool。项目声明 Photoshop 最低版本为 25.0，作者记录的实际验证版本为 27.8；macOS 尚缺少完整验证，本节按 Windows 编写。项目环境要求

UXP Developer Tool 可通过 Creative Cloud 安装，首次启动时按提示启用 Developer Mode，允许加载开发中的插件。Adobe 安装说明

2. 下载并构建项目

以下使用 C:/AI/Tools 作为示例安装目录。在 PowerShell 中依次执行：

New-Item -ItemType Directory -Path C:/AI/Tools -Force
Set-Location C:/AI/Tools
git clone https://github.com/drmedia/photoshop-mcp.git
Set-Location C:/AI/Tools/photoshop-mcp
npm install
npm run build

构建会生成服务器与插件需要的文件。该项目核对时尚未发布到 npm，应按源码方式安装。构建说明、发布状态说明

3. 把插件加载进 Photoshop

  1. 启动 Photoshop 和 UXP Developer Tool。
  2. 在 Developer Tool 中选择 Add Plugin，找到 C:/AI/Tools/photoshop-mcp/photoshop-uxp/manifest.json。
  3. 点击 Load，再在 Photoshop 的“插件 / Plugins”菜单中打开 Photoshop MCP 面板。

保留 Photoshop 与插件面板，接着配置 AI 客户端。插件加载说明

4. 在 Agent 客户端中添加 MCP 服务器

客户端必须支持启动本地 stdio MCP 服务器。以下以 Claude Desktop 的配置方式举例：打开 %APPDATA%\Claude\claude_desktop_config.json，把下面的服务器条目加入配置；已有其他服务器时，将其合并进现有 mcpServers 对象。

{
  "mcpServers": {
    "photoshop-uxp": {
      "command": "node",
      "args": [
        "C:/AI/Tools/photoshop-mcp/packages/mcp-server/bin/photoshop-mcp.js"
      ],
      "env": {
        "PHOTOSHOP_MCP_BRIDGE": "uxp",
        "PHOTOSHOP_MCP_PROFILE": "full",
        "PHOTOSHOP_MCP_ALLOW": "read,edit,external",
        "PHOTOSHOP_MCP_EXTENSIONS_ENABLED": "none"
      }
    }
  }
}

将安装路径换成自己的实际路径，保存后重启客户端。服务器由客户端按配置启动，无需再手工运行一个 npm start 实例。

这些设置分别表示：连接真实的 UXP 插件、显示完整 Photoshop 工具、允许读取与编辑以及另存/导出文件、关闭本章用不到的扩展。项目默认只允许 read,edit，所以这里加入了保存与导出需要的 external；覆盖原文件等操作属于另一权限级别，不包含在此示例中。项目启动配置、环境变量与权限说明、Claude Desktop 配置位置示例

使用其他 Agent 时，填写相同的启动命令、参数和环境变量，但采用该客户端自己的配置格式。例如 VS Code 可通过命令面板运行 MCP: Add Server → Command (stdio) 添加；不同客户端的顶层字段可能是 mcpServers 或 servers，不能直接混用。VS Code 官方接入说明

5. 连接插件，并选择输出目录

回到 Photoshop MCP 面板，点击 Connect。插件加载成功后，默认仍不会主动连接，所以这一步需要单独执行。正常连接后，面板会显示桥接状态与端口；默认会在本机 8765–8774 端口中寻找服务器，通常无需手填端口。连接行为说明

如需保存或导出，在该面板中由用户选择并授权一个输出文件夹。Agent 随后提供文件名，例如 poster-v1.psd，文件会写入这个文件夹；此项目不接受由 Agent 任意指定完整输出路径。输出文件夹与保存规则

接入方案 B：airtaxi/PhotoshopMcpServer（Windows COM）

这条路线通过 Windows COM 调用 Photoshop，无需加载上述 UXP 插件。需要 Windows、支持 COM 自动化和 DoJavaScript 的 Photoshop，以及 .NET 10 SDK 或以上。具体安装与客户端配置见项目说明。

1. 下载并生成可执行文件

在 PowerShell 中执行：

New-Item -ItemType Directory -Path C:/AI/Tools -Force
Set-Location C:/AI/Tools
git clone https://github.com/airtaxi/PhotoshopMcpServer.git
Set-Location C:/AI/Tools/PhotoshopMcpServer
dotnet publish PhotoshopMcpServer/PhotoshopMcpServer.csproj -c Release -r win-x64 --self-contained

发布过程会构建项目。按照项目当前目录与目标框架，可执行文件位于下方配置所示位置。发布步骤、项目目标框架

2. 配置客户端并连接

同样以 Claude Desktop 为例，把服务器条目加入其配置：

{
  "mcpServers": {
    "photoshop-com": {
      "command": "C:/AI/Tools/PhotoshopMcpServer/PhotoshopMcpServer/bin/Release/net10.0-windows/win-x64/publish/PhotoshopMcpServer.exe"
    }
  }
}

换成自己的实际路径，保存并重启客户端，然后打开 Photoshop。其他 Agent 使用相同可执行文件作为本地 stdio 服务器的启动命令即可。可执行文件接入示例

此项目既提供读取文档、查询图层和导出的工具，也允许 Agent 编写并执行 Photoshop JavaScript。日常使用时直接描述任务即可；用户无需先自行编写脚本。工具清单

确认接入成功

在 Photoshop 中打开一张测试图片，在 Agent 客户端启用对应 MCP 工具，然后输入：

请实际调用 Photoshop 工具，读取当前文档名称、宽高和图层名称。只查询，先不要修改。

检查返回信息是否与 Photoshop 中的文档一致，并确认客户端出现了实际的工具调用记录。UXP 方案可以调用文档与图层查询工具；COM 方案可使用 GetActiveDocumentInfo 和 GetLayerInfo。仅显示服务器配置，或聊天中回复“已连接”，还不足以证明 Photoshop 已经接通。UXP 工具参考、COM 工具参考

随后可做一次小修改验证：

在当前文档最上方新建一个空白图层，命名为“连接测试”，完成后重新查询图层，告诉我它的名称与位置。

最后测试一次另存与导出，确认指定目录中确实出现文件。使用 UXP 方案时，可输入：

将当前文档另存为 connect-test-v1.psd，保留图层，再导出 connect-test-v1.png。保存到我在 Photoshop MCP 面板中选定的文件夹，告诉我各文件的保存结果。

以上三步分别验证读取、编辑和文件输出。完成后即可进入日常对话操作。

接入后怎样下达任务

已经会写提示词的用户，可以直接按“对象、修改要求、保留内容、交付结果”描述任务。例如：

把当前海报中名为“标题”的文字图层改成“秋季新品”，保留原字体、字号和位置。将结果另存为 poster-v1.psd，并导出 poster-v1.png。

看到结果后继续说“标题改成两行”“整体再亮一点”“只调整背景”即可。遇到对象不明确的图片，可以先要求 Agent 查询图层；使用 UXP 方案时，还可以要求它返回当前画面截图，再据此修改。

接入后的可操作范围取决于所选工具。例如，读取和调整图层、置入已有背景，与调用生成式填充是不同功能；是否能够生成新背景、使用某项新 AI 功能，应查看工具清单并实际验证。

常见接入问题

现象优先检查
客户端启动服务器失败，工具列表为空检查安装目录、构建产物和配置格式；UXP 方案确认 Node 可被客户端找到，安装运行环境后重启客户端
UXP 返回 PHOTOSHOP_NOT_CONNECTED确认 Photoshop 已打开、插件已 Load，并在面板中点击 Connect；确认客户端启动的是真实 uxp 桥接模式
能查询、能修改，但无法保存或导出UXP 方案检查 external 权限与面板输出文件夹；同名文件已存在时换用新文件名
COM 服务器已启动，但 Photoshop 操作失败先调用 IsPhotoshopRunning、GetPhotoshopVersion，核对本机版本是否支持项目要求的 COM 接口
某项功能没有工具或调用失败让 Agent 查看实际工具列表与错误信息；UXP 方案可调用 photoshop.diagnostics，按诊断结果处理
