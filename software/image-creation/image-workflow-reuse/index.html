阅读说明

本章围绕人物一致性、商品图、局部修改和图片放大，选取已有完整流程、配套说明与公开示例的方案。它们可作为复用起点，具体效果仍取决于输入素材与运行条件。本次于 2026 年 10 月 31 日核对资料和原始工作流配置，尚未进行本机图像生成验收。

人物一致性案例 IP-Adapter FaceID Plus v2

适用条件与边界

适合用一张人脸参考图练习同一人物在不同场景中的面部特征保持。输入先选清楚、无遮挡、脸部居中的单人图；这套流程主要约束脸部身份，不同时保证服装、体型、动作和场景一致。模型作者也说明身份一致性并不完美。

FaceID 模型卡明确限定研究用途，不应把这一案例作为可直接商用的人像方案。配套插件作者已将项目置于维护模式，复用时应记录能跑通的 ComfyUI 与插件版本，保留对应文件。用途与能力说明、插件安装与维护说明

资料与流程文件

  • 作者的 FaceID 工作流 JSON：保存为 JSON 后载入 ComfyUI。核对时该文件使用 SD 1.5 系列的 Realistic Vision V5.1 checkpoint，加载器选择 FACEID PLUS V2，输出起始尺寸为 512 × 512。
  • 模型文件与使用说明：SD 1.5 版与 SDXL 版分开，需选择同一模型家族的配套文件。
  • RunComfy 人物一致性教程：补充参考图准备、使用界面与效果示例；平台流程与作者 JSON 分别按各自说明使用。

复用步骤

  1. 下载作者 JSON 并载入。按插件 README 安装 ComfyUI_IPAdapter_plus，并在同一 ComfyUI 的 Python 环境安装 InsightFace。
  2. 准备 JSON 所用的 checkpoint。SD 1.5 分支使用 ip-adapter-faceid-plusv2_sd15.bin、配对的 ip-adapter-faceid-plusv2_sd15_lora.safetensors 与 README 指定的 ViT-H 视觉编码器。分别放入 models/ipadapter、models/loras、models/clip_vision；checkpoint 放入 models/checkpoints。InsightFace 的配套人脸模型按插件说明准备。
  3. 在 Load Image 选择自己的参考图，替换作者文件中的示例图片名；在 Checkpoint Loader 重新选择本机模型。统一加载器依赖文件命名，按 README 保留所需名称。
  4. 保留 FACEID PLUS V2 与其余起始配置，输入一个简单的新场景描述，先生成单张图片。确认参考图中的人脸被正常识别。
  5. 固定参考图、模型和其他设置，再改变场景或表现形式。面貌偏离时逐项比较参考图裁切、FaceID 影响强度与提示词，保存每次对比。
  6. 逐张检查五官、脸型、年龄感及侧面表现。服装或姿态有额外要求时，另行增加相应控制；不要把仅保持面部特征写成整个人物完全一致。

商品图案例 产品重新布光与背景协调

适用条件与边界

适合已有产品照片，希望更换展示环境或调整照明的任务。完整案例选用 Andrea Baioni 的 Product Relighting，RunComfy 页面提供 JSON 下载入口、图示和作者视频。必需输入为清晰主体图，背景和光照蒙版可以选填；这些条件及下述开关来自案例操作说明。

这类流程会重新生成或协调图像，输出应与原产品逐项比较外形、颜色、包装文字、标识和小零件。需要保持准确的标识或文字，可在后续精修时使用原素材恢复。

资料与流程文件

  • Product Relighting 完整案例与工作流 JSON 下载入口。
  • 作者配套视频：从案例页链接进入的操作演示。
  • IC-Light 原作者说明：核对重新布光模型、输入条件与相关组件要求。
  • IC-Light 的 ComfyUI 节点说明及本地基础工作流原始 PNG：供单独练习基础重新布光。它是另一套流程，不替代完整商品图流程。

完整商品图流程的复用步骤

  1. 在案例页下载 Workflow.json，或打开平台预配置环境。本地导入时，按该 JSON 的节点与模型清单补齐依赖；平台预配置环境不等于本机已经具备同样组件。
  2. 在 Input Images 组上传 Subject Image。需要指定背景时上传 Background，并打开 Background Switch；需要光照蒙版时上传 Light Mask，并打开 Light Mask Switch。没有上传时保留相应关闭状态。
  3. 在 Input Prompts 填写简洁的产品描述与光线描述，例如产品材质、颜色，以及柔和侧光或冷色轮廓光。先保留其余设置，生成一版。
  4. 对照原产品检查两种输出：Color Matched Result 与 Relit Result。它们分别便于观察颜色协调和重新布光后的表现。
  5. 需要调整背景变化幅度时，比较 Denoise 设置；需要调整明暗时，再按案例的结果组说明修改。每次只改变少量设置。
  6. 保存所选结果、输入素材和流程配置，再进入 Photoshop 检查或修复产品细节。

本地基础示例的运行条件

Kijai 的原始 PNG 内保存了 SD 1.5 分支的 photon_v1.safetensors、iclight_sd15_fc.safetensors 及 ImageResizeKJ 等节点配置。载入后需准备相应 checkpoint、ComfyUI-IC-Light 和所需 KJNodes；IC-Light 模型依节点说明放入 models/unet 下相应目录，再在加载节点中选择。替换示例输入图，在文本输入中描述主体和照明，先按原有约 512 像素配置练习；改用其他 checkpoint 应另作效果比较。

IC-Light 原作者还特别指出，原始演示中的 BRIA RMBG 1.4 限非商业使用；如工作流使用了抠图模型，商品用途应检查该组件的条件，不能仅凭 IC-Light 主项目的代码许可判断整条流程。

局部修改案例 ComfyUI 官方 Inpainting

适用条件与边界

适合整体画面已满意，只修改帽子、衣服纹理或背景杂物等局部区域。需要原图和标明修改区域的蒙版。基础练习采用官方指定的 512-inpainting-ema.safetensors，先使用约 512 像素输入跑通，暂不加入第三方节点。

原始流程文件名虽然包含 sd1.5，加载节点实际指定上述专用重绘文件；应以节点与模型要求为准，不能仅凭示例图片文件名判断模型版本。

资料与流程文件

  • 官方中文局部重绘教程：包含模型、输入图片、蒙版编辑与运行说明。
  • 可拖入 ComfyUI 的原始工作流 PNG。
  • 官方教程链接的模型文件页。
  • 维护者的局部重绘与扩图示例。

复用步骤

  1. 下载原始 PNG，拖入 ComfyUI 或用 Workflow → Open 载入。使用原文件，避免截图或图片压缩后丢失流程信息。
  2. 下载指定模型，放入 ComfyUI/models/checkpoints，在 Load Checkpoint 中选择它。先保留模板的采样设置。
  3. 在 Load Image 上传官方配套输入图，先运行一次带已有透明蒙版的示例。
  4. 换成自己的原图，右击 Load Image 中的图片，打开 Open in MaskEditor，覆盖需要修改的对象及衔接边缘，并保存蒙版。
  5. 输入对目标内容的描述，例如把帽子换成红色针织帽。检查图像和蒙版均连接到 VAE Encode (for Inpainting)，再执行生成。
  6. 比较修改区域、边缘与周围画面。出现接缝时先调整蒙版范围；要求不变的区域也应与原图比较，必要时在 Photoshop 用蒙版将修改结果合回原图。
  7. 保存原图、蒙版、提示词及工作流。更换为 SDXL 或其他重绘模型时，使用相应配套流程重新确认参数。

图片放大案例 ESRGAN 与 Real-ESRGAN 模型放大

适用条件与边界

适合构图已确定、需要增加像素尺寸的照片或插画。采用 ComfyUI 原生的模型放大流程，无需额外 SD checkpoint、提示词、LoRA 或随机种子。放大结果仍需检查文字、轮廓、五官和纹理；增加像素不能保证恢复原图中不存在的真实细节。

资料与流程文件

  • 官方中文放大教程及基础工作流原始 PNG。
  • 维护者的模型放大示例。
  • Real-ESRGAN 原作者的模型列表：提供照片与插画等用途的权重链接。它是可替换的放大模型来源，与官方示例默认使用的 4x-ESRGAN 分别识别。

模型选择参考

图片与目标可比较的模型
常规图像放大RealESRGAN_x4plus 或 RealESRGAN_x2plus
动漫与插画RealESRGAN_x4plus_anime_6B
优先降低耗时和显存占用realesr-general-x4v3；原作者说明其去模糊、去噪能力较有限

复用步骤

  1. 下载官方工作流原始 PNG 并载入。首次练习可按官方教程使用 4x-ESRGAN；也可从 Real-ESRGAN 原作者列表下载对应的推理权重，避免下载用于训练的 netD 文件。
  2. 将模型放入 ComfyUI/models/upscale_models，在 UpscaleModelLoader 中选择。原工作流保存的 RealESR/4x-ESRGAN.pth 是作者目录记录，需按本机实际文件重新选择。
  3. 在 Load Image 上传待处理图。确认图像与放大模型连接到 ImageUpscaleWithModel，再运行流程并保存输出。
  4. 以实际像素尺寸检查输出。4 倍模型会将宽和高分别扩大约 4 倍；例如 512 × 512 变成约 2048 × 2048。
  5. 放大后在 100% 显示下比较纹理、边缘、文字和面部特征。普通图片与动漫图片可分别比较模型，选择符合用途的结果。
  6. 若运行时显存不足，先用小图测试或降低输入尺寸；需要大图时再选择提供分块处理的配套实现，并检查块间衔接。原作者命令行工具提供 tile 设置，它不是上述基础节点图中的同名参数。
  7. 在继续制作中可把生成流程的图像输出接入这一放大流程，并记录放大模型名称、倍率和输出尺寸。

复用前的共同准备与结果记录

上述流程均先按各自原始配置运行，再替换输入。模型、LoRA、节点和输入素材通常不会随一个 JSON 文件全部打包。没有明确来源依据时，不给出统一的最低显存承诺；本地需求受模型、输入尺寸、精度、同时加载的组件与软件版本影响。RunComfy 等云端环境按平台当前运行配置和费用说明使用。

从官方模板开始时，可使用 Workflow → Browse Workflow Templates，按缺失提示补齐模型；作者分享的流程按 JSON 或原始 PNG 载入，再核对自定义节点。参考模板操作说明与缺失节点和模型排查。

建议每次保留以下记录，便于继续修改或比较候选：

记录项内容
流程来源页面、文件名、下载日期，以及能够确认的版本或提交
运行配置ComfyUI 与自定义节点版本、模型与配套文件、关键参数
输入与目标参考图、蒙版、提示词、需要保留和修改的内容
检查结果人物特征、产品细节、修改范围或放大纹理是否符合要求
实际投入耗时、运行错误和人工修正量

随机种子与参数相同也不保证跨环境完全一致，复现条件见 Diffusers 指南。用同一批素材比较多个候选，才能判断哪条流程更适合当前任务。
