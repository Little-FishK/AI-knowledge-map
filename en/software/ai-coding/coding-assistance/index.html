Chapter overview

AI can provide substantial help with the core stages of traditional programming.

Following the same five stages as Chapter 1, this chapter explains how AI can help and introduces methods and tools you can use directly.

1. Clarify the problem

A requirements clarification assistant can ask questions to establish your goal, use cases and constraints, then organize the answers into requirements that can guide the programming work.

NameHow it helps clarify requirements
Superpowers: Brainstorming skillAsks questions step by step to understand your goal, current situation and constraints, discusses possible approaches, then develops a design. The complete workflow instructions are publicly available. Project instructions
BMad: Analyst, named MaryA dedicated analyst role with workflows for brainstorming, research, user needs analysis and product briefs. BMad supports integration with several AI tools. Project documentation
GitHub awesome-copilot: PRD skillStarts with an interview about the problem, success criteria and constraints, then defines the scope and organizes a requirements document. Its public instructions can also inform a requirements clarification assistant. Skill instructions

2. Gather information

The runtime environment and language version, package manager, dependency manifest and lockfile, virtual environment, and configuration files from Chapter 1 establish the conditions needed to run a project. An existing environment setup skill can guide an agent to identify and install tools from the project requirements, prepare an isolated environment and dependencies, complete the configuration, then launch the program or run a minimal check. This helps a beginner get an environment ready for programming.

NameHow it helps beginners prepare the environment
Microsoft VS Code: setup-environment skillReads the project's installation instructions, checks required tools and versions, attempts to install missing tools for the operating system, then builds the project and tries to start it. It records newly discovered setup steps. Its goal is to help the user successfully build and run the project; virtual environments and specific configuration details depend on the project instructions. Skill instructions
HermeticOrmus community project: setup-env skillIdentifies runtime requirements from project files, installs the specified runtime and package manager versions, installs dependencies using the lockfile, creates a virtual environment for Python projects, and prepares local configuration. It then validates the environment through builds, checks and an actual launch, recording repeatable setup steps. Skill instructions

These skills need an agent that can access project files and execute commands. Users still need to supply information that cannot be determined from the project, such as accounts, keys and personal settings. Judge whether setup is complete by the actual execution results.

Once the task is clear and the environment is ready, existing agents and skills can help break requirements into processing steps, assign responsibilities to functions and modules, design data processing, and add explanations that make the code easier to understand.

4. Write and run the program step by step

You can give the plan from Section 3 directly to an agent that can edit files and execute commands. Ask it to create or change the code step by step, run the program and check the results. An additional skill is not always needed. Editors and IDEs let you inspect code, diffs and execution output. An ordinary Run button usually executes existing code; to have AI write code, you need to ask the agent to implement the plan.

You can continue with a coding agent in VS Code, moving from planning to implementation. Alternatively, use Superpowers' Executing Plans skill to make and verify changes one task at a time while recording progress, or BMad's bmad-build skill to take on the task, modify code, run checks and make Git commits.

This stage focuses on practicing Git version control. You can let your existing agent handle Git operations and inspect the results in a visual interface, or use a coding assistant with built-in Git integration.

Beginners can practice three actions:

  1. Inspect changes: Ask the agent to explain its changes, and compare the before-and-after code in the interface.
  2. Save a version: After completing a small task and checking it by running the program, save a Git commit with a description.
  3. Restore changes: Choose the changes to undo, then ask the agent to explain the impact before carrying it out, or use a graphical interface.

If you already use a coding agent, you can combine it with the git-commit skill and your editor's Git interface. Saving a file keeps its current contents; a Git commit records history that you can compare and restore. Commits can stay on your own computer without being uploaded to GitHub immediately. An automatic commit does not mean the program works correctly: you still need to check what actually happens.

5. Verify results, locate errors and improve the program

After writing a program, run it and check existing features again. Use logs and error symptoms to locate causes, then restructure code or measure performance where needed. You can also ask a review agent to compare the code with the requirements and the design from Section 3, checking code logic, module responsibilities and interfaces.

The table keeps tools for verification, debugging, code and structure review, refactoring, and performance analysis. Choose performance tools for your particular situation, such as a website, JavaScript or Python; you do not need to install them all.

Reviewing the overall structure requires reading the main modules, interfaces, dependencies and related calling code, then comparing them with the design from Section 3. A review should identify the problem's location, triggering conditions or structural evidence, actual impact and suggested improvements. Important conclusions still need to be verified by running checks. After refactoring, check that behavior has been preserved; after performance optimization, compare actual measurements from before and after the change.

For practical accounts, see CyberAgent's browser inspection and repair case, Google Chat's memory investigation case, and Superpowers project user feedback. These accounts cover different scopes and do not mean that every individual skill in the table has received the same effectiveness evaluation.
