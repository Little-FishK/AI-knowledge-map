This chapter selects existing workflows with instructions and public examples for character consistency, product images, local editing and upscaling. They are starting points for reuse; results still depend on inputs and runtime conditions. Resources and original workflow configurations were checked on October 31, 2026; local image generation has not been acceptance-tested.

Character consistency: IP-Adapter FaceID Plus v2

Conditions and limits

Use one face reference to practice retaining the same person's facial features across scenes. Begin with a clear, unobstructed, centered image of one face. This workflow mainly constrains facial identity; it does not also guarantee consistent clothing, body shape, pose and setting. The model author notes that identity consistency is imperfect.

The FaceID model card restricts use to research. Do not treat this example as a ready-to-use commercial portrait solution. The plugin author has placed the project in maintenance mode; record working ComfyUI and plugin versions and retain their files. Uses and capabilities, plugin installation and maintenance

Resources and workflow files

  • Author's FaceID workflow JSON: save as JSON and load in ComfyUI. At verification, it used the SD 1.5-series Realistic Vision V5.1 checkpoint, FACEID PLUS V2 in the loader, and a starting output size of 512 × 512.
  • Model files and usage: SD 1.5 and SDXL files are separate; select matching files from the same model family.
  • RunComfy character-consistency tutorial: additional guidance on reference preparation, interface use and outputs. Follow the platform workflow and the author's JSON according to their respective instructions.

Reuse steps

  1. Download and load the author's JSON. Install ComfyUI_IPAdapter_plus following its README, and install InsightFace in the same Python environment as ComfyUI.
  2. Obtain the checkpoint used by the JSON. The SD 1.5 branch uses ip-adapter-faceid-plusv2_sd15.bin, its paired ip-adapter-faceid-plusv2_sd15_lora.safetensors, and the README's ViT-H vision encoder. Put them in models/ipadapter, models/loras and models/clip_vision, respectively; put the checkpoint in models/checkpoints. Prepare InsightFace's face models as the plugin instructs.
  3. Select your reference in Load Image, replacing the sample filename. Reselect the installed model in Checkpoint Loader. Follow the README's required naming for files used by the unified loader.
  4. Keep FACEID PLUS V2 and the other starting settings. Enter a simple new scene description and generate one image first. Confirm that the reference face is recognized correctly.
  5. Keep the reference, model and other settings fixed while changing the scene or medium. If the face drifts, compare reference cropping, FaceID strength and prompts individually; save each comparison.
  6. Inspect facial features, face shape, apparent age and side views in each image. Add separate controls for clothing or poses when needed; retaining facial features alone is not complete character consistency.

Product images: relighting and background coordination

Conditions and limits

Suitable for changing the presentation environment or lighting of an existing product photo. The full example is Andrea Baioni's Product Relighting; its RunComfy page includes a JSON download, illustrations and the author's video. A clear subject image is required; background and light masks are optional. These conditions and the switches below come from the case instructions.

These workflows regenerate or harmonize an image. Compare the output with the original product's shape, color, packaging text, logos and small components. Restore exact text or logos from original assets during subsequent refinement when needed.

Resources and workflow files

  • Full Product Relighting case and workflow JSON download.
  • Author's accompanying video: the operation demonstration linked by the case page.
  • Original IC-Light documentation: verify relighting models, inputs and component requirements.
  • IC-Light ComfyUI node documentation and original PNG for the basic local workflow: practice basic relighting separately. This is another workflow, not a replacement for the complete product-image workflow.

Reuse the complete product-image workflow

  1. Download Workflow.json from the case page or open the preconfigured platform environment. For a local import, install the nodes and models specified by that JSON; a preconfigured cloud environment does not mean your computer already has those components.
  2. Upload Subject Image in Input Images. To specify a background, upload Background and enable Background Switch. For a lighting mask, upload Light Mask and enable Light Mask Switch. Leave the corresponding switches off when no image is supplied.
  3. Enter concise product and lighting descriptions in Input Prompts, such as material, color, soft side lighting or cool rim lighting. Keep the remaining settings and generate a first version.
  4. Compare both outputs with the original product: Color Matched Result and Relit Result show color coordination and relighting, respectively.
  5. Compare Denoise settings to adjust the amount of background change. To adjust brightness, follow the case's output-group instructions. Change only a few settings at a time.
  6. Save the selected output, inputs and workflow, then inspect or repair product details in Photoshop.

Requirements for the basic local example

Kijai's original PNG stores the SD 1.5-branch photon_v1.safetensors, iclight_sd15_fc.safetensors and nodes including ImageResizeKJ. Prepare that checkpoint, ComfyUI-IC-Light and the required KJNodes. Put the IC-Light model in the appropriate directory under models/unet according to the node documentation and select it in the loader. Replace the sample input, describe the subject and lighting, and start with the original approximately 512-pixel configuration. Compare results separately if using another checkpoint.

The IC-Light author also notes that BRIA RMBG 1.4 in the original demo is restricted to noncommercial use. If a workflow uses a background-removal model, check that component's conditions for product use; the main IC-Light code license alone does not determine the whole workflow's terms.

Local editing: official ComfyUI Inpainting

Conditions and limits

Suitable when the overall image is satisfactory and only a region such as a hat, clothing texture or background clutter needs changing. You need the original image and an edit mask. For basic practice, use the officially specified 512-inpainting-ema.safetensors with an approximately 512-pixel input; do not add third-party nodes initially.

Although the original workflow filename contains sd1.5, its loader specifies the inpainting file above. Follow the node and model requirements rather than inferring the model version from an image filename.

Resources and workflow files

  • Official Chinese inpainting tutorial: models, input images, mask editing and execution.
  • Original workflow PNG to drag into ComfyUI.
  • Model file page linked by the official tutorial.
  • Maintainer's inpainting and outpainting examples.

Reuse steps

  1. Download the original PNG and drag it into ComfyUI or load it through Workflow → Open. Use the original file: screenshots and recompression may lose workflow information.
  2. Download the specified model into ComfyUI/models/checkpoints and select it in Load Checkpoint. Keep the template's sampling settings initially.
  3. Upload the official input image in Load Image and run the example once with its existing transparency mask.
  4. Replace it with your original image, right-click the image in Load Image and choose Open in MaskEditor. Cover the target object and blending edges, then save the mask.
  5. Describe the desired content, such as replacing a hat with a red knitted hat. Check that both image and mask connect to VAE Encode (for Inpainting), then generate.
  6. Compare the edited region, edges and surrounding image. If seams appear, adjust the mask coverage first. Also compare areas that should remain unchanged; if needed, use a mask in Photoshop to composite the edit back onto the original.
  7. Save the original, mask, prompt and workflow. When switching to SDXL or another inpainting model, use its matching workflow and recheck parameters.

Upscaling: ESRGAN and Real-ESRGAN

Conditions and limits

Suitable for photos or illustrations whose composition is settled but need larger pixel dimensions. ComfyUI's native model-upscaling workflow needs no additional SD checkpoint, prompt, LoRA or seed. Inspect text, outlines, faces and textures afterward; more pixels do not guarantee recovery of real details absent from the original.

Resources and workflow files

  • Official Chinese upscaling tutorial and original basic-workflow PNG.
  • Maintainer's model-upscaling examples.
  • Original Real-ESRGAN model list: weight links for photos, illustrations and other uses. This is an alternative model source; distinguish it from the official example's default 4x-ESRGAN.

Model selection reference

Image and goalModels to compare
General image upscalingRealESRGAN_x4plus or RealESRGAN_x2plus
Anime and illustrationsRealESRGAN_x4plus_anime_6B
Lower runtime and VRAM userealesr-general-x4v3; its author notes more limited deblurring and denoising

Reuse steps

  1. Download and load the official original workflow PNG. For a first exercise, use 4x-ESRGAN as instructed, or download appropriate inference weights from the Real-ESRGAN author's list. Avoid netD files intended for training.
  2. Put the model in ComfyUI/models/upscale_models and select it in UpscaleModelLoader. The saved RealESR/4x-ESRGAN.pth path is the author's directory record; reselect your actual local file.
  3. Upload the input in Load Image. Confirm that the image and upscaling model connect to ImageUpscaleWithModel, then run and save the output.
  4. Check the actual pixel dimensions. A 4× model increases both width and height approximately fourfold: 512 × 512 becomes about 2048 × 2048.
  5. At 100% display, compare textures, edges, text and facial features. Compare models separately for ordinary and anime images, and choose the result appropriate to the use.
  6. If VRAM runs out, test a smaller image or lower the input dimensions. For large images, select a supporting implementation with tiled processing and inspect tile boundaries. The author's command-line tool has a tile setting; it is not a same-named parameter in this basic node graph.
  7. In further work, connect the image output of a generation workflow to this upscaling workflow and record the upscaling model, factor and dimensions.

Shared preparation and result records

Run each workflow with its original configuration before replacing inputs. Models, LoRAs, nodes and assets are usually not all bundled inside one JSON file. Without an explicit source, do not assume a universal minimum VRAM requirement: local needs depend on models, dimensions, precision, simultaneously loaded components and software versions. Use RunComfy or other cloud environments according to their current configurations and fees.

For official templates, use Workflow → Browse Workflow Templates and obtain models indicated as missing. Load author-shared workflows from JSON or original PNG, then check custom nodes. See template instructions and missing-node and model troubleshooting.

Keep these records for further changes or comparisons:

RecordContent
Workflow sourcePage, filename, download date and identifiable version or commit
Runtime configurationComfyUI and custom-node versions, models and companion files, key parameters
Inputs and goalReferences, masks, prompts, content to retain and changes to make
ChecksWhether identity, product details, edit boundaries or upscaled textures meet requirements
Actual effortRuntime, execution errors and manual correction

Matching seeds and parameters still do not guarantee identical outputs across environments; see the Diffusers guide for reproducibility conditions. Compare candidates using the same assets to determine which workflow fits the current task.
