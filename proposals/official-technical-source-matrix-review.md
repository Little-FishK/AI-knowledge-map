# “官方技术资料”二级来源知识矩阵初筛

日期：2026-09-24  
状态：审核记录；Qwen、Moonshot AI 与 Zhipu AI 已按用户决策撤销

## 1. 审核对象与口径

本轮审核 `official` 一级来源下现有 13 个二级来源。判断对象是“这个二级来源是否值得作为长期、独立的来源入口存在”，不是审核其中每一篇资料，也不以现有条目数作为通过依据。

证据边界：国内四个来源的 40 条资料已经填写 `linkedNodes`；早期精选包中的 90 条资料除 ElevenLabs 外尚未填写节点关联，因此这 90 条的矩阵位置暂按标题、摘要、`selectionReason` 和项目现有节点人工判定。矩阵可以用于来源初筛，但不能替代下一轮逐条资料映射。

知识矩阵由项目 130 个节点的九段学习顺序合并为六个审核域：

1. 模型基础：学习原理、模型架构、训练与适配；
2. 推理上下文：推理接口、提示、上下文、缓存与优化；
3. 应用工程：检索、评测、部署、可观测与数据工程；
4. 推理与 Agent：推理策略、工具、协议、Agent 与编码系统；
5. 多模态：图像、视频、语音、音频及相关生成系统；
6. 安全治理：安全、对齐、隐私、红队、内容治理与责任边界。

矩阵符号：

- `●`：该来源在该域有持续、直接且较难替代的贡献；
- `△`：主要提供品牌实现、工程实例或有限补充；
- `—`：现有资料没有形成稳定的必要覆盖。

二级来源保留必须同时满足：

- 至少在一个审核域为 `●`；
- 该贡献不是仅靠一篇偶然材料成立，而是来源主体持续发布的正式资料；
- 与其他来源重复时，能够说明独特对象、实现层或证据责任；
- 能够形成明确的收录边界，而不是把官网整体背书。

## 3. 筛选结果

### 3.1 核心来源：7 个

长期保留为独立入口：

- OpenAI
- Anthropic
- Google / DeepMind
- Meta AI
- NVIDIA
- Hugging Face 官方
- DeepSeek

这些来源至少承担一个难以由其他来源替代的知识位置。其中模型厂商提供当前模型、接口和系统卡事实；Meta、NVIDIA 与 Hugging Face 分别补足开放模型研究、计算基础设施和开放工具链，不能简单视作又一组重复的品牌文档。

“核心来源”不代表每个来源都要覆盖六个审核域，也不产生最低篇数。每个来源只在其明确的主责知识域内持续收录。

### 3.2 专业来源：2 个

保留独立入口，但只收其不可替代的工程资料：

- Microsoft：重点限于 ONNX Runtime、AutoGen、Semantic Kernel、Presidio，以及 Azure 托管层与模型层的关键区别；普通产品总览和通用模型选型页不因品牌身份自动收录。
- AWS：重点限于 Bedrock/SageMaker 的生产架构、AWS Neuron 和有明确机制的治理资料；通用快速开始、服务列表和营销式架构介绍不收录。

这两个来源不负责解释通用 AI 概念，只负责云平台和企业工程实现证据。若后续资料逐条审核后无法各自留下至少一个稳定、不可替代的工程资料簇，再考虑合并成“云平台 AI 工程”集合。

### 3.3 取消来源：4 个

取消“其他厂商官方资料”作为二级来源。它混合 ElevenLabs、Mistral、Cohere、Stability AI、Runway、xAI、Groq、Perplexity、Adobe、Databricks 等不同主体，既没有统一发布责任，也没有共同技术范围，无法形成可执行的来源级审核边界。

另按用户决策撤销 Qwen、Moonshot AI 与 Zhipu AI 三个独立二级来源；其原有来源入口、治理元数据和资料卡均不再保留。

取消混合分类不等于删除其中所有资料。原有资料应逐条按知识贡献处理：

- ElevenLabs：可作为声音克隆专项来源候选；
- Cohere：可作为重排与企业检索专项来源候选；
- Stability AI、Adobe：可作为图像生成/编辑专项来源候选；
- Runway：可作为视频生成专项来源候选；
- Groq：可作为低延迟推理专项来源候选；
- Perplexity：可作为检索原生与引用型应用专项来源候选；
- 其他只有通用 API 总览、没有独立知识贡献的资料不收录。

只有某个发布方通过逐条审核形成至少一个持续、明确的专业资料簇时，才为它新建独立二级来源；不能预先为“品牌全面性”创建空栏目。

## 4. 防止重复与品牌损失的入库规则

后续逐条内容审核使用两个独立增量字段：

- `knowledgeDelta`：相对全库增加了什么通用知识；
- `brandEvidenceDelta`：相对该品牌已有资料增加了什么实现、能力边界、版本或责任证据。

资料满足任一增量即可进入候选，但采用不同处理方式：

- 有 `knowledgeDelta`：可以建立或更新独立知识资料对象；
- 只有 `brandEvidenceDelta`：作为对应知识对象下的品牌实现证据，不重复创建通用概念条目；
- 两项都没有：不收录；
- 同一品牌、同一主题、同一事实有多页文档：选择当前最直接的主文档，其余只在确有版本或证据作用时作为关联材料。

因此，全面性不再用“每品牌十篇”衡量，而用两项结果衡量：

1. 130 个知识节点中的重要知识问题是否有合适证据；
2. 核心来源及专业来源的关键实现差异是否有证据。

## 5. 实施结果

该来源初筛已经实施：

1. `official` 已取消每个二级来源至少 10 篇的数量门禁；
2. 保留 12 个具有持续贡献的二级来源；
3. `vendor-docs-other` 已撤销，不再设置混合兜底分类；
4. 原 130 条官方资料已按知识矩阵重建；
5. 五步规则已正式形成[官方技术资料审核机制](../docs/OFFICIAL_TECHNICAL_REVIEW_POLICY.md)，并完成 [OpenAI 试审](../docs/OFFICIAL_TECHNICAL_OPENAI_PILOT_20260924.md)。

后续品牌必须逐源执行同一机制，但一个品牌的试审结果不得替代另一个品牌的逐条审核。
